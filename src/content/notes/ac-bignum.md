## 高精度四则运算的使用场景

**题目给出的位数上限超出内置类型能表示的范围，才需要自己实现。**

| 类型 | 十进制有效位 | 上限 | $100!$（158 位）存得下吗 |
| :--- | :--- | :--- | :--- |
| `int` | 约 10 位 | $2^{31}-1 \approx 2.15\times10^{9}$ | 否 |
| `long long` | 约 19 位 | $2^{63}-1 \approx 9.22\times10^{18}$ | 否 |
| `unsigned long long` | 约 20 位 | $2^{64}-1 \approx 1.84\times10^{19}$ | 否 |
| `double` | 约 15~16 位**有效数字** | 约 $1.8\times10^{308}$ | 能表示数量级，但每一位都不可信 |

注意：`double` 并非「装不下大数」，它装得下 $10^{300}$ —— 但尾数只有 53 个二进制位，换算成十进制只有 15~16 位有效数字，$10^{50}+1$ 在它眼里就是 $10^{50}$。**大数要的不是「更大的范围」，而是「每一位都准确」**，所以只能自己用数组把每一位存下来。

> **提示**：`double` 的失效方式很隐蔽 —— 它在小数据上完全正确，所以样例能过。只有位数上去之后才突然开始丢低位，而且**不报错**

反过来也有个方向要分清：如果题目要求的是「答案对 $10^9+7$ 取模」，那不需要高精度 —— 那是取模运算的题，每一步都在模意义下进行，中间结果永远不会变大。

## 数组逆序模拟竖式

列竖式手算 123 + 456：

```
     1  2  3
  +  4  5  6
  ───────────
     5  7  9
```

程序做的是同一件事，只是把纸换成了数组。**唯一关键的约定是：个位存在索引 0，也就是整个数逆序存放**

```
a[] = {3, 2, 1}   ← 123，个位在索引 0
b[] = {6, 5, 4}   ← 456
c[] = {9, 7, 5}   ← 579，同样逆序
输出时从最高位往低位遍历 → "579"
```

**逆序存储的原因** 运算随时可能往更高位长出一位（$999 + 1 = 1000$）。正序存放时，最高位在索引 0，新长出的最高位要把所有元素整体后移一位 —— 每进一次位就是 $O(n)$，最坏情况下总代价 $O(n^2)$。逆序存放时，新的最高位就是数组末尾的下一个位置，**一次赋值就够，整体仍是 $O(n)$**。

#### 输入输出的固定数据流

```
输入(string) → 逐位转 int → 逆序存入 int[] → 运算 → 逆序输出
```

```cpp
// 读入后逆序存进数组
string s;
cin >> s;
int len = s.size();
for (int i = 0; i < len; i++)
    a[i] = s[len - 1 - i] - '0';   // s 的末位 → a[0]
```

```cpp
for (int i = len - 1; i >= 0; i--) cout << c[i];
```

## 高精度加法

```cpp
#include <iostream>
#include <string>
#include <algorithm>
using namespace std;

const int N = 510;          // 按题目的位数上限开，再留 10 位余量

int main() {
    string s1, s2;
    cin >> s1 >> s2;

    int a[N] = {0}, b[N] = {0}, c[N] = {0};
    int len1 = s1.size(), len2 = s2.size();

    for (int i = 0; i < len1; i++) a[i] = s1[len1 - 1 - i] - '0';
    for (int i = 0; i < len2; i++) b[i] = s2[len2 - 1 - i] - '0';

    int maxLen = max(len1, len2);
    int carry = 0;
    for (int i = 0; i < maxLen; i++) {
        int sum = a[i] + b[i] + carry;
        c[i] = sum % 10;        // 本位
        carry = sum / 10;       // 进位，留给下一位
    }
    if (carry) c[maxLen] = carry, maxLen++;   // 最高位还有进位：结果多一位

    for (int i = maxLen - 1; i >= 0; i--) cout << c[i];
    cout << endl;

    return 0;
}
```

:::example 例 1 · A+B Problem（高精度）
输入两个不超过 500 位的非负整数，输出它们的和。

**思路**：逆序存两个数，从个位起逐位相加。每一位的结果是 `a[i] + b[i] + carry`，本位保留 `% 10`，进位留给下一位。两个数长度不同时，短的那个高位按 0 参与运算 —— 数组初始化为 0，所以越界读到的 `b[i]` 就是 0，**前提是数组开得够大**。

**解**：见上面完整代码。

**评注**：`if (carry) c[maxLen] = carry, maxLen++;` 这一行是最容易被漏掉的边界。$99 + 1$ 走完循环后 `carry = 1`，不补这一行就不会输出百位，结果变成 `00`。另一处细节是循环上界取 `max(len1, len2)` 而不是 `len1 + len2` —— 加法最多只多出一位，循环里不可能超过较长的那个数。
:::

> **易错点**：加法**不要**学乘法那样「先逐位加起来最后统一进位」。加法的进位每轮只可能是 0 或 1（`9 + 9 + 1 = 19`），边加边进是最短的写法；而乘法的中间值可能远大于 10，统一进位反而更清晰。

**框架**：

1. `string` 读入（不要用整型，装不下）；
2. 逐位 `- '0'` 转数值，**逆序**存进 `int[]`；
3. 逐位运算，处理进位 / 借位；
4. 处理最高位（加法的进位、减法的符号、乘法的多余位）；
5. 去前导零，**逆序输出**。

## 高精度减法

```cpp
#include <iostream>
#include <string>
#include <algorithm>
using namespace std;

const int N = 510;

int main() {
    string s1, s2;
    cin >> s1 >> s2;

    // 关键一步：保证 a >= b，否则结果带负号
    bool negative = false;
    if (s1.size() < s2.size() || (s1.size() == s2.size() && s1 < s2)) {
        swap(s1, s2);
        negative = true;
    }

    int a[N] = {0}, b[N] = {0}, c[N] = {0};
    int len1 = s1.size(), len2 = s2.size();
    for (int i = 0; i < len1; i++) a[i] = s1[len1 - 1 - i] - '0';
    for (int i = 0; i < len2; i++) b[i] = s2[len2 - 1 - i] - '0';

    for (int i = 0; i < len1; i++) {
        if (a[i] < b[i]) {      // 本位不够减，向高位借 1
            a[i] += 10;
            a[i + 1]--;
        }
        c[i] = a[i] - b[i];
    }

    // 去前导零：至少保留一位，否则 0 会被删光
    int top = len1 - 1;
    while (top > 0 && c[top] == 0) top--;

    if (negative) cout << '-';
    for (int i = top; i >= 0; i--) cout << c[i];
    cout << endl;
    return 0;
}
```

#### 符号判断

字符串比大小不是按数值比的，但**在位数相同的前提下**，字典序与数值序一致。所以只需要两级判断：先比长度，长度相同再比 `s1 < s2`（`std::string` 的 `<` 就是字典序比较）。

判完之后**永远用大数减小数**，最后看 `negative` 补一个负号 —— 这样中间过程全是非负的，完全不用考虑「负数怎么借位」。

#### 借位传播

:::example 例 2 · 1000 − 1 的逐位推演
$1000 - 1$ 是借位一路传播三位的典型。逆序存进来：

| 索引 | 0（个位） | 1 | 2 | 3 |
| :--- | :--- | :--- | :--- | :--- |
| `a[]` 初始 | 0 | 0 | 0 | 1 |
| `b[]` | 1 | 0 | 0 | 0 |

**解**：逐位走一遍 `for (i = 0; i < 4; i++)`：

| `i` | 进入时 `a[i]` | `a[i] < b[i]`？ | 借位后 `a[i]` | `a[i+1]--` 之后 | `c[i] = a[i] - b[i]` |
| :--- | :--- | :--- | :--- | :--- | :--- |
| 0 | 0 | 是 | 10 | `a[1] = -1` | 9 |
| 1 | -1 | 是 | 9 | `a[2] = -1` | 9 |
| 2 | -1 | 是 | 9 | `a[3] = 0` | 9 |
| 3 | 0 | 否 | 0 | 不变 | 0 |

`c[] = {9, 9, 9, 0}`，最高位 `c[3] = 0` 被前导零循环削掉，输出 `999`。

**评注**：注意 `a[1]`、`a[2]` 进入循环时是**负数**。这正是这套写法最巧妙的地方 —— 借位不需要单独设计「连锁借位」逻辑，`-1 < 0` 自然又成立一次，借位就自己一路传下去了。如果换成「先算差、再统一修负数」的写法，得专门写一个循环往回找可以借的位，代码要长一倍。
:::

#### 前导零

$123 - 123 = 0$，每一位都是 0，但结果不能输出空字符串。所以去零循环的条件必须是 `top > 0`，而不是 `top >= 0`：

```cpp
int top = len1 - 1;
while (top > 0 && c[top] == 0) top--;   // 削到只剩索引 0 为止
```

> **易错点**：减法里还有一个隐蔽的边界 —— `a[i + 1]--` 会写到 `len1` 的位置。数组开 `N = 510` 而数字最多 500 位时这是安全的；但如果把 `N` 卡得刚刚好（题目说 500 位就开 500），最后一次借位就写到数组外面去了。**数组永远比位数上限多开 10 位。**

## 高精度乘法

### 高精度 × 低精度

乘数是一个普通的 `int`（竞赛里最常见于求阶乘、乘系数），复杂度 $O(n)$：

```cpp
    string s;
    int b;                    // 低精度乘数，题目保证 b < 10000
    cin >> s >> b;

    int a[N] = {0};
    int len = s.size();
    for (int i = 0; i < len; i++) a[i] = s[len - 1 - i] - '0';

    int carry = 0;
    for (int i = 0; i < len; i++) {
        int cur = a[i] * b + carry;   // a[i] ≤ 9，b < 10000，不会溢出
        a[i] = cur % 10;
        carry = cur / 10;
    }
    // 循环结束后把剩下的进位一位位写出去
    int p = len;
    while (carry > 0) {
        a[p++] = carry % 10;
        carry /= 10;
    }
    len = p;
```

`b < 10000` 这个限制不是随意的：`a[i] * b` 最大是 $9 \times 9999$，加上进位还不到 10 万，离 $2^{31}$ 差了四个数量级。**如果题目给的 `b` 更大，把 `cur` 换成 `long long` 即可，逻辑一个字都不用改。**

顺带一个高频用法：求 $n!$ 时反复做「现有结果 × 下一个数」，而下一个数 $i \le n$ 通常远小于 10000，所以**整条阶乘只需要「高 × 低」**，根本用不上 $O(n^2)$ 的高 × 高。

### 高精度 × 高精度

两个数逐位交叉相乘，复杂度 $O(n^2)$。核心就一行：**`a[i] * b[j]` 累加到 `c[i + j]`**。

```cpp
    // a[]、b[] 已逆序存好，长度分别是 len1、len2；c[] 至少开 2 * N
    for (int i = 0; i < len1; i++)
        for (int j = 0; j < len2; j++)
            c[i + j] += a[i] * b[j];

    int maxLen = len1 + len2;          // 积最多 len1 + len2 位
    for (int i = 0; i < maxLen; i++) { // 双重循环结束后统一进位
        if (c[i] >= 10) {
            c[i + 1] += c[i] / 10;
            c[i] %= 10;
        }
    }
```

:::example 例 3 · 123 × 456：`c[i+j]` 的索引从哪来
`a[] = {3, 2, 1}`、`b[] = {6, 5, 4}`（都是逆序），交叉相乘后**先不进位**：

| `c` 的下标 | 落到这里的乘积 | 累加值 |
| :--- | :--- | :--- |
| 0 | `a[0]b[0] = 3 × 6` | 18 |
| 1 | `a[0]b[1] + a[1]b[0] = 3 × 5 + 2 × 6` | 27 |
| 2 | `a[0]b[2] + a[1]b[1] + a[2]b[0] = 12 + 10 + 6` | 28 |
| 3 | `a[1]b[2] + a[2]b[1] = 8 + 5` | 13 |
| 4 | `a[2]b[2] = 1 × 4` | 4 |

再统一进位（从左往右，`c[i + 1] += c[i] / 10`）：

| 进位步骤 | `c[0]` | `c[1]` | `c[2]` | `c[3]` | `c[4]` |
| :--- | :--- | :--- | :--- | :--- | :--- |
| 进位前 | 18 | 27 | 28 | 13 | 4 |
| 处理 `i = 0` | 8 | 28 | 28 | 13 | 4 |
| 处理 `i = 1` | 8 | 8 | 30 | 13 | 4 |
| 处理 `i = 2` | 8 | 8 | 0 | 16 | 4 |
| 处理 `i = 3` | 8 | 8 | 0 | 6 | 5 |

`c[] = {8, 8, 0, 6, 5}`，逆序输出 `56088`，与 $123 \times 456 = 56088$ 一致。

**评注**：为什么是 `i + j`？因为 `a[i]` 的权值是 $10^i$、`b[j]` 的权值是 $10^j$，两者相乘的权值是 $10^{i+j}$，所以落进 `c[i + j]`。这和十进制竖式里「第 $i$ 位乘第 $j$ 位落在第 $i + j$ 列」是同一件事 —— 手算时那些错开一格的加法行，就是这个索引关系。
:::

> **易错点**：`c[i + j] += a[i] * b[j]` 的累加值上限是 $81 \times \min(len_1, len_2)$。位数几千时只有几十万，`int` 完全够用；真正的风险不在溢出，而在**数组开小了**：两个 $n$ 位数相乘最多 $2n$ 位（$99 \times 99 = 9801$），所以 `c[]` 至少要开 `2 * N`，而且进位循环会访问到 `c[len1 + len2]`。

## 高精度除法

### 高精度 ÷ 低精度

**这是唯一一个不用逆序的运算。** 因为人手算除法就是从高位往低位算的：先看前几位够不够除，不够就多看一位，余数顺手往后传。

```cpp
    string s;
    int b;                        // 除数（低精度）
    cin >> s >> b;

    int a[N] = {0}, c[N] = {0};
    int len = s.size();
    for (int i = 0; i < len; i++) a[i] = s[i] - '0';   // 正序！a[0] 是最高位

    long long remainder = 0;      // 余数必须用 long long
    for (int i = 0; i < len; i++) {
        remainder = remainder * 10 + a[i];   // 把下一位"落下来"
        c[i] = remainder / b;                // 这一位的商
        remainder %= b;                      // 剩下的余数传给下一位
    }
```

案例 $123456789 \div 7$ ：

| `i` | 落下的位 `a[i]` | `remainder * 10 + a[i]` | `c[i]`（商位） | 新 `remainder` |
| :--- | :--- | :--- | :--- | :--- |
| 0 | 1 | 1 | 0 | 1 |
| 1 | 2 | 12 | 1 | 5 |
| 2 | 3 | 53 | 7 | 4 |
| 3 | 4 | 44 | 6 | 2 |
| 4 | 5 | 25 | 3 | 4 |
| 5 | 6 | 46 | 6 | 4 |
| 6 | 7 | 47 | 6 | 5 |
| 7 | 8 | 58 | 8 | 2 |
| 8 | 9 | 29 | 4 | 1 |

商是 `017636684`，去掉首位的前导零得到 `17636684`，余数 1。验算：$7 \times 17636684 + 1 = 123456789$。

> **易错点**：商的第 0 位可能是 0（被除数首位比除数小），所以**必须从前往后跳过前导零**，方向与加减法「从后往前跳」正好相反：
>
> ```cpp
> int start = 0;
> while (start < len - 1 && c[start] == 0) start++;
> for (int i = start; i < len; i++) cout << c[i];
> ```
>
> 条件 `start < len - 1` 同样是为了让 $0 \div 5 = 0$ 能输出一个 `0`。

### 高精度 ÷ 高精度

除数也是高精度时，没有「一次就能定出一位商」的捷径（除数是变量，不能像低精度那样直接除）。最直观的做法是**用减法模拟**：把除数对齐到被除数的某一位，反复减，**能减几次，这一位的商就是几**。

```cpp
const int N = 510;

// 把 x 对齐到 y 的 offset 位置（相当于让 x 乘 10^(offset-1)）
void cpy(int x[], int y[], int offset) {
    for (int i = 1; i <= x[0]; i++) y[i + offset - 1] = x[i];
    y[0] = x[0] + offset - 1;
}

// x >= y ?
bool ge(int x[], int y[]) {
    if (x[0] != y[0]) return x[0] > y[0];
    for (int i = x[0]; i >= 1; i--)
        if (x[i] != y[i]) return x[i] > y[i];
    return true;
}

// x -= y（要求 x >= y）
void sub(int x[], int y[]) {
    for (int i = 1; i <= x[0]; i++) {
        if (x[i] < y[i]) { x[i] += 10; x[i + 1]--; }
        x[i] -= y[i];
    }
    while (x[0] > 1 && x[x[0]] == 0) x[0]--;
}

int main() {
    string s1, s2;
    cin >> s1 >> s2;

    int a[N] = {0}, b[N] = {0}, c[N] = {0};

    // 1-索引：索引 1 是个位，索引 0 存长度
    a[0] = s1.size();
    for (int i = 1; i <= a[0]; i++) a[i] = s1[a[0] - i] - '0';
    b[0] = s2.size();
    for (int i = 1; i <= b[0]; i++) b[i] = s2[b[0] - i] - '0';

    if (ge(a, b)) {                        // 被除数 < 除数时商就是 0，跳过整段
        c[0] = a[0] - b[0] + 1;            // 商的最大可能位数
        for (int i = c[0]; i >= 1; i--) {
            int t[N] = {0};
            cpy(b, t, i);                  // t = b × 10^(i-1)
            while (ge(a, t)) {
                sub(a, t);
                c[i]++;                    // 减一次，这一位的商加 1
            }
        }
        while (c[0] > 1 && c[c[0]] == 0) c[0]--;   // 去商的前导零
    } else {
        c[0] = 1;                          // 商就是 0
    }

    for (int i = c[0]; i >= 1; i--) cout << c[i];
    cout << endl;
    // 此时 a 里剩下的就是余数
    return 0;
}
```

:::example 例 4 · 112 ÷ 12
`a[] = {3, 3, 1, 1}`（`a[0] = 3` 是长度，`a[1..3]` 是个位到百位），`b[] = {2, 2, 1}`。商的位数 `c[0] = 3 - 2 + 1 = 2`。

| `i` | `t = b × 10^(i-1)` | `ge(a, t)` | 减了几次 | `c[i]` |
| :--- | :--- | :--- | :--- | :--- |
| 2 | 120 | 112 ≥ 120？否 | 0 | 0 |
| 1 | 12 | 112 ≥ 12？是 | 9（112 → 4） | 9 |

`c[] = {2, 9, 0}`（1-索引），去掉高位那个前导零后输出 `9`；`a` 里剩 `4`，即余数。验算：$112 = 12 \times 9 + 4$。

**评注**：`i` 从高位往低位走，是因为**商的每一位都必须从高位开始确定** —— 这与手算除法的顺序一致。每定下一位，就把除数这个量级从被除数里尽量减掉，剩下的部分自然留给更低的位。

`while` 里最多减 9 次：进入第 `i` 轮时 `a` 一定小于 $b \times 10^{i}$，而 `t` 是 $b \times 10^{i-1}$，所以 `a < 10t`，商位不可能超过 9。这也是它复杂度的来源：$n$ 位商、每位最多 9 次减法、每次减法 $O(n)$，总计 $O(n^2)$。
:::

> **易错点**：1-索引的写法里 `[0]` 是长度、不是数字，混用两种风格是最常见的错误来源 —— 同一道题里所有运算必须统一成一种。另外这段**必须先判 `a >= b`**，否则 `c[0] = a[0] - b[0] + 1` 会算出非正数，循环一次都不执行，输出一片乱码。

## 小结

#### 复杂度与选型

| 运算 | 时间复杂度 | 关键点 |
| :--- | :---: | :--- |
| 高精度 ± 低精度 | $O(n)$ | 遍历高精度数的每一位 |
| 高精度 ± 高精度 | $O(n)$ | 同时遍历两个数，进位 / 借位是 $O(1)$ |
| 高精度 × 低精度 | $O(n)$ | 每位乘 `b`，再把进位推完 |
| 高精度 × 高精度 | $O(n^2)$ | 双重循环，`c[i+j] += a[i]*b[j]` |
| 高精度 ÷ 低精度 | $O(n)$ | 正序逐位除，余数下传 |
| 高精度 ÷ 高精度 | $O(n^2)$ | 减法模拟，每位最多减 9 次 |

:::summary

1. **逆序存是默认**，只有「高 ÷ 低」例外（正序更像手算）；
2. **加减法边算边进/借**，**乘法统一进位**，**除法靠反复减**；
3. **每次都要处理前导零**，而「至少保留一位」是所有去零循环的边界条件。

选型上：高 × 高与高 ÷ 高在竞赛里出现频率很低，因为 $O(n^2)$ 一旦位数上万就会超时。**先想想能不能只用低精度乘除解决** —— $100!$ 只要「高 × 低」就够，不需要完整的 $O(n^2)$ 乘法。实在不行再考虑压位（把每 9 位十进制压进一个 `int`，进位阈值改成 $10^9$，常数直接降到 1/9），或者换一门有 `BigInteger` 的语言。
:::
