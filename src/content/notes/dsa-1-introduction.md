## 数据结构

**数据结构**是计算机存储、组织数据的方式，它决定了数据在计算机中的**表示形式**与**可施加的运算**

### 数据结构的基本概念

#### 数据

**数据**（Data）是信息的载体，是描述客观事物属性的数、字符，以及**所有能输入到计算机中并被程序识别和处理的符号**的集合。一份学生档案里的学号（数字）、姓名（字符）、证件照（图像）都是数据。数据是程序加工的原料——没有数据，程序就失去了处理对象。

#### 数据元素

**数据元素**（Data Element）是数据的**基本单位**，通常作为一个整体被考虑和处理。一条学生记录就是一个数据元素。

#### 数据项

**数据项**（Data Item）是构成数据元素的、不可分割的**最小单位**。上面那条记录里的"姓名""年龄"，各是一个数据项。

值得一提的是，**何为数据元素、何为数据项取决于实际业务需求**：在学籍管理系统里"一条学生记录"是数据元素，而在成绩管理系统里"一名学生"可能只是某个数据元素下的一个数据项。

| 概念层级 | 名称 | 说明 |
| :--- | :--- | :--- |
| **最大单位** | **数据**（Data） | 信息的载体，计算机程序加工的原料 |
| **基本单位** | **数据元素**（Data Element） | 由若干数据项组成；在不同结构中称谓不同 |
| **最小单位** | **数据项**（Data Item） | 不可再分割的原子单位 |

> **易错点**：数据元素与数据项是两个层级，不能混为一谈。数据元素是基本单位，数据项是它的组成部分。

同一份数据元素在不同结构里叫法不同：在线性表中称为**元素**，在树中称为**结点**，在图中称为**顶点**，在查找和排序中称为**记录**。看到这些词时要意识到，它们说的是同一个概念。

#### 数据结构

**结构**（Structure）指各个组成部分相互搭配和排列的方式，简单理解就是**关系**。在此基础上：

**数据结构**（Data Structure）：相互之间存在一种或多种特定关系的数据元素的集合。

#### 数据对象

**数据对象**（Data Object）：具有相同性质的数据元素的集合，是数据的一个子集。

在不产生混淆的情况下，人们常把数据对象直接称为数据。例如"整数数据对象"就是集合 $\{0, \pm 1, \pm 2, \cdots\}$，"学生数据对象"则是若干条学生记录的集合。

![数据结构与数据对象示例](/notes-assets/dsa1-01-data-structure-and-object.jpg)

> **注意**：数据、数据对象与数据元素是三个不同粒度的概念——数据是全体，数据对象是其中具有相同性质的一类，数据元素是这一类的个体成员。

### 数据结构的三要素

一个数据结构可以从三个角度完整刻画：

- **逻辑结构**回答"数据元素之间存在什么关系"；
- **物理结构**回答"这种关系在计算机中如何存储"；
- **数据的运算**回答"能对数据施加哪些操作"。

三者共同决定了一个数据结构的全貌与效率。分析任何一个数据结构，都要先问这三个问题。

#### 逻辑结构

**逻辑结构**是数据元素之间的逻辑关系，与存储方式无关，属于数据结构的"抽象层"。按元素之间关系的紧密程度，逻辑结构分为四类：

**集合**：各个元素同属一个集合，**别无其他关系**。

**线性结构**：元素之间是**一对一**的关系——除第一个元素外，所有元素都有唯一前驱；除最后一个元素外，所有元素都有唯一后继。

**树形结构**：元素之间是**一对多**的关系。

**图状结构**：又称网状结构，元素之间是**多对多**的关系。

![四种逻辑结构](/notes-assets/dsa1-02-logical-structure.jpg)

| 逻辑结构 | 关系类型 | 前驱-后继特征 | 典型示例 |
| :--- | :--- | :--- | :--- |
| **集合** | 无关系 | 无前驱/后继约束 | 散列表中的元素 |
| **线性结构** | 一对一 | 首元素无前驱，尾元素无后继 | 数组、链表、栈、队列 |
| **树形结构** | 一对多 | 根结点无前驱，叶子结点无后继 | 文件目录、组织架构 |
| **图状结构** | 多对多 | 无固定前驱/后继规律 | 社交网络、地图导航 |

> **记忆**：四种逻辑结构速记——**集合**（无关系）→ **线性**（一对一）→ **树形**（一对多）→ **图状**（多对多），关系从松散到紧密。

> **例 1（逻辑结构辨析）** 判断下列数据组织分别属于哪种逻辑结构：① 学生成绩表中按行排列的记录；② 公司的组织架构图；③ 社交网络中的好友关系。
>
> **思路**：抓住各类逻辑结构的本质——元素之间关系的"度数"：一对一、一对多、多对多；元素之间别无其他关系则为集合。**判断只看元素间的逻辑关系，与存储方式无关。**
>
> **解**：
> ① 成绩表中除首尾记录外，每行都有唯一前驱和唯一后继，属于**线性结构**；
> ② 组织架构中每个部门只有一个上级、可有多个下级，属于**树形结构**；
> ③ 任意两人之间都可能存在好友关系，属于**图状结构**。

#### 物理结构

**物理结构**也叫存储结构，是计算机表示数据元素逻辑关系的方式，即"逻辑结构在内存里长什么样"。逻辑结构是抽象的，物理结构却可以多种多样，常见的有四类：

**顺序存储**：把逻辑上相邻的元素存储在物理位置上也相邻的存储单元中，元素之间的关系由存储单元的衔接关系直接体现。

**链式存储**：逻辑上相邻的元素在物理位置上可以不相邻，借助指示元素存储地址的**指针**来表示元素之间的逻辑关系。

**索引存储**：在存储元素信息的同时建立附加的**索引表**；索引表中的每项称为索引项，一般形式为（关键字，地址）。

**散列存储**：根据元素的关键字直接计算出该元素的存储地址，又称哈希存储。

![四种物理结构](/notes-assets/dsa1-03-physical-structure.jpg)

| 存储结构 | 存储方式 | 逻辑关系体现方式 | 物理连续性 |
| :--- | :--- | :--- | :---: |
| **顺序存储** | 连续存储单元 | 存储单元的相邻关系 | 必须连续 |
| **链式存储** | 任意位置 + 指针 | 指针指示 | 可以离散 |
| **索引存储** | 数据区 + 索引表 | 索引项（关键字 → 地址） | 可以离散 |
| **散列存储** | 哈希函数映射 | 关键字直接计算地址 | 可以离散 |

> **注意**：存储结构的选择直接影响**存储空间分配的方便程度**和**数据运算的速度**。顺序存储支持随机访问（$O(1)$ 定位），非顺序存储支持灵活的动态扩容——两者各有代价，没有绝对优劣，需结合运算需求选择。

#### 数据的运算

施加在数据上的运算包括**运算的定义**和**运算的实现**两个层面：

**运算的定义**针对逻辑结构，指出运算的功能——"做什么"。

**运算的实现**针对存储结构，指出运算的具体操作步骤——"怎么做"。

| 运算 | 定义（做什么） | 实现（怎么做） |
| :--- | :--- | :--- |
| **入队** | 在队尾插入新元素 | 依存储结构而定（后续章节展开） |
| **出队** | 删除队头元素 | 依存储结构而定（后续章节展开） |

> **三要素的关系**：**逻辑结构**定义"是什么关系"，**物理结构**决定"怎么存储"，**数据的运算**描述"能做什么"。逻辑结构抽象、物理结构具体，两者共同决定了运算的效率。

> **易错点**：逻辑结构与存储结构不是一回事。逻辑结构抽象、与机器无关；存储结构具体、依赖存储介质。**一种逻辑结构可以用多种存储结构实现**——顺序表和链表都是线性结构，区别只在存储方式。

### 解决问题方法效率的有关因素

同一个问题，选用不同的数据处理方案，效率可能天差地别。影响效率的主要有三个因素：

- **数据的组织方式**——同样的数据，按线性表组织还是按树组织，查找代价可能从 $O(n)$ 降为 $O(\log n)$
- **空间的利用效率**——存储密度不同，内存开销不同
- **算法的巧妙程度**——同一个问题，暴力枚举与巧妙算法的时间开销往往相差几个数量级

这正是学习数据结构与算法的意义：**选择好的数据组织方式与算法，往往比提升硬件更有效**。

### 数据类型

**数据类型**是一个**值的集合**和定义在此集合上的**一组操作**的总称。例如 `int` 类型就是 $\{-2^{31}, \cdots, 2^{31}-1\}$ 这个整数集合，与加、减、乘、除、取模等操作的统一体。类型既约束取值范围，也规定可施加的操作。

按值是否可再分，数据类型分为两类：

#### 原子类型

其值**不可再分**的数据类型。

#### 结构类型

其值**可以再分解为若干成分（分量）**的数据类型。

| 对比维度 | 原子类型 | 结构类型 |
| :--- | :--- | :--- |
| **可分性** | 值不可再分 | 可分解为若干分量 |
| **示例** | `bool`、`int`、`float`、`char` | `struct`、`class`、`union` |
| **典型场景** | 基本运算 | 复合实体建模 |

例如用 C/C++ 的结构体建模"人"：

```cpp
struct Person
{
    String name;  // 名字
    int age;      // 年龄
    // ……         // 其他必要信息
};
```

其中 `age` 是原子类型 `int`，而整个 `Person` 是结构类型——它的值可以分解为 `name`、`age` 等分量。

### 抽象数据类型

**抽象数据类型**（Abstract Data Type，ADT）指**抽象数据组织及与之相关的操作**：它用数学化的语言定义数据的逻辑结构和运算，**与具体的实现无关**。

#### ADT 的书写格式

```
ADT 抽象数据类型名 {
    数据对象：
    数据关系：
        数据元素之间的逻辑关系的定义
    基本操作：
        操作1
        操作2
        ……
        操作n
} ADT 抽象数据类型名
```

#### 抽象的价值

ADT 的价值在于"抽象"——使用者只需知道"能做什么"，无需关心"怎么做"，从而把设计与实现分离开来。

> **易错点**：ADT 只定义逻辑结构与运算，**不给出具体实现**。用顺序表还是链表来实现入队，属于"实现"层面的事，ADT 不管——这正是"抽象"两个字的含义。

#### 例：用 ADT 描述队列

**例 2** 用 ADT 语言描述"队列"这一数据结构。

**思路**：按 ADT 标准格式依次给出数据对象、数据关系与基本操作；基本操作只写"做什么"（定义），不写"怎么做"（实现）。

**解**：

```
ADT Queue {
    数据对象：D = { a_i | a_i ∈ ElemType, i = 1, 2, …, n, n ≥ 0 }
    数据关系：R = { <a_{i-1}, a_i> | a_{i-1}, a_i ∈ D, i = 2, 3, …, n }
              —— 元素按线性关系排列，一端为队头，另一端为队尾
    基本操作：
        InitQueue(&Q)      // 初始化：构造空队列
        EnQueue(&Q, x)     // 入队：在队尾插入元素 x
        DeQueue(&Q, &x)    // 出队：删除队头元素，并由 x 返回其值
        QueueEmpty(Q)      // 判空：队列为空返回 true
} ADT Queue
```

这里体现的正是"运算的定义 vs 实现"的分工：ADT 只给出定义层，入队"在队尾插入"的具体步骤（用顺序表还是链表实现）留待后续章节。

## 算法

如果说数据结构是程序的"骨架"，那么**算法**就是程序的"灵魂"——数据是处理的对象，算法是处理的步骤

**算法**（Algorithm）是对特定问题求解步骤的一种描述，它是指令的有限序列，其中的每条指令表示一个或多个操作。例如"二分查找"就是解决"在有序表中查找某个值"这一问题的一组步骤描述。

### 算法的五大特性

一个算法必须满足以下五个特性：

| 特性 | 含义 | 关键要点 |
| :--- | :--- | :--- |
| **有穷性** | 执行有穷步后结束，每一步在有穷时间内完成 | 算法必须是有穷的，而程序可以是无穷的 |
| **确定性** | 每条指令有确切的含义 | 相同输入 → 相同输出 |
| **可行性** | 操作可通过已实现的基本运算有限次执行 | 不可包含无法实现的操作 |
| **输入** | 零个或多个输入 | 取自特定对象的集合 |
| **输出** | 一个或多个输出 | 输出与输入存在特定关系 |

> **注意**：算法 ≠ 程序。程序可以无限运行（例如操作系统），但算法必须在有限步骤之后终止——**有穷性**是算法与程序最根本的区别。

### 优秀算法的四个特质

满足五大特性只是"算法"的及格线。优秀的算法还应具备四个特质：

| 特质 | 含义 |
| :--- | :--- |
| **正确性** | 算法应能够正确地解决问题 |
| **可读性** | 算法应具有良好的可读性，以帮助人们理解 |
| **健壮性** | 输入非法数据时，算法能适当地做出反应或进行处理，而不会产生莫名其妙的输出结果 |
| **高效性** | 算法执行省时、不费内存，即时间复杂度和空间复杂度低 |

> **注意**：这四个特质存在优先级——**正确性 > 健壮性 > 可读性 > 高效性**。一个高效但结果错误的算法没有意义；在保证正确的前提下，再依次追求健壮、可读、高效。

### 程序 = 数据结构 + 算法

$$
\text{程序} = \text{数据结构} + \text{算法}
$$

这是计算机科学最经典的等式之一：**数据结构是要处理的信息的组织方式，算法是处理这些信息的步骤**。数据结构是程序的"内容"，算法是程序的"过程"，二者缺一不可。

| 维度 | 数据结构 | 算法 |
| :--- | :--- | :--- |
| **关注点** | 数据的组织方式 | 处理数据的步骤 |
| **核心问题** | 如何存储？ | 如何计算？ |
| **三要素 / 五特性** | 逻辑结构、物理结构、运算 | 有穷性、确定性、可行性、输入、输出 |
| **效率指标** | 存储密度、空间利用率 | 时间复杂度、空间复杂度 |
| **评价标准** | 是否便于运算 | 是否高效、正确 |
| **两者关系** | 算法处理的对象 | 操作数据结构的方法 |

算法之所以重要，有两条理由：

- 算法联系着数据在计算机中的组织方式——好的算法往往依托恰当的数据组织；
- 算法是研究数据结构的重要途径——数据结构的优劣，最终要通过算法（运算）的效率来检验。

### 算法的时间复杂度

两个都能解决问题的算法，如何比较优劣？本节建立统一的度量工具：**时间复杂度** $T(n)$ 与**空间复杂度** $S(n)$。它们用大 O 表示法刻画算法开销随问题规模 $n$ 增长的趋势，与机器、语言、编译器无关——这是理论分析的基石，也是全书一切"复杂度结论"的出处。

#### 时间复杂度的度量方法

| 方法 | 做法 | 优缺点 |
| :--- | :--- | :--- |
| **事后统计** | 实际运行程序，测量执行时间和内存占用 | 直观，但受机器、语言、编译器影响 |
| **事前分析估算** | 分析算法本身的复杂度，不运行程序 | 客观，与运行环境无关，是理论分析的主流方法 |

同样一段代码，实测运行时间受多种环境因素干扰，所以必须剥离环境因素做"事前分析"：

| 影响因素 | 举例 |
| :--- | :--- |
| 机器性能 | 超级计算机 vs 单片机 |
| 编程语言 | C vs Java（越高级的语言执行效率越低） |
| 编译程序产生的机器指令质量 | — |
| 算法采用的策略、方法 | — |
| 问题的输入规模 | — |

**时间复杂度**就是事前预估算法时间开销 $T(n)$ 与问题规模 $n$ 的关系。问题规模 $n$ 通常指输入数据的规模（如数组长度、矩阵阶数）。它只依赖算法本身，因此可以客观比较。

> **易错点**：时间复杂度**不是**实际运行时间，不能用秒来衡量。它描述的是开销随 $n$ 增长的**趋势**，与机器、语言无关。

#### 时间复杂度的表示记号

当 $n$ 趋于无穷大时，$T(n)$ 的增长速度由最高阶项主导。为刻画这种渐近增长，引入以下记号：

| 记号 | 名称 | 定义 | 常用程度 |
| :---: | :--- | :--- | :---: |
| $O(f(n))$ | 大 O（上界） | $T(n) \le C \cdot f(n)$（当 $n \ge n_0$） | 最常用 |
| $\Omega(g(n))$ | 大 Ω（下界） | $T(n) \ge C \cdot g(n)$（当 $n \ge n_0$） | 较少使用 |
| $\Theta(h(n))$ | 大 Θ（确界） | $T(n) = O(h(n))$ 且 $T(n) = \Omega(h(n))$ | 精确分析时使用 |
| $o(p(n))$ | 小 o（非紧上界） | $T(n) = O(p(n))$ 且 $T(n) \ne \Theta(p(n))$ | 偶尔使用 |

最常用的是大 O 表示法，它刻画"同阶"关系：$T(n) = O(f(n))$ 意味着 $T(n)$ 与 $f(n)$ 是**同阶无穷大**，即

$$
\lim_{n \to \infty} \frac{T(n)}{f(n)} = c \quad (c \text{ 为正常数})
$$

判断算法效率时，函数中的常数和其他次要项常常可以忽略，只需关注**主项（最高阶项）的阶数**。

> **易错点**：大 O 不是精确值，而是**渐近上界**。$T(n) = O(n)$ 表示开销随 $n$ 至多线性增长，常数项与低阶项都被忽略了——$3n + 3$ 与 $3n$ 同阶，都是 $O(n)$。

#### 例：用语句频度求时间复杂度

**例 3** 求下列程序的时间复杂度。

```cpp
int main()
{
    int i = 1, n = 3000;  // 语句1
    while (i <= n)         // 语句2
    {
        i++;               // 语句3
        printf("%d\n", i); // 语句4
    }
    printf("%d\n", n);     // 语句5
}
```

**思路**：先统计每条语句的**执行次数（语句频度）**，累加得到 $T(n)$，再取最高阶项。注意循环条件（语句2）比循环体多执行一次——这是频度统计最容易漏掉的细节。

**解**：各语句的频度如下：

| 语句 | 频度 |
| :--- | :---: |
| 语句1 | 1 次 |
| 语句2 | 3001 次 |
| 语句3、4 | 3000 次 |
| 语句5 | 1 次 |

总时间开销：

$$
T(3000) = 1 + 3001 + 2 \times 3000 + 1 = 9003
$$

推广到一般规模 $n$：

$$
T(n) = 3n + 3 \approx 3n = O(n)
$$

实际分析时不必逐条语句累加，只需挑循环中**一个基本操作**（如 `i++`），分析其执行次数与 $n$ 的关系即可。同类结论：$T(n) = n^2 + 3n + 3 \Rightarrow O(n^2)$；$T(n) = n^3 + n^2 + 3n + 3 \Rightarrow O(n^3)$。

#### 例：嵌套循环的复杂度

**例 4** 求下列程序的时间复杂度。

```cpp
int main()
{
    int n = 100;
    for (int i = 1; i <= n; i++)       // 外层循环
        for (int j = 1; j <= n; j++)   // 内层循环
            x++;                       // 基本操作
}
```

**思路**：多层嵌套循环只需关注**最深层循环**的执行次数。外层每执行 1 次，内层执行 $n$ 次，共 $n$ 轮。

**解**：基本操作 `x++` 的执行次数为 $n \times n = n^2$ 次，故

$$
T(n) = O(n^{2})
$$

"只需关注最深层循环"是分析嵌套循环的统一捷径。若内层循环上界依赖外层变量（如 $j \le i$），则需对 $i$ 求和：

$$
\sum_{i=1}^{n} i = \frac{n(n+1)}{2} = O(n^2)
$$

结论不变。

#### 加法规则与乘法规则

多个程序段组合时，复杂度按以下法则合成：

| 法则 | 公式 | 说明 |
| :--- | :--- | :--- |
| **加法规则** | $T(n) = O(f(n)) + O(g(n)) = O(\max(f(n), g(n)))$ | 多项相加，只保留最高阶的项，且系数变为 1 |
| **乘法规则** | $T(n) = O(f(n)) \times O(g(n)) = O(f(n) \times g(n))$ | 多项相乘，都保留 |

由此可以总结出三条简化分析的结论：

- 顺序执行的代码只会影响常数项，可以忽略；
- 只需挑循环中的一个基本操作，分析它的执行次数与 $n$ 的关系；
- 有多层嵌套循环时，只需关注最深层循环的执行次数。

#### 常见阶数与记忆口诀

常见复杂度从低到高排列：

$$
O(1) < O(\log_2 n) < O(n) < O(n \log_2 n) < O(n^{2}) < O(n^{3}) < O(2^{n}) < O(n!) < O(n^{n})
$$

| 阶数 | 名称 | 典型算法 |
| :--- | :--- | :--- |
| $O(1)$ | 常数级 | 数组随机访问、哈希查找 |
| $O(\log n)$ | 对数级 | 二分查找 |
| $O(n)$ | 线性级 | 顺序查找、遍历 |
| $O(n \log n)$ | 线性对数级 | 归并排序、快速排序（平均） |
| $O(n^{2})$ | 平方级 | 冒泡排序、选择排序 |
| $O(n^{3})$ | 立方级 | Floyd 算法 |
| $O(2^{n})$ | 指数级 | 子集枚举 |
| $O(n!)$ | 阶乘级 | 全排列枚举 |

记忆口诀是**常对幂指阶**：常数级 → 对数级 → 线性级 → 线性对数级 → 幂级 → 指数级 → 阶乘级，由快到慢依次记。

把 $n = 100$ 代进去，能直观感受到阶数差异有多大：

| 阶数 | 名称 | 当 $n=100$ 时的量级 | 可行性 |
| :---: | :--- | :---: | :---: |
| $O(1)$ | 常数级 | 1 | 最优 |
| $O(\log n)$ | 对数级 | ≈7 | 优秀 |
| $O(n)$ | 线性级 | 100 | 良好 |
| $O(n \log n)$ | 线性对数级 | ≈700 | 可接受 |
| $O(n^{2})$ | 平方级 | 10,000 | 谨慎 |
| $O(n^{3})$ | 立方级 | 1,000,000 | 小规模可用 |
| $O(2^{n})$ | 指数级 | ≈$1.27 \times 10^{30}$ | 不可行 |
| $O(n!)$ | 阶乘级 | ≈$9.33 \times 10^{157}$ | 不可行 |

> **易错点**：对数阶的**底数不影响复杂度**。换底公式只差一个常数倍，所以 $\log_2 n$ 与 $\log_{10} n$ 同阶，统一记作 $O(\log n)$。

#### 最好、最坏与平均时间复杂度

同一算法对不同输入，时间开销可能不同，因此按输入情况把时间复杂度分为三类：

**最好时间复杂度**：最理想输入下的复杂度，参考意义有限。

**最坏时间复杂度**：最坏输入下的复杂度，提供**上界保证**，是最常用的一类。

**平均时间复杂度**：所有输入等概率下的期望值，更贴近实际场景。

分析时一般都计算最坏时间复杂度和平均时间复杂度。最坏时间复杂度给出了算法效率的**上界保证**——无论输入如何，实际开销都不会超过它。

### 算法的空间复杂度

**空间复杂度**指事前预估算法空间开销 $S(n)$ 与问题规模 $n$ 之间的关系，与时间复杂度一样使用大 O 表示法。

计算时只需关注**存储空间大小与问题规模相关**的变量，与规模无关的固定开销（如若干常量变量）可以忽略：

| 变量类型 | 空间复杂度 |
| :--- | :---: |
| **一维数组** | $S(n) = O(n)$ |
| **二维数组** | $S(n) = O(n^{2})$ |
| **递归函数** | $S(n) = \text{递归调用的深度}$ |

#### 原地工作

若无论问题规模怎么变，算法运行所需的内存空间都是固定常量，就称该算法**原地工作**，此时 $S(n) = O(1)$。

#### 例：递归的空间复杂度

**例 5** 求递归计算 $n!$ 的算法的空间复杂度。

```cpp
int factorial(int n)
{
    if (n == 0 || n == 1) return 1;  // 递归出口
    return n * factorial(n - 1);     // 递归调用
}
```

**思路**：递归函数每调用一层，系统就要在栈中分配一块空间保存参数与返回地址，因此空间开销等于**递归调用的深度**。

**解**：调用链为 `factorial(n) → factorial(n-1) → … → factorial(1)`，共 $n$ 层，故

$$
S(n) = O(n)
$$

对比：若用循环迭代实现同样的功能，只需几个常量变量，$S(n) = O(1)$，属于**原地工作**。

> **易错点**：递归算法的空间复杂度**不是**数一数用了几个变量，而是看**递归深度**——每一层调用都要占一块栈空间。递归写起来简洁，但空间代价可能高达 $O(n)$，规模很大时要考虑改写为迭代。

#### 时间与空间的权衡

工程中常通过**牺牲空间来换取时间**（如缓存、预计算表）。时间与空间往往存在权衡，需根据实际场景取舍。

## 小结

1. 数据、数据元素、数据项是三个不同粒度：数据是全体，数据元素是基本单位，数据项是不可再分的最小单位。
2. 数据结构的三要素是逻辑结构、物理结构与数据的运算；**一种逻辑结构可以用多种存储结构实现**。
3. 逻辑结构只有四种：集合、线性、树形、图状，对应关系的四种"度数"。
4. 算法有五大特性（有穷、确定、可行、输入、输出）与四个追求（正确、可读、健壮、高效），有穷性是它与程序的根本区别。
5. 时间复杂度是渐近趋势而非实际耗时，用大 O 刻画上界，常数与低阶项都被忽略。
6. 常见阶数记**常对幂指阶**，对数阶不看底数；分析时只看循环中的基本操作与最深层循环。
7. 递归算法的空间复杂度等于递归深度——这是它比迭代版多出来的那部分开销。
