## 树

### 树的基本概念

#### 树的定义

**树**（Tree）是 $n$（$n \ge 0$）个结点的有限集合。没有后继的结点称为**叶子结点**（终端结点），有后继的结点称为**分支结点**（非终端结点），结点数为 0 的树称为**空树**，记为 $\varnothing$。

![一棵树的形态](/notes-assets/dsa5-01-tree.jpg)

> **注意**：树与二叉树是**两种不同的数据结构**，不是包含关系：树的每个结点可以有任意多个子结点且子树无序，二叉树的每个结点至多 2 个子结点且左右有序。任何树都能通过"左孩子右兄弟"规则唯一地转换为二叉树，所以二叉树的算法可以间接作用在一般树上。

#### 非空树的特性

非空树满足三条特性：① 有且仅有一个**根结点**；② 除根结点外，任何一个结点都有且仅有一个前驱；③ 当 $n > 1$ 时，其余结点可分为 $m$（$m > 0$）个互不相交的有限集合 $T_1, \dots, T_m$，其中每个集合本身又是一棵树，称为根结点的**子树**。

![非空树的特性](/notes-assets/dsa5-02-nonempty-tree-properties.jpg)

第 ③ 条就是树的**递归定义**：一棵树由根和若干棵子树组成，而子树又是树。**空树是任何树的子树**——这条约定保证递归定义能够自洽地终止。

#### 结点之间的关系

判断亲属关系时先分清两件事：这是"可达"关系，还是"同层同亲"关系。

**祖先与子孙**：若 $a \neq d$ 且 $a$ 可达 $d$，则 $a$ 是 $d$ 的**祖先结点**，$d$ 是 $a$ 的**子孙结点**（可跨越若干层）。

**孩子与双亲**：若结点 $a$ 邻接到结点 $b$，则 $b$ 是 $a$ 的**孩子结点**（子结点），$a$ 是 $b$ 的**双亲结点**（父结点）。

**兄弟与堂兄弟**：

若 $b$、$c$ 同为 $a$ 的孩子，则 $b$、$c$ 互为**兄弟结点**。

若 $b$、$c$ 不互为兄弟但祖先相同，则 $b$、$c$ 互为**堂兄弟结点**。

#### 路径与路径长度

自上而下的通路称为**路径**，路径经过的边数称为**路径长度**。

#### 度、深度、高度与层次

| 属性 | 结点的 | 树的 |
| :--- | :--- | :--- |
| **度**（Degree） | 该结点的孩子数量 | 各结点度的最大值 |
| **深度**（Depth） | 从根到该结点的路径长度（从上往下） | 最大深度 |
| **高度**（Height） | 从该结点到最远叶子的路径长度（从下往上） | 根结点的高度 |
| **层次**（Level） | 根为第 1 层，孩子层次 = 双亲层次 + 1 | — |

深度与高度是两个方向相反的概念，由此得到三条常用结论：**深度从根向下数，高度从叶子向上数**（最好用的一句口诀）；结点的高度 = 树的高度 − 结点的深度 + 1；根结点的深度最小、高度等于树高，叶子结点的高度为 1。

> **注意**：树的深度与高度数值相等（都等于最大层数），但**结点的深度与结点的高度一般不相等**。层号从 0 开始还是从 1 开始，不同约定相差恰好 1，使用公式前先确认自己采用的是哪一种。

#### 有序树与无序树

- **有序树**：逻辑上各结点的子树从左至右有序，不能互换；
- **无序树**：逻辑上各结点的子树从左至右无序，可以互换。

**二叉树是有序树**（左右子树不能颠倒）；一般树默认按无序树处理，除非特别声明。

#### 树的四种表示法

同一棵树有四个等价的描述视角：

| 表示法 | 方式 | 特点 |
| :--- | :--- | :--- |
| **树形表示法** | 倒置树结构，根在上、叶在下，用线段连接双亲与孩子 | 最直观、最常用 |
| **广义表表示法** | 嵌套括号 `A(B(D,E),C(F,G))`，根后跟各子树的括号序列 | 便于程序输入与存储 |
| **文氏图表示法** | 嵌套集合，每棵子树是包含在父集合圆内的子集 | 突出层次包含关系 |
| **凹入表示法** | 每层缩进固定宽度，同层结点对齐 | 类似目录树／大纲视图 |

![树的四种表示法](/notes-assets/dsa5-03-tree-representations.jpg)

> **注意**：四种表示法各有主场——树形适合手绘与理解结构；广义表是程序输入的标准格式（第 7 节的括号表示法建树就解析这种串）；文氏图常见于集合论与分类学；凹入表示法广泛用于文件管理器、Markdown 标题层级与书籍目录。理解四者的等价性，才算真正掌握树的结构。

#### 森林

**森林**（Forest）是 $m$（$m \ge 0$）棵互不相交的树的集合。给森林添加一个统一的根结点，森林即变成一棵树；删去树的根结点，树即变成森林。这条转化关系是第 9 节"树与森林 → 二叉树"的基础。

### 树的性质

树的所有计数公式都只源于两个事实：**除根以外每个结点恰好贡献一条入边**，以及**满树是结点数的极端情况**。掌握这两个源头，公式不必死记。

#### 结点数 = 总度数 + 1

设树的结点数为 $n$，各结点的度分别为 $d_1, d_2, \dots, d_n$，则

$$
n = \sum_{i=1}^{n} d_i + 1
$$

**推导**：树中除根结点以外的每个结点都恰好有一个前驱，即贡献一个入度；而所有结点的入度之和等于出度之和（总度数），于是总度数 $= n - 1$，移项即得。它只用到"每个非根结点只有一个双亲"，因此对**任意**树（含多叉树）都成立。

> **例 1（由度数求叶子数）** 一棵树中有 3 个度为 2 的结点和 2 个度为 3 的结点，其余结点都是叶子，求叶子结点数。

**思路**：先用"结点数 = 总度数 + 1"求出总结点数，再用"总结点数 − 非叶子结点数"得到叶子数。

**解**：总度数 $= 3 \times 2 + 2 \times 3 = 12$，故总结点数 $n = 12 + 1 = 13$，叶子数 $= 13 - 3 - 2 = 8$。

**要点**：$n = \sum d_i + 1$ 对任意树成立；二叉树的 $n_0 = n_2 + 1$（第 3 节）是它在二叉树上的特例，两者层次不同，不要混用。

#### 度为 m 的树与 m 叉树

**$m$ 叉树**指每个结点最多只能有 $m$ 个孩子的树。"度为 $m$ 的树"与"$m$ 叉树"只差一个字，含义却不同：

| 对比维度 | 度为 m 的树 | m 叉树 |
| :--- | :--- | :--- |
| 结点度数 | 任意结点度 $\le m$ | 任意结点度 $\le m$ |
| 是否严格约束 | **是**：至少有一个结点度 $= m$ | **否**：允许所有结点度 $< m$ |
| 空树 | 不允许（至少 $m+1$ 个结点） | 允许 |
| 最少结点数（高度 h） | $h + m - 1$ | $h$ |
| 严格程度 | 严格（必须"达标"） | 宽容（只设"上限"） |

> **注意**：记忆口诀——度为 $m$ 的树"**严格**"（必须存在度为 $m$ 的结点），$m$ 叉树"**宽容**"（只要求最大度不超过 $m$）。判断"是不是 $m$ 叉树"只看最大度是否 $\le m$；判断"是不是度为 $m$ 的树"还要额外检查是否存在度为 $m$ 的结点。表中最少结点数一行的 $h + m - 1$ 只在 $h \ge 2$ 时有意义——高度为 1 的树只有根结点，不可能出现度为 $m > 0$ 的结点。

#### 层数上限与最小高度

度为 $m$ 的树第 $i$ 层至多有 $m^{i-1}$ 个结点（$i \ge 1$）；高度为 $h$ 的 $m$ 叉树至多有 $\frac{m^h - 1}{m - 1}$ 个结点、至少有 $h$ 个结点。**推导**：要让某一层的结点最多，就让上一层每个结点都长满 $m$ 个孩子，于是第 1 层 $1 = m^0$ 个、第 2 层至多 $m$ 个、第 3 层至多 $m^2$ 个……把 $h$ 层相加，得到等比数列求和公式。$m = 2$ 时退化为二叉树：第 $i$ 层至多 $2^{i-1}$ 个，总结点至多 $2^h - 1$ 个。

具有 $n$ 个结点的 $m$ 叉树的最小高度为

$$
h_{\min} = \lceil \log_m (n(m-1) + 1) \rceil
$$

**推导**：高度最小意味着结点尽量塞满每一层，即前 $h-1$ 层全满、第 $h$ 层不满，于是

$$
\frac{m^{h-1} - 1}{m - 1} < n \le \frac{m^h - 1}{m - 1}
$$

两边同乘 $m - 1$ 再加 1，得 $m^{h-1} < n(m-1) + 1 \le m^h$；取以 $m$ 为底的对数并向上取整，即得

$$
h-1 < \log_m (n(m-1) + 1) \le h \quad \Longrightarrow \quad h_{\min} = \lceil \log_m (n(m-1) + 1) \rceil
$$

> **例 2（m 叉树最小高度）** 求 50 个结点的 3 叉树的最小高度。

**思路**：直接套用 $h_{\min} = \lceil \log_m (n(m-1) + 1) \rceil$，再用"满树结点数夹逼"验证。

**解**：$h = \lceil \log_3 (50 \times 2 + 1) \rceil = \lceil \log_3 101 \rceil = \lceil 4.19 \rceil = 5$。验证：3 层满树 $1 + 3 + 9 = 13$ 个结点不够，4 层满树 $13 + 27 = 40$ 个仍不够，5 层满树 $40 + 81 = 121$ 个够了。

**要点**：公式的几何意义是"把结点尽量塞满每一层"，最小高度必然出现在"前 $h-1$ 层全满、最后一层不满"的形态。手算时先算 $\log$ 值再**向上取整**，不要四舍五入。所有上限公式都来自"满 $m$ 叉树"、所有下限公式都来自"单链"，$m = 2$ 时全部退化为二叉树的情形。

## 二叉树

### 二叉树的基本概念

二叉树是本章乃至整门课最重要的结构：它把"一对多"压缩为"至多两个分支"，从而获得优雅的递归定义与一套编号性质。**结论先行**——二叉树的一切定理都建立在两条定义之上：子树至多两棵（于是结点只有度 0、1、2 三种），以及左右有序（于是"只有左孩子"和"只有右孩子"是两棵不同的树）。

#### 二叉树的定义与形态

**二叉树**（Binary Tree）是 $n$（$n \ge 0$）个结点的有限集合：或者为空二叉树（$n = 0$），或者由一个根结点和两棵互不相交的、分别称为根的**左子树**与**右子树**的二叉树组成。

两条基本特点：每个结点至多只有两棵子树（不存在度大于 2 的结点）；**左右子树不能颠倒**（二叉树是有序树）。

![二叉树](/notes-assets/dsa5-04-binary-tree.jpg)

因为左右有序，二叉树的形态在"空／非空"与"孩子在左／在右"的组合下共有**五种**：

| 形态 | 说明 |
| :--- | :--- |
| **空二叉树** | 没有任何结点 |
| **只有根结点** | 左、右子树均为空 |
| **只有左子树** | 左子树非空，右子树为空 |
| **只有右子树** | 右子树非空，左子树为空 |
| **左、右子树都非空** | 根同时拥有两侧子树 |

> **注意**：五种形态中，"只有左子树"与"只有右子树"是两棵**不同**的二叉树。正因如此，只给出前序 + 后序序列时无法唯一确定一棵二叉树（第 6 节会展开）。另外，二叉树的定义是**递归**的——左右子树本身又是二叉树，这决定了后面所有遍历算法天然地用递归实现。

#### 特殊二叉树

| 类型 | 定义 | 关键特征 | 主要用途 |
| :--- | :--- | :--- | :--- |
| **满二叉树** | 高度为 $h$，含 $2^h - 1$ 个结点 | 每层都满；不存在度为 1 的结点 | 理论分析的基准形态 |
| **完全二叉树** | 与同高度满二叉树的编号 $1 \sim n$ **一一对应** | 叶子只出现在最后两层；至多一个度为 1 的结点 | 堆、顺序存储 |
| **二叉排序树**（BST） | 左子树所有关键字 < 根 < 右子树所有关键字 | 中序遍历得到有序序列 | 动态查找、插入、删除 |
| **平衡二叉树**（AVL） | 任一结点左右子树高度差 $\le 1$ | 查找效率稳定在 $O(\log n)$ | 高效查找 |

![特殊的二叉树](/notes-assets/dsa5-05-special-binary-trees.jpg)

> **注意**：**满二叉树是特殊的完全二叉树**，反之不成立。判断完全二叉树的标准是"**是否与满二叉树的前 $n$ 个结点编号一一对应**"，而不是"除最后一层外每层都满"。一棵每层都有结点、但编号不连续的树（例如某个分支结点只有左孩子、而它右侧的兄弟却有两个孩子）不是完全二叉树。

#### 完全二叉树的编号性质

对完全二叉树按层序从 1 开始编号，就得到一组可以当公式用的下标关系：

**左右孩子编号**：结点 $i$ 的左孩子为 $2i$，右孩子为 $2i + 1$。

**双亲编号**：非根结点 $i$ 的双亲为 $\lfloor i/2 \rfloor$。

**分支与叶子**：$i \le \lfloor n/2 \rfloor$ 的是**分支结点**，$i > \lfloor n/2 \rfloor$ 的是**叶子结点**。

这组性质是**完全二叉树专属**的（顺序存储与堆排序都依赖它），对普通二叉树不成立。

### 二叉树的核心性质

#### 叶子与二分支结点

**性质 1**：设非空二叉树中度为 0、1、2 的结点个数分别为 $n_0$、$n_1$、$n_2$，则

$$
n_0 = n_2 + 1
$$

即**叶子结点总比二分支结点多一个**。**推导**：结点总数 $n = n_0 + n_1 + n_2$；另一方面，除根以外每个结点都提供一条边，所以总边数 $= n - 1 = n_1 + 2n_2$。两式联立消去 $n$，即得 $n_0 = n_2 + 1$。

#### 层数与结点上限

**性质 2**：二叉树第 $i$ 层至多有 $2^{i-1}$ 个结点；高度为 $h$ 的二叉树至多有 $2^h - 1$ 个结点（此时即满二叉树）。

#### 完全二叉树的高度

**性质 3**：具有 $n$（$n > 0$）个结点的完全二叉树的高度为 $h = \lceil \log_2 (n+1) \rceil = \lfloor \log_2 n \rfloor + 1$。**推导**：完全二叉树前 $h-1$ 层全满、第 $h$ 层不满，于是 $2^{h-1} \le n < 2^h$，等价地 $2^{h-1} < n + 1 \le 2^h$，取对数并向上取整即得。

#### 度为 1 的结点

**性质 4**：度为 1 的结点个数 $n_1 = 0$ 或 $1$；$n_0 + n_2$ 一定是奇数（因为 $n_0 + n_2 = 2n_2 + 1$）；推论：若 $n = 2k$（偶数），则 $n_1 = 1$、$n_0 = k$、$n_2 = k - 1$，若 $n = 2k - 1$（奇数），则 $n_1 = 0$、$n_0 = k$、$n_2 = k - 1$。

> **注意**：$n_0 = n_2 + 1$ 贯穿所有二叉树证明。记忆方法是：每个二分支结点"贡献"两个子结点位置，而总边数 = 结点数 − 1，两式联立即得。它在哈夫曼树（不存在度为 1 的结点，于是 $n_0 = n_2 + 1$ 且 $n = 2n_0 - 1$）中同样关键。另外，$n_1 \le 1$ 是**完全**二叉树的性质，不是所有二叉树的性质——普通二叉树完全可以有多个度为 1 的结点。

> **例 1（完全二叉树计数）** 设一棵完全二叉树有 768 个结点，求叶子结点数、度为 1 的结点数、度为 2 的结点数。

**思路**：$n = 768$ 是偶数，套用性质 4 的推论——$n = 2k$ 时 $n_1 = 1$、$n_0 = k$、$n_2 = k - 1$。

**解**：$k = 384$，故叶子结点 $n_0 = 384$，$n_1 = 1$，$n_2 = 383$。验证：$n_0 + n_1 + n_2 = 384 + 1 + 383 = 768$，且 $n_0 = n_2 + 1 = 384$。

**要点**：完全二叉树中度为 1 的结点至多 1 个。当 $n$ 为偶数时，最后一层多出的那个结点只能挂在其双亲的**左**孩子位置（否则编号不连续），于是 $n_1 = 1$，口诀是"**偶 n 有单枝，奇 n 无单枝**"。

> **例 2（完全二叉树编号）** $n = 13$ 的完全二叉树，求：① 分支结点与叶子结点的编号范围；② 结点 5 的左、右孩子及双亲；③ 验证 $n_0 = n_2 + 1$。

**思路**：编号按层序从 1 开始；分支结点满足 $i \le \lfloor n/2 \rfloor$，孩子为 $2i$、$2i+1$，双亲为 $\lfloor i/2 \rfloor$。

**解**：① $\lfloor 13/2 \rfloor = 6$，故分支结点编号为 1~6，叶子结点编号为 7~13，共 7 片叶子。② 结点 5 的左孩子 $= 2 \times 5 = 10$，右孩子 $= 11$，双亲 $= \lfloor 5/2 \rfloor = 2$。③ $n = 13$ 为奇数，故 $n_1 = 0$、$n_0 = 7$、$n_2 = 6$，验证 $7 = 6 + 1$ 成立。

**要点**：快速判断叶子的口诀是"**编号大于 $\lfloor n/2 \rfloor$ 的一律是叶子**"。

### 二叉树的存储结构

二叉树的存储选型可以压缩成三句话：**完全二叉树用顺序存储**（编号即下标，空间最省），**通用二叉树用二叉链表**（默认选择），**需要频繁找双亲时用三叉链表**（多一个 parent 指针）。三者的差别说到底就是"哪一个方向的操作要变成 $O(1)$"。

#### 顺序存储

顺序存储用一维数组按"从上至下、从左至右"的层序存放结点，并用一个标记位记录该位置是否真的存在结点：

```c
const int MaxSize = 100;
struct TreeNode {
    ElemType value;   // 结点中的数据元素
    bool isEmpty;     // 该位置是否为空
};
TreeNode t[MaxSize];
for (int i = 0; i < MaxSize; i++)   // 初始化时把所有位置标记为空
    t[i].isEmpty = true;
```

![二叉树的顺序存储](/notes-assets/dsa5-06-sequential-storage.jpg)

下标从 1 开始的基本操作：结点 $i$ 的左孩子 $\to 2i$，右孩子 $\to 2i + 1$；双亲 $\to \lfloor i/2 \rfloor$；所在层次 $\to \lceil \log_2 (i+1) \rceil$ 或 $\lfloor \log_2 i \rfloor + 1$。

> **注意**：顺序存储**只适合完全二叉树**。最坏情况是高度为 $h$、只有 $h$ 个结点的单支树（每个结点都只有右孩子）：它至少需要 $2^h - 1$ 个存储单元，空间利用率只有 $\frac{h}{2^h-1}$，随高度呈指数级浪费。因此**非完全二叉树必须用链式存储**。

#### 二叉链表

```c
struct BiTNode {
    ElemType data;                     // 数据域
    struct BiTNode *lchild, *rchild;   // 左、右孩子指针
};
typedef BiTNode *BiTree;
```

![二叉链表](/notes-assets/dsa5-07-binary-linked-list.jpg)

$n$ 个结点的二叉链表共有 **$n+1$ 个空链域**。推导：$2n$ 个指针域中只有 $n-1$ 条边会真正占用一个指针，所以空链域 $= 2n - (n-1) = n+1$。

> **注意**：$n+1$ 个空链域是线索二叉树存在的数学基础（第 8 节）——线索二叉树正是利用这些空链域存放前驱／后继信息，从而把遍历所需空间从 $O(h)$ 降到 $O(1)$。二叉链表的优劣也很清楚：找左右孩子是 $O(1)$，寻找双亲必须从根遍历，代价 $O(n)$。

> **例 1（空链域计算）** 一棵有 15 个结点的二叉树用二叉链表存储，共有多少个空链域？若改用三叉链表呢？

**思路**：二叉链表空链域 $= 2n - (n-1) = n + 1$；三叉链表有 $3n$ 个指针域，但同样只被 $n-1$ 条边占用。

**解**：二叉链表空链域 $= 15 + 1 = 16$；三叉链表空链域 $= 3 \times 15 - 14 = 31$。

**要点**：三叉链表多出的 parent 指针让"找双亲"从 $O(n)$ 变为 $O(1)$，代价是每个结点多一个指针的开销。

#### 三叉链表

```c
struct BiTNode {
    ElemType data;
    struct BiTNode *lchild, *rchild;
    struct BiTNode *parent;            // 双亲指针
};
typedef BiTNode *BiTree;
```

三叉链表在二叉链表的基础上增加 parent 指针，使找双亲降为 $O(1)$。它也是线索二叉树的常见配套存储——先序线索找前驱、后序线索找后继都需要双亲信息。

#### 三种存储结构对比

| 对比维度 | 顺序存储 | 二叉链表 | 三叉链表 |
| :--- | :---: | :---: | :---: |
| **适用场景** | 完全二叉树 | 通用二叉树 | 需频繁找双亲 |
| **找左／右孩子** | $O(1)$（$2i$ / $2i+1$） | $O(1)$ | $O(1)$ |
| **找双亲** | $O(1)$（$\lfloor i/2 \rfloor$） | $O(n)$（需遍历） | $O(1)$ |
| **存储密度** | 最高（只存数据） | 中（2 指针／结点） | 低（3 指针／结点） |
| **空间浪费** | 最坏指数级（单支树） | 线性（$n+1$ 空链域） | 线性 |
| **内存连续性** | 连续（对缓存友好） | 离散 | 离散 |
| **动态扩容** | 困难 | 天然动态 | 天然动态 |

> **注意**：选型建议——堆排序／优先队列用**顺序存储**（完全二叉树，空间效率最高）；通用二叉树的遍历与操作默认用**二叉链表**；需要频繁找双亲时用**三叉链表**。

## 二叉树的遍历

遍历是二叉树所有操作的"访问总纲"。**结论先行**——把"访问根结点"这一步放在递归的两个子树之前、之间还是之后，就分别得到先序、中序、后序遍历；把"逐层推进"改成"先进先出"，就得到层序遍历。三种深度优先遍历的代码差别只有一行，但它们给出的序列可以反推出整棵树的结构，这才是遍历真正的价值。递归版本简短，但递归深度等于树高，单支树上会退化为 $O(n)$；非递归版本用**显式栈**手动管理上下文，是理解"递归的本质是栈"的最好练习。

### 先序、中序与后序遍历

**先序遍历**（NLR，根左右）：访问根 $\to$ 先序遍历左子树 $\to$ 先序遍历右子树。

**中序遍历**（LNR，左根右）：中序遍历左子树 $\to$ 访问根 $\to$ 中序遍历右子树。

**后序遍历**（LRN，左右根）：后序遍历左子树 $\to$ 后序遍历右子树 $\to$ 访问根。

![二叉树的先中后序遍历](/notes-assets/dsa5-08-traversal-orders.jpg)

> **注意**：三种遍历的记忆口诀——**区别只在于 `visit(T)` 的位置**：先序在最前面、中序在正中间、后序在最后面；左右子树的递归顺序永远不变（先左后右）。记住这一点就能瞬间写出三种遍历。

> **例 1（三种遍历序列）** 对下图所示的二叉树，分别写出先序、中序、后序遍历序列。

![先中后序遍历示例](/notes-assets/dsa5-09-traversal-example.jpg)

**思路**：先序"根左右"，每到一结点先访问再递归；中序"左根右"；后序"左右根"，递归执行即可。

**解**：先序遍历为 **ABDGECF**；中序遍历为 **DGBEAFC**；后序遍历为 **GDEBFCA**。

**要点**：三种序列中**中序序列是"分界神器"**——它能告诉我们哪些结点在根的左子树、哪些在右子树，第 6 节由遍历序列构造二叉树全靠它。写后序时记住"根一定在最后"，可以快速自查。

#### 遍历与表达式的对应

二叉树是表达式最自然的存储形式：**运算符是内部结点，操作数是叶子**。三种遍历恰好对应三种表达式：

| 遍历方式 | 表达式类型 | 别名 | 求值扫描方向 |
| :--- | :--- | :--- | :---: |
| 先序遍历 | 前缀表达式 | 波兰式（Polish Notation） | 从右往左 |
| 中序遍历 | 中缀表达式 | —（需添加界限符） | 需考虑优先级 |
| 后序遍历 | 后缀表达式 | 逆波兰式（Reverse Polish Notation） | 从左往右 |

![表达式分析树](/notes-assets/dsa5-10-expression-tree.jpg)

> **注意**：任意一棵表达式树，用不同方式遍历就得到三种表达式形式——这就是表达式转换的本质。后缀表达式天然无括号、无优先级歧义，正是编译器做表达式求值的标准形式。

> **例 2（表达式转换）** 将中缀表达式 $(a+b) \times (c-d)$ 转换为前缀表达式和后缀表达式。

**思路**：先画表达式树（根是**最后计算**的运算符），再按先序／后序遍历取序列。

**解**：表达式树的根为 $\times$，左子树是 $+$（孩子 $a$、$b$），右子树是 $-$（孩子 $c$、$d$）。前缀表达式（先序）为 $\times\ +\ a\ b\ -\ c\ d$；后缀表达式（后序）为 $a\ b\ +\ c\ d\ -\ \times$。

**要点**：画树口诀是"**最后计算的运算符是根**"（本题 $\times$ 最后算），然后递归分解左右子表达式。

**求树的深度**是后序遍历的典型应用——先算完左右子树的深度，再把两者中较大的加一（完整实现见第 7 节的 `GetHeight`）。

#### 递归实现

三种遍历的递归代码放在一起看，差别确实只有 `visit(T)` 的位置：

```c
void PreOrder(BiTree T) {          // 先序遍历
    if (T != NULL) {
        visit(T);
        PreOrder(T->lchild);
        PreOrder(T->rchild);
    }
}
void InOrder(BiTree T) {           // 中序遍历
    if (T != NULL) {
        InOrder(T->lchild);
        visit(T);
        InOrder(T->rchild);
    }
}
void PostOrder(BiTree T) {         // 后序遍历
    if (T != NULL) {
        PostOrder(T->lchild);
        PostOrder(T->rchild);
        visit(T);
    }
}
```

> **注意**：递归遍历的栈深度等于树的高度。最坏情况是单支树，递归深度达到 $O(n)$，可能导致栈溢出；处理很深的树时应改用下面的非递归版本。

#### 非递归实现：用显式栈替代递归栈

任何递归算法都可以改写成"**迭代 + 显式栈**"。

先序遍历按"根左右"入栈**先右后左**，这样出栈时左孩子先出：

```c
void PreOrderNonRec(BiTree T) {
    if (T == NULL) return;
    BiTNode* stack[100];           // 显式栈
    int top = -1;
    stack[++top] = T;              // 根结点入栈
    while (top != -1) {
        BiTNode* p = stack[top--]; // 弹出栈顶并访问
        visit(p);
        // 右孩子先入栈、左孩子后入栈，保证左孩子先出栈
        if (p->rchild != NULL) stack[++top] = p->rchild;
        if (p->lchild != NULL) stack[++top] = p->lchild;
    }
}
```

中序遍历沿左链一路到底，回溯时访问根，再转向右子树：

```c
void InOrderNonRec(BiTree T) {
    BiTNode* stack[100];
    int top = -1;
    BiTNode* p = T;
    while (p != NULL || top != -1) {
        if (p != NULL) {           // 沿左链一路走到底
            stack[++top] = p;
            p = p->lchild;
        } else {                   // 左子树为空，回溯
            p = stack[top--];
            visit(p);              // 访问根
            p = p->rchild;         // 转向右子树
        }
    }
}
```

后序遍历是"左右根"，把它看成"根右左"的逆序即可得到一个极简洁的双栈写法：

```c
// 方法一：双栈法——"根右左"的逆序恰好是"左右根"
void PostOrderNonRec(BiTree T) {
    if (T == NULL) return;
    BiTNode* s1[100];              // 辅助栈（按根右左的顺序弹出）
    BiTNode* s2[100];              // 输出栈（逆序后即左右根）
    int top1 = -1, top2 = -1;
    s1[++top1] = T;
    while (top1 != -1) {
        BiTNode* p = s1[top1--];
        s2[++top2] = p;            // 记录到输出栈
        if (p->lchild != NULL) s1[++top1] = p->lchild;
        if (p->rchild != NULL) s1[++top1] = p->rchild;
    }
    while (top2 != -1)             // 输出栈依次弹出即"左右根"
        visit(s2[top2--]);
}
// 方法二：单栈 + prev 标记法（空间 O(h)，逻辑稍复杂）
void PostOrderNonRec2(BiTree T) {
    BiTNode* stack[100];
    int top = -1;
    BiTNode *p = T, *prev = NULL;  // prev 记录上一次访问的结点
    while (p != NULL || top != -1) {
        if (p != NULL) {           // 沿左链走到底
            stack[++top] = p;
            p = p->lchild;
        } else {
            p = stack[top];        // 先查看栈顶，暂不出栈
            if (p->rchild != NULL && p->rchild != prev) {
                p = p->rchild;     // 右子树存在且未访问 → 转向右子树
            } else {               // 右子树为空或已访问 → 访问根
                top--;
                visit(p);
                prev = p;          // 标记已访问
                p = NULL;          // 强制回溯
            }
        }
    }
}
```

| 遍历 | 非递归难度 | 关键技巧 |
| :--- | :---: | :--- |
| 先序 | 简单 | 右孩子先入栈，左孩子后入栈 |
| 中序 | 中等 | 沿左链到底 $\to$ 回溯访问根 $\to$ 转右子树 |
| 后序 | 较难 | 双栈法（根右左的逆序）或 prev 标记法 |

> **注意**：先序与中序的非递归写法应当做到随手写出；后序推荐用**双栈法**，逻辑简洁不易错。核心理解是：**递归通过函数调用栈隐式保存上下文，非递归通过显式栈手动管理**——两者保存的是同一份信息。

### 层序遍历

**层序遍历**先从上到下、再在每一层从左到右访问结点。它借助队列的先进先出特性，保证"先访问的结点，其孩子也先被处理"：

![二叉树的层序遍历](/notes-assets/dsa5-11-level-order.jpg)

```c
void LevelOrder(BiTree T) {
    LinkQueue Q;
    InitQueue(Q);
    BiTree p;
    EnQueue(Q, T);
    while (!IsEmpty(Q)) {
        DeQueue(Q, p);
        visit(p);
        if (p->lchild != NULL) EnQueue(Q, p->lchild);
        if (p->rchild != NULL) EnQueue(Q, p->rchild);
    }
}
```

> **注意**：层序遍历本质上就是图的广度优先搜索（BFS）在二叉树上的特例——队列保证了"先访问的结点，其孩子也先被处理"，这正是 BFS 的核心思想。它也是求树的宽度、按层打印等操作的实现基础。

> **例 1（层序遍历序列）** 对例 1 中的二叉树（先序序列 ABDGECF），写出层序遍历序列。

**思路**：用队列——根先入队；出队时访问并把孩子入队；循环至队空。手算时按"逐层从左到右"直接列出即可。

**解**：该树的结构为 A(B(D(右孩子 G), E), C(F))，层序序列为 **ABCDEFG**。

**要点**：层序与先序的区别在于——先序会让 B、D、G 连续出现（一路扎进左子树），层序则严格按层输出（第二层的 B、C 排在一起）。层序序列就是"完全二叉树编号"的物理顺序，这也是顺序存储天然支持层序遍历的原因。

#### 四种遍历方式对比

| 遍历方式 | 顺序 | 辅助结构 | 典型应用 |
| :--- | :--- | :--- | :--- |
| **先序遍历**（NLR） | 根 $\to$ 左 $\to$ 右 | 递归／栈 | 前缀表达式、复制树、深度优先搜索 |
| **中序遍历**（LNR） | 左 $\to$ 根 $\to$ 右 | 递归／栈 | 二叉排序树得有序序列、中缀表达式 |
| **后序遍历**（LRN） | 左 $\to$ 右 $\to$ 根 | 递归／栈 | 后缀表达式、删除树（先删子树再删根） |
| **层序遍历** | 上 $\to$ 下、左 $\to$ 右 | 队列 | 广度优先搜索、求树的宽度 |

### 由遍历序列构造二叉树

**结论先行**：只给出一种遍历序列**不能**唯一确定一棵二叉树；能唯一确定的两两组合只有三种——**中序序列必须出现**，因为只有它能把结点划分到根的左右两侧。

| 组合 | 能否唯一确定 | 方法 |
| :--- | :---: | :--- |
| 前序 + 中序 | 可以 | 前序定根，中序定左右子树范围 |
| 后序 + 中序 | 可以 | 后序（逆序）定根，中序定左右子树范围 |
| 层序 + 中序 | 可以 | 层序第一个为根，中序定左右子树范围 |
| 前序 + 后序 | **不可以** | 无法区分"只有左子树"与"只有右子树"的情况 |

![根据遍历构造二叉树](/notes-assets/dsa5-12-construct-from-traversals.jpg)

> **注意**：口诀是"**前／后／层序定根，中序定左右子树**"。为什么前序 + 后序不行？因为当一个结点只有一个孩子时，两种序列都无法说明这个孩子是左还是右——例如 A(B, ∅) 与 A(∅, B) 的先序都是 AB、后序都是 BA，却是两棵不同的树。

> **例 1（由先序 + 中序构造并求后序）** 已知某二叉树的先序遍历为 ABDGECF，中序遍历为 DGBEAFC，求后序遍历。

**思路**：先序的第一个元素是根；在中序中找到根，它左边即左子树结点集、右边即右子树结点集；对左右子树递归重复。

**解**：① 先序首元素 A 是根，中序为 DGBE | **A** | FC，故左子树是 {D, G, B, E}、右子树是 {F, C}。② 左子树先序为 B D G E，根是 B；中序为 DG | **B** | E，故 B 的左子树是 {D, G}、右子树是 {E}；先序为 D G，根是 D，中序为 D | **G**，故 G 是 D 的右孩子。③ 右子树先序为 C F，根是 C；中序为 F | **C**，故 F 是 C 的左孩子。④ 后序遍历（左右根）为 G D E B F C A，即 **GDEBFCA**。

**要点**：构造的每一步都依赖"**中序分界**"——根在中序中的位置左侧是左子树全体、右侧是右子树全体；再用先序确定各棵子树的根。这两步交替进行，直到所有区间为空。

### 二叉树的进阶操作

二叉树的绝大多数算法共享同一个递归模板：**空树返回边界值，否则递归左右子树，再合并结果**。**结论先行**——只要认清"空树的边界值是什么"和"子树结果如何合并"这两件事，绝大部分函数都能直接写出来；复杂度也遵循同一条规律：每个结点恰好被访问一次，时间 $O(n)$，递归深度等于树高，空间 $O(h)$。

#### 广义表表示法建树

**广义表表示法**的核心思路是：在 `A(B(D,E),C(F,G))` 这种格式里，字母创建结点，`(` 表示接下来的结点是栈顶结点的**左孩子**，`,` 切换到**右孩子**模式，`)` 表示当前子树结束、栈顶结点出栈。

```c
typedef char ElementType;
typedef struct BiTNode {
    ElementType data;
    struct BiTNode* lchild;
    struct BiTNode* rchild;
} BiTNode, *BiTree;
BiTree CreateTree(const char* str) {
    if (str == NULL || str[0] == '\0') return NULL;
    BiTNode* s[110];             // 结点栈：栈顶始终是当前待处理子树的双亲
    int top = -1;
    BiTree root = NULL;
    BiTNode* p = NULL;
    int k = 1;                   // k=1 准备接左孩子，k=2 准备接右孩子
    for (int i = 0; str[i] != '\0'; i++) {
        char ch = str[i];
        if (ch >= 'A' && ch <= 'Z') {
            p = (BiTNode*)malloc(sizeof(BiTNode));
            p->data = ch;
            p->lchild = p->rchild = NULL;
            if (root == NULL) root = p;              // 第一个结点即根
            else if (k == 1) s[top]->lchild = p;     // 挂到双亲的左链
            else s[top]->rchild = p;                 // 挂到双亲的右链
        } else if (ch == '(') {
            s[++top] = p;        // 刚读入的结点成为新的双亲
            k = 1;               // 它的第一个孩子是左孩子
        } else if (ch == ',') {
            k = 2;               // 接下来的结点是右孩子（下一个兄弟）
        } else if (ch == ')') {
            top--;               // 当前子树结束，双亲出栈
        }
    }
    return root;
}
```

> **注意**：关键在 `(` 处把**双亲入栈**、在 `)` 处出栈，而不是每读一个结点就入栈。否则遇到 `A(B,C)` 这样的串时，`,` 之后的 C 会被挂到 B 下面，而不是挂到共同的父亲 A 下面。

#### 前序标记建树

**前序序列 + 空指针标记**则用 `#` 表示空树：`ABD###CE##F##` 按先序递归读入，遇 `#` 返回 NULL，否则创建结点并递归创建左右子树。

```c
BiTree _CreateByPreorder(const char* str, int* idx) {
    if (str[*idx] == '#' || str[*idx] == '\0') {
        (*idx)++;
        return NULL;
    }
    BiTNode* p = (BiTNode*)malloc(sizeof(BiTNode));
    p->data = str[(*idx)++];
    p->lchild = _CreateByPreorder(str, idx);
    p->rchild = _CreateByPreorder(str, idx);
    return p;
}
BiTree CreateTreeByPreorder(const char* str) {
    if (str == NULL || str[0] == '\0') return NULL;
    int idx = 0;
    return _CreateByPreorder(str, &idx);
}
```

两者的分工很清晰：广义表法用**栈 + k 标志**（迭代、显式管理父子关系），适合读入带括号的输入串；前序标记法用**递归 + 下标指针**（天然契合先序的递归结构），更接近"手工按先序写出一棵树"。

#### 统计：高度、结点数、叶子数与宽度

```c
int GetHeight(BiTree T) {              // 递归求高度
    if (T == NULL) return 0;
    int lh = GetHeight(T->lchild);
    int rh = GetHeight(T->rchild);
    return (lh > rh ? lh : rh) + 1;
}
int GetNodeCount(BiTree T) {           // 递归统计结点总数
    if (T == NULL) return 0;
    return GetNodeCount(T->lchild) + GetNodeCount(T->rchild) + 1;
}
int GetLeafCount(BiTree T) {           // 递归统计叶子结点
    if (T == NULL) return 0;
    if (T->lchild == NULL && T->rchild == NULL) return 1;
    return GetLeafCount(T->lchild) + GetLeafCount(T->rchild);
}
int GetWidth(BiTree T) {               // 层序遍历 + 层级标记，求最大宽度
    if (T == NULL) return 0;
    BiTNode* Q[110];
    int front = 0, rear = 0;
    int width[110] = {0};          // 每一层的结点数
    int level[110] = {0};          // 队列中每个结点所属的层
    Q[rear] = T; level[rear] = 1; rear++;
    int maxLevel = 1;
    while (front < rear) {
        BiTNode* p = Q[front];
        int curLevel = level[front];
        front++;
        width[curLevel]++;
        if (p->lchild != NULL) {
            Q[rear] = p->lchild; level[rear] = curLevel + 1; rear++;
        }
        if (p->rchild != NULL) {
            Q[rear] = p->rchild; level[rear] = curLevel + 1; rear++;
        }
        // 只要还有孩子，就说明存在下一层
        if ((p->lchild != NULL || p->rchild != NULL) && curLevel + 1 > maxLevel)
            maxLevel = curLevel + 1;
    }
    int maxWidth = 0;
    for (int i = 1; i <= maxLevel; i++)
        if (width[i] > maxWidth) maxWidth = width[i];
    return maxWidth;
}
```

> **注意**：求宽度是层序遍历的进阶应用，关键是在队列中**同时记录每个结点的层号**，这样出队时就知道当前结点属于哪一层。上面的 `maxLevel` 更新必须放在左右孩子判断**之外**——如果只写在左孩子分支里，遇到"只有右孩子"的结点就会漏掉最下面一层。

> **例 1（统计演示）** 对例 1 中的二叉树 A(B(D(右孩子 G), E), C(F))，求高度、结点数、叶子数，并按度分类统计。

**解**：该树的度分布为 A、B 度 2（分别有 B、C 与 D、E），D 度 1（只有右孩子 G），C 度 1（只有左孩子 F），E、G、F 度 0。于是最长路径 A $\to$ B $\to$ D $\to$ G 给出高度 **4**，结点数为 **7**，叶子数为 **3**（E、G、F），按度统计得 $n_0 = 3$、$n_1 = 2$、$n_2 = 2$，验证 $n_0 = n_2 + 1$ 成立。注意 D 只有右孩子，说明**在完全二叉树之外，度为 1 的结点可以有任意多个**。

#### 按值查找

按值查找是"**先查自身，再查左、右，命中即返回**"，为了让返回的一定是最左侧的匹配结点，要先用左子树结果短路：

```c
BiTNode* FindNode(BiTree T, char x) {
    if (T == NULL) return NULL;
    if (T->data == x) return T;
    BiTNode* left = FindNode(T->lchild, x);
    if (left != NULL) return left;
    return FindNode(T->rchild, x);
}
```

#### 判断两树相同

判断类的骨架是"**双空相等、单空不等、再递归**"，`&&` 的短路特性保证只要发现一处不同就立即返回：

```c
int IsSameTree(BiTree T1, BiTree T2) {          // 结构 + 数据都相同
    if (T1 == NULL && T2 == NULL) return 1;
    if (T1 == NULL || T2 == NULL) return 0;
    if (T1->data != T2->data) return 0;
    return IsSameTree(T1->lchild, T2->lchild) &&
           IsSameTree(T1->rchild, T2->rchild);
}
```

#### 交换左右子树

变换类以交换左右子树为代表。它**必须用后序**：如果先交换根的两个指针再递归子树，子树会被交换两次而回到原状：

```c
void SwapChildren(BiTree T) {
    if (T == NULL) return;
    SwapChildren(T->lchild);
    SwapChildren(T->rchild);
    BiTNode* temp = T->lchild;
    T->lchild = T->rchild;
    T->rchild = temp;
}
```

#### 复制与销毁

`CopyTree` 与 `MirrorCopy` 的递归结构完全相同，唯一的区别是左右子树的**赋值方向**——前者 lchild 对 lchild，后者 lchild 对 rchild。销毁则必须用**二级指针**并后序释放：

```c
void DestroyTree(BiTree* pT) {
    if (pT == NULL || *pT == NULL) return;
    DestroyTree(&((*pT)->lchild));
    DestroyTree(&((*pT)->rchild));
    free(*pT);
    *pT = NULL;           // 置空，防止野指针
}
```

> **注意**：`free` 只释放内存，不会修改调用方的指针变量。如果 `DestroyTree` 的参数写成一级指针 `BiTree T`，`free(T)` 之后外部的指针仍指向已释放的内存，成为野指针；传二级指针才能保证调用后外部指针被置为 NULL。

#### 二叉树操作复杂度速查

| 操作 | 时间复杂度 | 空间复杂度 | 关键技巧 |
| :--- | :---: | :---: | :--- |
| CreateTree（广义表表示法） | $O(n)$ | $O(h)$（栈） | k 标志位 + 双亲栈 |
| CreateTreeByPreorder | $O(n)$ | $O(h)$（递归栈） | idx 指针 + `#` 标记空树 |
| GetHeight | $O(n)$ | $O(h)$ | 后序合并，$\max(l,r)+1$ |
| GetNodeCount | $O(n)$ | $O(h)$ | 左 $+$ 右 $+ 1$ |
| GetLeafCount | $O(n)$ | $O(h)$ | 双孩子皆空的判定 |
| GetWidth | $O(n)$ | $O(n)$ | 层序 + 层级标记数组 |
| FindNode / FindParent | $O(n)$ | $O(h)$ | 根／左／右三处判断 |
| IsSameTree | $O(n)$ | $O(h)$ | 递归 + `&&` 短路 |
| SwapChildren | $O(n)$ | $O(h)$ | **必须后序** |
| CopyTree / MirrorCopy | $O(n)$ | $O(h)$ | 分配结点 + 递归 |
| DestroyTree | $O(n)$ | $O(h)$ | **二级指针** + 后序释放 |
| FindPath | $O(n)$ | $O(h)$ | 路径数组 + 深度参数 |
| GetMax / GetMin | $O(n)$ | $O(h)$ | 哨兵值 `#` 处理空树 |

> **注意**：复杂度分析的关键只有一句——**每个结点被访问恰好一次**，所以时间是 $O(n)$；递归深度等于树高，所以空间是 $O(h)$。单支树上 $h = n$，此时空间退化为 $O(n)$。

## 线索二叉树

**结论先行**：$n$ 个结点的二叉链表有 $n+1$ 个空链域，与其让它们闲着，不如用来存放该结点在遍历序列中的前驱与后继——这就是线索。线索化之后，中序遍历不再需要递归或栈，空间从 $O(h)$ 降到 $O(1)$。理解线索二叉树需要两把钥匙：**pre 指针追踪前驱**（线索化的核心机制）与 **ltag/rtag 区分指针与线索**（否则会把线索当成孩子）。

### 线索二叉树的概念

- $n$ 个结点的二叉树有 **$n+1$ 个空链域**，可以用来记录前驱、后继的信息；
- 指向前驱、后继的指针称为**线索**（Thread）；
- **线索二叉树**（Threaded Binary Tree）就是利用空链域存储遍历序列中前驱与后继的二叉树。

![线索二叉树](/notes-assets/dsa5-13-threaded-binary-tree.jpg)

```c
struct ThreadNode {
    ElemType data;
    struct ThreadNode *lchild, *rchild;
    int ltag, rtag;   // 标志位：0 表示指向孩子，1 表示该指针是线索
};
typedef ThreadNode *ThreadTree;
```

**标志位约定**：`ltag = 0` 表示 `lchild` 指向左孩子，`ltag = 1` 表示 `lchild` 指向前驱线索；`rtag` 同理对应右孩子与后继。线索二叉树的动机是典型的"**把必然存在的浪费变成便利**"——$n+1$ 个空链域本来就存在，用它换掉递归栈，遍历就变成了 $O(1)$ 空间的线性扫描。下面按"先/中/后序"三种次序分别线索化，其中中序线索化最常用。

### 二叉树的线索化

#### 中序线索化

```c
BiTNode *pre = NULL;   // 指向当前访问结点的前驱
void visit(BiTNode *q) {
    if (q->lchild == NULL) {        // 左子树为空，把左链改造成前驱线索
        q->lchild = pre;
        q->ltag = 1;
    }
    if (pre != NULL && pre->rchild == NULL) {  // 给前驱结点补上后继线索
        pre->rchild = q;
        pre->rtag = 1;
    }
    pre = q;                       // pre 前移
}
void InThread(BiTree T) {
    if (T != NULL) {
        InThread(T->lchild);
        visit(T);
        InThread(T->rchild);
    }
}
void CreateInThread(ThreadTree T) {
    pre = NULL;
    if (T != NULL) {
        InThread(T);
        if (pre->rchild == NULL) pre->rtag = 1;  // 处理最后一个结点
    }
}
```

> **注意**：线索化本质上是把递归遍历中的"访问顺序"固化成指针。当 `q->lchild == NULL` 时，`q` 的前驱就是 `pre`；当 `pre->rchild == NULL` 时，`pre` 的后继就是当前结点 `q`。每处理完一个结点，`pre` 前移一次——这样每个空链域恰好被利用一次。

> **例 1（中序线索化的前驱与后继）** 对例 1 的二叉树（中序序列 DGBEAFC）进行中序线索化，写出每个结点的前驱与后继。

**思路**：中序序列就是线索的依据——每个结点的前驱／后继就是它在序列中的左右邻居；首结点没有前驱，末结点没有后继。

**解**：

| 结点 | D | G | B | E | A | F | C |
| :---: | :---: | :---: | :---: | :---: | :---: | :---: | :---: |
| **前驱** | NULL | D | G | B | E | A | F |
| **后继** | G | B | E | A | F | C | NULL |

**要点**：D 没有前驱，它的左链域留空（或指向 NULL）；C 没有后继，`CreateInThread` 末尾把 `pre->rtag` 置 1 处理的就是它。手算线索表的方法就是"写出中序序列 + 邻居配对"。

#### 先序线索化

先序线索化先处理根结点，再递归左、右子树；这里有一个必须注意的陷阱：

> **注意**：先序线索化存在**死循环风险**。若 `q->lchild` 刚被设为前驱线索（指向 `pre`），随后递归 `T->lchild` 时**没有检查 `ltag`**，就会沿着线索走回前驱，形成无限循环。解决办法是加一个判断：`if (T->ltag == 0) InThread(T->lchild);`。

#### 后序线索化

后序线索化先递归左、右子树，最后处理根结点，**不存在死循环问题**——处理根的时候两棵子树都已经线索化完毕，不会再沿着线索往下走。

### 线索二叉树寻找前驱、后继

中序线索二叉树是唯一两个方向都能 $O(1)$ 求解的形态。

#### 中序找后继

**找后继（正向中序遍历）**：

```c
ThreadNode *Firstnode(ThreadNode *p) {
    while (p->ltag == 0) p = p->lchild;   // 一路向左，找到最左下结点
    return p;
}
ThreadNode *Nextnode(ThreadNode *p) {
    if (p->rtag == 0) return Firstnode(p->rchild);  // 有右子树 → 右子树的最左下结点
    else return p->rchild;                          // 线索直接指向后继
}
void Inorder(ThreadNode *T) {
    for (ThreadNode *p = Firstnode(T); p != NULL; p = Nextnode(p))
        visit(p);
}
```

#### 中序找前驱

**找前驱（反向中序遍历）**：

```c
ThreadNode *Lastnode(ThreadNode *p) {
    while (p->rtag == 0) p = p->rchild;   // 一路向右，找到最右下结点
    return p;
}
ThreadNode *Prenode(ThreadNode *p) {
    if (p->ltag == 0) return Lastnode(p->lchild);   // 有左子树 → 左子树的最右下结点
    else return p->lchild;                          // 线索直接指向前驱
}
void RevInorder(ThreadNode *T) {
    for (ThreadNode *p = Lastnode(T); p != NULL; p = Prenode(p))
        visit(p);
}
```

规律可以概括成一句话：**有右孩子（rtag = 0）就找右子树的最左下结点，否则线索所指就是后继**；找前驱完全对称——**有左孩子就找左子树的最右下结点，否则线索所指就是前驱**。

#### 先序与后序的查找

先序线索二叉树：找后继时，若 `rtag == 1` 则 `next = rchild`（线索），若 `rtag == 0` 且左孩子存在则 `next = lchild`，否则 `next = rchild`；找前驱需要知道双亲，**较复杂**。后序线索二叉树恰好相反：找前驱时，若 `ltag == 1` 则 `pre = lchild`（线索），若 `ltag == 0` 且右孩子存在则 `pre = rchild`，否则 `pre = lchild`；找后继同样需要双亲信息。

#### 三种线索树对比

| 对比维度 | 中序线索 | 先序线索 | 后序线索 |
| :--- | :---: | :---: | :---: |
| **找后继** | 容易（$O(1)$） | 容易（$O(1)$） | 困难（需双亲） |
| **找前驱** | 容易（$O(1)$） | 困难（需双亲） | 容易（$O(1)$） |
| **非递归遍历** | 完美支持 | 可正向遍历 | 不完整 |
| **实用性** | 最实用 | 适中 | 较少用 |

> **注意**：**中序线索二叉树最实用**——前驱和后继都能 $O(1)$ 找到，正向与反向遍历都支持，实现也最完整。先序线索和后序线索各有一个方向需要双亲信息，通常要配合三叉链表才能补齐。

## 树的存储结构与遍历

一般树的结点有任意多个孩子，无法直接套用二叉链表，于是发展出三种存储方式：**双亲表示法**（数组 + parent 域，找双亲 $O(1)$，是并查集的基石）、**孩子表示法**（数组 + 孩子链表，找孩子 $O(1)$）、**孩子兄弟表示法**（二叉链表，"左孩子右兄弟"，是树与二叉树互相转换的桥梁）。**结论先行**：遍历方面，树只有先根、后根、层次三种，而且有一个非常漂亮的对应关系——**树的后根遍历恰好等于对应二叉树的中序遍历**，先根遍历等于先序遍历。这条关系把一般树的算法接入了二叉树的算法体系。

### 树的存储

#### 双亲表示法

每个结点（除根以外）都有唯一的双亲，于是可以用数组存储，每个结点只记数据与双亲的位置：

![树的双亲表示法](/notes-assets/dsa5-14-parent-representation.jpg)

```c
const int MAX_TREE_SIZE = 100;
struct PTNode {
    ElemType data;
    int parent;          // 双亲在数组中的下标（根结点的 parent = -1）
};
struct PTree {
    PTNode nodes[MAX_TREE_SIZE];
    int n;               // 结点数
} PTree;
```

寻找双亲是 $O(1)$，寻找孩子必须遍历整个数组，代价 $O(n)$——这个取舍正好适合"只需要向上找父亲"的场景。

#### 双亲表示法的应用：并查集

**并查集**（Disjoint Set Union）是只支持**并集**（Union）与**查找**（Find）两种操作的集合结构。它之所以高效，恰恰是因为它**只用双亲表示法**——不需要找孩子，不需要遍历：

![并查集](/notes-assets/dsa5-15-disjoint-set.jpg)

- 数组下标表示元素，值表示双亲的下标；
- 根结点的 `parent` 指向自身（`parent[x] == x`）；
- `rank` 数组记录树的近似高度，用于按秩合并。

```c
typedef enum { OK = 1, ERROR = 0 } Status;
typedef struct {
    int* parent;
    int* rank;
    int  size;
} UnionFind;
// 查找根结点，同时把路径上的结点直接挂到根下（路径压缩）
int UFFind(UnionFind* uf, int x)
{
    if (uf == NULL || x < 0 || x >= uf->size)
        return -1;
    if (uf->parent[x] != x)
        uf->parent[x] = UFFind(uf, uf->parent[x]);
    return uf->parent[x];
}
// 按秩合并：始终把矮树挂到高树下面
Status UFUnion(UnionFind* uf, int x, int y)
{
    if (uf == NULL || x < 0 || x >= uf->size || y < 0 || y >= uf->size)
        return ERROR;
    int rootX = UFFind(uf, x);          // 必须先取到两个根
    int rootY = UFFind(uf, y);
    if (rootX == rootY) return ERROR;   // 已经在同一个集合里
    if (uf->rank[rootX] < uf->rank[rootY])
        uf->parent[rootX] = rootY;
    else if (uf->rank[rootX] > uf->rank[rootY])
        uf->parent[rootY] = rootX;
    else {                              // 秩相等：被挂者的秩不变，挂入者的秩加一
        uf->parent[rootY] = rootX;
        uf->rank[rootX]++;
    }
    return OK;
}
```

![并查集的路径压缩](/notes-assets/dsa5-17-path-compression.jpg)

![并查集按大小合并](/notes-assets/dsa5-16-union-by-size.jpg)

**复杂度**：只做按秩合并时树高为 $O(\log n)$，Find 最坏 $O(\log n)$；只做路径压缩时均摊也接近 $O(\log n)$；**两者同时使用**时，Find 与 Union 的均摊复杂度为 $O(\alpha(n))$，其中 $\alpha$ 是反阿克曼函数。$\alpha(n)$ 增长极慢——即使 $n = 2^{65536}$，也有 $\alpha(n) \le 5$，因此可以认为并查集的操作是**近乎常数时间**的。

> **注意**：Union 之前**必须先 Find**（拿到两个根再合并），直接修改 `parent[x]` 会破坏已有的树结构。并查集在图中最经典的应用是 Kruskal 最小生成树算法——按边权从小到大尝试加入，用并查集判断两端点是否已经连通。

> **例 1（并查集操作演示）** 并查集初始有 5 个元素 0~4，各自单独成集。依次执行 Union(0,1)、Union(2,3)、Union(1,3)、Find(3)，给出每次操作后的 parent 数组。

**思路**：Union 先 Find 两个元素的根；根不同则按秩合并（秩小的挂到秩大的下面）；Find 沿途做路径压缩。

**解**：初始 `parent = [0, 1, 2, 3, 4]`，`rank` 全为 0。

① Union(0,1)：根 0 与根 1 的秩相等，令 `parent[1] = 0`、`rank[0] = 1`，得到 `parent = [0, 0, 2, 3, 4]`。

② Union(2,3)：秩相等，令 `parent[3] = 2`、`rank[2] = 1`，得到 `parent = [0, 0, 2, 2, 4]`。

③ Union(1,3)：Find(1) $= 0$，Find(3) $= 2$，`rank[0] = 1` 与 `rank[2] = 1` 相等，令 `parent[2] = 0`、`rank[0] = 2`，得到 `parent = [0, 0, 0, 2, 4]`。

④ Find(3)：路径为 3 $\to$ 2 $\to$ 0，沿途压缩后 `parent[3] = 0`，得到 `parent = [0, 0, 0, 0, 4]`。

最终集合为 {0, 1, 2, 3}（以 0 为根）与 {4}（独立）。

**要点**：按秩合并保证树高为 $O(\log n)$，路径压缩让 Find 均摊接近 $O(1)$，两步缺一不可。

#### 孩子表示法

用数组顺序存储各个结点，每个结点保存数据元素与一条"孩子链表"的头指针：

![树的孩子表示法](/notes-assets/dsa5-18-child-representation.jpg)

```c
struct CTNode {
    int child;                   // 孩子在数组中的位置
    struct CTNode *next;         // 下一个孩子
};
struct CTBox {
    ElemType data;
    struct CTNode *firstChild;   // 第一个孩子
};
struct CTree {
    CTBox nodes[MAX_TREE_SIZE];
    int n, r;                    // 结点数与根的位置
};
```

寻找孩子是 $O(1)$（沿孩子链表走），寻找双亲要遍历所有链表、代价 $O(n)$。它适合需要频繁"从上级找下级"的结构，如服务流程树、组织结构图。

#### 孩子兄弟表示法

采用二叉链表实现，每个结点包含数据域、第一个孩子指针与下一个兄弟指针：

![树的孩子兄弟表示法](/notes-assets/dsa5-19-child-sibling-representation.jpg)

```c
struct CSNode {
    ElemType data;
    struct CSNode *firstchild, *nextsibling;
};
typedef CSNode *CSTree;
```

#### 树的三种存储结构对比

| 对比维度 | 双亲表示法 | 孩子表示法 | 孩子兄弟表示法 |
| :--- | :---: | :---: | :---: |
| **存储方式** | 顺序（数组） | 顺序 + 链式 | 链式（二叉链表） |
| **找双亲** | $O(1)$ | $O(n)$ | $O(n)$ |
| **找孩子** | $O(n)$（遍历数组） | $O(1)$（沿链表） | $O(1)$（第一个孩子） |
| **找兄弟** | $O(n)$ | $O(1)$（沿链表） | $O(1)$（沿 nextsibling） |
| **核心应用** | 并查集 | 组织结构图 | 树 $\leftrightarrow$ 二叉树转换 |

### 树和森林的遍历

#### 树与森林的转换

**树与森林到二叉树的转换规则**：树转二叉树用"**左孩子右兄弟**"——`firstchild` 变成 `lchild`，`nextsibling` 变成 `rchild`；森林转二叉树则先把每棵树各自转成二叉树，再用右指针把各棵二叉树的根依次串起来；反向操作就是二叉树还原成树或森林。

![树、森林转化为二叉树](/notes-assets/dsa5-20-tree-forest-to-binary.jpg)

![二叉树转化为树、森林](/notes-assets/dsa5-21-binary-to-tree-forest.jpg)

> **注意**："左孩子右兄弟"是树与二叉树之间的**桥梁**。任何树（以及森林）都可以通过这条规则唯一地转换为二叉树，反之亦然。这意味着**所有二叉树的算法都可以作用在一般树上**——先转换、再处理、最后还原即可。

#### 树的遍历与森林的遍历

| 树的遍历 | 定义 | 对应二叉树的遍历 | 序列特征 |
| :--- | :--- | :---: | :--- |
| **先根遍历** | 先访问根，再依次先根遍历每棵子树 | **先序遍历** | 根在最前 |
| **后根遍历** | 先依次后根遍历每棵子树，最后访问根 | **中序遍历** | 根在最后 |
| **层次遍历** | 从上到下、从左到右（队列辅助） | 层序遍历 | 逐层输出 |

森林的遍历有两种：**先序遍历森林**——访问第一棵树的根，先序遍历第一棵树的子树森林，再先序遍历其余树构成的森林，等价于依次对每棵树做**先根遍历**；**中序遍历森林**——中序遍历第一棵树的子树森林，访问第一棵树的根，再中序遍历其余树构成的森林，等价于依次对每棵树做**后根遍历**。汇总成一张对应表：

| 树／森林的遍历 | 等价于二叉树的遍历 |
| :--- | :---: |
| 树的先根遍历 | 二叉树的**先序**遍历 |
| 树的后根遍历 | 二叉树的**中序**遍历 |
| 森林的先序遍历 | 二叉树的**先序**遍历 |
| 森林的中序遍历 | 二叉树的**中序**遍历 |

> **注意**：为什么树的后根遍历等于二叉树的中序遍历？树转二叉树时，每个结点的**第一个孩子**变成它的左孩子，**其余兄弟**变成右孩子。树的后根遍历顺序是"先各子树、后根"，映射到二叉树上恰好是"左子树 $\to$ 根 $\to$ 右子树"，而这正是中序遍历的定义。

> **例 1（遍历对应关系验证）** 一棵树的根为 T，T 的孩子依次为 A、D；A 的孩子依次为 B、C。求树的先根、后根遍历序列，并验证它们与其转换所得二叉树的先序、中序序列一致。

**思路**：先根 $=$ 根 $+$ 各子树的先根；后根 $=$ 各子树的后根 $+$ 根；转换规则是"左孩子右兄弟"。

**解**：树的先根遍历为 **T A B C D**，后根遍历为 **B C A D T**。

转换成二叉树后：T 的左孩子是 A（T 没有兄弟，故右孩子为空）；A 的左孩子是 B、右孩子是 D（A 的下一个兄弟）；B 的右孩子是 C（B 的下一个兄弟）。该二叉树的先序序列为 T A B C D，与树的先根遍历一致；中序序列为 B C A D T，与树的后根遍历一致。

**要点**：转换之后，**树的每个结点的全部孩子**在二叉树中变成"从左孩子开始的一条右链"——B 的兄弟 C 挂在 B 的右链上，A 的兄弟 D 挂在 A 的右链上。正因为"孩子链"与"兄弟链"分别落在左、右两个方向上，树的后根遍历才会等价于二叉树的中序遍历。反过来把二叉树还原成树时，同样是把右链拆成兄弟关系。

## 哈夫曼树

**结论先行**：哈夫曼树（最优二叉树）是贪心策略最经典的范例——每次从森林中选**权值最小的两棵树**合并，最终让权值大的叶子离根近、权值小的叶子离根远，从而让整棵树的带权路径长度 WPL 全局最小。它同时给出了数据压缩的基石——**哈夫曼编码**，一种最优前缀编码。

### 哈夫曼树的基本概念

#### 结点的权

**结点的权**：结点上带有某种现实含义的值，例如字符在文本中出现的频度。

#### 带权路径长度

**结点的带权路径长度**：从根到该结点的**路径长度**（经过的边数）与该结点权值的乘积。

#### 树的 WPL

**树的带权路径长度**（Weighted Path Length, WPL）：树中**所有叶结点**的带权路径长度之和。

$$
WPL = \sum_{i=1}^{n} w_i l_i
$$

其中 $w_i$ 为第 $i$ 个叶结点的权值，$l_i$ 为从根到该叶结点的路径长度。注意 WPL **只统计叶结点**——内部结点（合并产生的结点）不直接计入，但由此可以推出一个很实用的验算技巧：**WPL 恰好等于所有内部结点的权值之和**。

### 哈夫曼树的构造

**哈夫曼树**（Huffman Tree）指在含有 $n$ 个带权叶结点的所有二叉树中 **WPL 最小**的那一棵，因此又称最优二叉树。**构造算法**（贪心策略，给定 $n$ 个权值 $w_1, w_2, \dots, w_n$）：

1. 把这 $n$ 个权值分别作为 $n$ 棵只含一个结点的二叉树，构成森林 $F$；
2. 从 $F$ 中选取两棵**根结点权值最小**的树，作为新结点的左、右子树，新结点的权值等于这两棵子树根结点权值之和；
3. 从 $F$ 中删除这两棵树，把新树加入 $F$；
4. 重复步骤 2、3，直到 $F$ 中只剩一棵树。

![哈夫曼树的构造过程](/notes-assets/dsa5-22-huffman-construction.jpg)

哈夫曼树的核心性质：每个初始结点最终都成为**叶结点**，且权值越小的结点到根的路径长度越大；结点总数为 **$2n - 1$**（$n$ 片叶子 $+$ $n-1$ 个内部结点）；**不存在度为 1 的结点**（$n_1 = 0$，于是 $n_0 = n$、$n_2 = n - 1$）；哈夫曼树**不唯一**（左右子树可以互换，权值相等时选法也不同），但 **WPL 必然相同且最小**。

> **注意**：构造口诀只有一句——"**每次选最小的两棵树合并**"。实现时可以用**最小堆**优化"选两个最小"这一步，把总代价从 $O(n^2)$ 降到 $O(n \log n)$；数据量不大时线性扫描就足够了。

> **例 1（哈夫曼树构造与 WPL）** 给定 4 个权值 {2, 4, 5, 7}，构造哈夫曼树并求 WPL。

**思路**：每次从森林中选两个权值最小的根合并；WPL 既可以用 $\sum(\text{叶权} \times \text{路径长度})$ 求，也可以用"内部结点权值之和"验算。

**解**：① 选 2、4，合并为新结点 6（森林：5, 6, 7）；② 选 5、6，合并为新结点 11（森林：7, 11）；③ 选 7、11，合并为根 18。树形为：根 18 的左孩子是 11（11 的左孩子是 6、右孩子是 5），右孩子是 7。各叶子的深度为：7 的深度是 1，5 的深度是 2，2 与 4 的深度是 3。于是

$$
WPL = 7 \times 1 + 5 \times 2 + 2 \times 3 + 4 \times 3 = 7 + 10 + 6 + 12 = 35
$$

验算：所有内部结点的权值之和 $= 6 + 11 + 18 = 35$，一致。

**要点**：构造时有三个易错点——① 每次合并产生的新结点要**放回森林**参与后续选择；② 权值相等时选哪两个都可以，树形可能不同但 WPL 相同；③ 手算 WPL 用"内部结点权值之和"最快（每合并一次累加一次），用"$\sum$ 叶权 $\times$ 深度"最直观，两种方法可以互相验算。

### 哈夫曼编码

| 编码类型 | 原理 | 优点 | 缺点 |
| :--- | :--- | :--- | :--- |
| **固定长度编码** | 每个字符都用等长的二进制位 | 解码简单 | 空间浪费 |
| **可变长度编码** | 不同字符用不等长的二进制位 | 压缩率高 | 必须避免歧义 |
| **前缀编码** | 没有任何一个编码是另一个编码的前缀 | 可以唯一解码 | 构造需要算法 |
| **哈夫曼编码** | 按频度构造哈夫曼树，左分支标 0、右分支标 1 | WPL 最小，压缩率最优 | 需要额外传输编码表 |

- **前缀编码**（Prefix Code）：没有任何一个编码是另一个编码的前缀——这是可变长度编码能够**唯一解码**的充要条件；
- **哈夫曼编码**的生成：把字符集中的每个字符作为叶结点、频度作为权值构造哈夫曼树，左分支标 0、右分支标 1，从根到叶子的路径即该字符的编码。

> **注意**：记忆口诀——**左 0 右 1，从根到叶即编码；频度越高路径越短**。哈夫曼编码是最优前缀编码：没有任何其它前缀编码的 WPL 比它更小。

> **例 1（哈夫曼编码的生成与编解码）** 字符 a、b、c、d 的频度分别为 2、4、5、7，构造哈夫曼树并生成各字符编码；再把字符串 "abcd" 编码，并解码验证。

**思路**：复用上例的树（$18 = 11 + 7$，$11 = 6 + 5$，$6 = 2 + 4$），左分支标 0、右分支标 1，从根到叶的路径就是编码。

**解**：

| 字符 | 频度 | 路径 | 哈夫曼编码 | 编码长度 |
| :---: | :---: | :--- | :---: | :---: |
| d | 7 | 根 $\to$ 右 | 1 | 1 |
| c | 5 | 根 $\to$ 左 $\to$ 右 | 01 | 2 |
| b | 4 | 根 $\to$ 左 $\to$ 左 $\to$ 右 | 001 | 3 |
| a | 2 | 根 $\to$ 左 $\to$ 左 $\to$ 左 | 000 | 3 |

编码 "abcd" 得到 `000 001 01 1`，即 **000001011**。解码时 `000` 译作 a、`001` 译作 b、`01` 译作 c、`1` 译作 d，还原为 "abcd"，验证正确——前缀编码的性质保证从左到右扫描即可唯一切分。

**要点**：频度最高的 d 码长最短（1 位），频度最低的 a 码长最长（3 位），"高频短码、低频长码"就是压缩的本质；编码长度恰好等于该叶子在树中的深度。加权平均码长 $= WPL / \text{总频度} = 35/18 \approx 1.94$ 位，小于固定长度编码所需的 2 位。需要说明的是，如果只编码 "abcd" 这个四字符各出现一次的短串，哈夫曼编码要用 9 位，反而比定长编码的 8 位多——短样本上体现不出优势，它的收益来自按频度加权后的平均码长。

哈夫曼树有数组（顺序）与链表（链式）两种实现，前者用下标代替指针、适合数据量大的场合，后者用递归与指针、更贴近二叉树的通用写法。

### 哈夫曼树的实现

#### 数组实现（顺序存储）

数组大小固定为 $2n - 1$：前 $n$ 个位置是叶结点，后 $n - 1$ 个位置是合并产生的内部结点。

```c
typedef struct {
    char data;         // 字符（内部结点的 data = '\0'）
    int weight;        // 权值／频度
    int parent;        // 双亲下标，-1 表示无双亲
    int lchild;        // 左孩子下标，-1 表示无左孩子
    int rchild;        // 右孩子下标，-1 表示无右孩子
} HTNode;
typedef struct {
    HTNode* nodes;     // 动态数组，大小为 2n-1
    int n;             // 原始符号数（叶结点数）
    int size;          // 总容量 = 2n - 1
} HuffmanTree;
// 在 [0, end] 范围内选出权值最小的两个根（parent == -1 的结点）
void SelectMinTwo(HuffmanTree* ht, int end, int* s1, int* s2) {
    int min1 = -1, min2 = -1;
    for (int i = 0; i <= end; i++) {
        if (ht->nodes[i].parent != -1) continue;   // 跳过已合并的结点
        if (min1 == -1 || ht->nodes[i].weight < ht->nodes[min1].weight) {
            min2 = min1;
            min1 = i;
        } else if (min2 == -1 || ht->nodes[i].weight < ht->nodes[min2].weight) {
            min2 = i;
        }
    }
    *s1 = min1; *s2 = min2;
}
HuffmanTree* CreateHuffmanTree(const char* chars, const int* weights, int n) {
    HuffmanTree* ht = (HuffmanTree*)malloc(sizeof(HuffmanTree));
    ht->n = n; ht->size = 2 * n - 1;
    ht->nodes = (HTNode*)malloc(ht->size * sizeof(HTNode));
    for (int i = 0; i < ht->size; i++) {       // 初始化所有结点
        ht->nodes[i].parent = -1;
        ht->nodes[i].lchild = -1;
        ht->nodes[i].rchild = -1;
        ht->nodes[i].weight = 0;
        ht->nodes[i].data = '\0';
    }
    for (int i = 0; i < n; i++) {              // 填充叶结点
        ht->nodes[i].data = chars[i];
        ht->nodes[i].weight = weights[i];
    }
    for (int i = n; i < ht->size; i++) {       // 每次选两个最小者合并
        int s1, s2;
        SelectMinTwo(ht, i - 1, &s1, &s2);
        ht->nodes[s1].parent = i;
        ht->nodes[s2].parent = i;
        ht->nodes[i].lchild = s1;
        ht->nodes[i].rchild = s2;
        ht->nodes[i].weight = ht->nodes[s1].weight + ht->nodes[s2].weight;
    }
    return ht;
}
typedef struct { char ch; char code[256]; } CodeNode;   // 编码表项
typedef struct { CodeNode* codes; int n; } CodeTable;
// 利用 parent 指针从叶子向根回溯，编码倒着填进 temp
CodeTable* CreateCodeTable(HuffmanTree* ht) {
    CodeTable* ct = (CodeTable*)malloc(sizeof(CodeTable));
    ct->n = ht->n;
    ct->codes = (CodeNode*)malloc(ht->n * sizeof(CodeNode));
    for (int i = 0; i < ht->n; i++) {
        ct->codes[i].ch = ht->nodes[i].data;
        char temp[256] = {0};
        int pos = 255;
        temp[pos] = '\0';
        int cur = i;
        while (ht->nodes[cur].parent != -1) {
            int parent = ht->nodes[cur].parent;
            pos--;
            temp[pos] = (ht->nodes[parent].lchild == cur) ? '0' : '1';
            cur = parent;
        }
        strcpy(ct->codes[i].code, &temp[pos]);
    }
    return ct;
}
int GetWPL(HuffmanTree* ht) {                  // 每个叶子向根回溯，累加权值 × 深度
    int wpl = 0;
    for (int i = 0; i < ht->n; i++) {
        int path = 0, cur = i;
        while (ht->nodes[cur].parent != -1) {
            path++;
            cur = ht->nodes[cur].parent;
        }
        wpl += ht->nodes[i].weight * path;
    }
    return wpl;
}
char* EncodeString(HuffmanTree* ht, CodeTable* ct, const char* str) {
    int len = strlen(str);
    char* result = (char*)malloc(len * 256 + 1);
    result[0] = '\0';
    for (int i = 0; i < len; i++) {
        for (int j = 0; j < ct->n; j++) {
            if (ct->codes[j].ch == str[i]) {
                strcat(result, ct->codes[j].code);
                break;
            }
        }
    }
    return result;
}
char DecodeChar(HuffmanTree* ht, const char* code, int* pos) {   // 从根走到叶子
    int cur = ht->size - 1;                     // 最后创建的内部结点就是根
    while (ht->nodes[cur].lchild != -1) {       // 只要不是叶子就继续往下走
        if (code[*pos] == '0') cur = ht->nodes[cur].lchild;
        else cur = ht->nodes[cur].rchild;
        (*pos)++;
    }
    return ht->nodes[cur].data;
}
```

#### 链表实现（链式存储）

链式结点没有 parent 指针，因此选最小者改为在指针数组中扫描并移除，生成编码改为从根向叶子递归：

```c
typedef struct HuffmanNode {
    char data;
    int weight;
    struct HuffmanNode* lchild;
    struct HuffmanNode* rchild;
} HuffmanNode, *HuffmanTree;
typedef struct CodeNode {
    char ch;
    char code[256];
    struct CodeNode* next;
} CodeNode;
typedef struct { CodeNode* head; int n; } CodeTable;
// 从指针数组中取出权值最小的结点并移除
HuffmanNode* FindMinAndRemove(HuffmanNode** nodes, int* size) {
    if (nodes == NULL || size == NULL || *size <= 0) return NULL;
    int minIdx = 0;
    for (int i = 1; i < *size; i++)
        if (nodes[i]->weight < nodes[minIdx]->weight)
            minIdx = i;
    HuffmanNode* minNode = nodes[minIdx];
    for (int i = minIdx; i < *size - 1; i++)   // 后续元素前移，等于删掉这个位置
        nodes[i] = nodes[i + 1];
    (*size)--;
    return minNode;
}
HuffmanTree CreateHuffmanTree(char* chars, int* weights, int n) {
    if (chars == NULL || weights == NULL || n <= 0) return NULL;
    HuffmanNode** nodes = (HuffmanNode**)malloc(n * sizeof(HuffmanNode*));
    int size = n;
    for (int i = 0; i < n; i++) {              // 创建 n 个叶结点
        nodes[i] = (HuffmanNode*)malloc(sizeof(HuffmanNode));
        nodes[i]->data = chars[i];
        nodes[i]->weight = weights[i];
        nodes[i]->lchild = nodes[i]->rchild = NULL;
    }
    for (int i = 0; i < n - 1; i++) {          // 每次取两个最小者合并
        HuffmanNode* left = FindMinAndRemove(nodes, &size);
        HuffmanNode* right = FindMinAndRemove(nodes, &size);
        HuffmanNode* parent = (HuffmanNode*)malloc(sizeof(HuffmanNode));
        parent->data = '\0';
        parent->weight = left->weight + right->weight;
        parent->lchild = left;
        parent->rchild = right;
        nodes[size++] = parent;                // 新结点放回数组末尾
    }
    HuffmanTree root = nodes[0];               // 最后剩下的就是根
    free(nodes);
    return root;
}
void _Encode(HuffmanTree T, CodeTable* ct, char* path, int depth) {
    if (T == NULL) return;
    if (T->lchild == NULL && T->rchild == NULL) {   // 到达叶子，当前路径就是编码
        CodeNode* node = (CodeNode*)malloc(sizeof(CodeNode));
        node->ch = T->data;
        path[depth] = '\0';
        strcpy(node->code, path);
        node->next = ct->head;   // 头插法
        ct->head = node;
        ct->n++;
        return;
    }
    path[depth] = '0';           // 左分支为 0
    _Encode(T->lchild, ct, path, depth + 1);
    path[depth] = '1';           // 右分支为 1
    _Encode(T->rchild, ct, path, depth + 1);
}
CodeTable* CreateCodeTable(HuffmanTree T) {
    CodeTable* ct = (CodeTable*)malloc(sizeof(CodeTable));
    ct->head = NULL; ct->n = 0;
    char path[256];
    _Encode(T, ct, path, 0);
    return ct;
}
int _GetWPLHelper(HuffmanTree T, int depth) {  // 递归 + 深度参数
    if (T == NULL) return 0;
    if (T->lchild == NULL && T->rchild == NULL)   // 叶子
        return depth * T->weight;
    return _GetWPLHelper(T->lchild, depth + 1) +
           _GetWPLHelper(T->rchild, depth + 1);
}
int GetWPL(HuffmanTree T) { return _GetWPLHelper(T, 0); }
```

> **注意**：两种实现的编码生成方式是镜像的——**数组实现从叶子向根回溯**（因为 parent 访问是 $O(1)$ 的），**链表实现从根向叶子递归**（因为链式结点没有 parent 指针）。殊途同归，本质都是"从根到叶的路径即编码"。

#### 两种实现对比

| 对比维度 | 数组实现 | 链表实现 |
| :--- | :---: | :---: |
| **存储方式** | 连续数组（下标操作） | 离散结点（指针操作） |
| **找双亲** | $O(1)$（parent 下标） | $O(n)$（需遍历） |
| **选最小的两个** | $O(n)$（线性扫描） | $O(n)$（线性扫描 + 元素前移） |
| **生成编码** | 回溯法（叶子 $\to$ 根，用 parent） | 递归法（根 $\to$ 叶子，用 path[]） |
| **GetWPL** | 每个叶子各自回溯，代价随叶深度增长 | 一次递归遍历，$O(n)$ |
| **内存连续性** | 连续（对缓存友好） | 离散 |
| **适用场景** | 数据量大、在意常数 | 理解指针与递归 |

> **注意**：追求常数时选**数组实现**——下标操作没有分配开销，parent 数组也让编码生成更简单；理解原理时选**链表实现**——递归 + 指针是二叉树的通用模式，掌握之后可以无缝迁移到其它二叉树算法。另外要留意：数组版 `GetWPL` 让每个叶子各自向根回溯，代价是"所有叶子深度之和"；权值分布极端（如斐波那契式权值）时叶深度可达 $O(n)$，总代价会退化到 $O(n^2)$，并不总是 $O(n \log n)$。

## 小结

- **树的定义与术语**：树是"一对多"的递归结构，除根以外每个结点恰好一个双亲；**深度从根向下数、高度从叶向上数**，两者方向相反。
- **树的计数性质**：$n = \sum d_i + 1$ 是通式；$m$ 叉树只设上限，度为 $m$ 的树还要求"达标"；第 $i$ 层至多 $m^{i-1}$ 个结点，最小高度为 $\lceil \log_m (n(m-1)+1) \rceil$。
- **二叉树的性质**：$n_0 = n_2 + 1$ 是核心恒等式；完全二叉树独享编号性质（左孩子 $2i$、右孩子 $2i+1$、双亲 $\lfloor i/2 \rfloor$）与 $n_1 \le 1$。
- **存储结构**：顺序存储只适合完全二叉树；二叉链表有 $n+1$ 个空链域；三叉链表用额外指针把"找双亲"降到 $O(1)$。
- **遍历**：先／中／后序的差别只在 `visit` 的位置，非递归版本用显式栈，层序遍历是 BFS 的特例；**只有含中序的两种序列组合才能唯一确定一棵二叉树**。
- **线索二叉树与树森林转换**：线索用 $n+1$ 个空链域存放前驱／后继，中序线索最实用，遍历空间从 $O(h)$ 降到 $O(1)$；孩子兄弟表示法的"左孩子右兄弟"是树与二叉树的桥梁，树的后根遍历等价于二叉树的中序遍历。
- **哈夫曼树与并查集**：哈夫曼树用贪心构造，$2n-1$ 个结点、无度为 1 的结点，WPL 唯一且最小，其编码是最优前缀编码；并查集是双亲表示法的极致应用，路径压缩 + 按秩合并使均摊复杂度降到 $O(\alpha(n))$。
