## 1. 计算机网络概述

### 计算机网络的定义

给事物下定义，目的是**区分和识别**它，手段是**抓住它的本质或特征**。那么计算机网络的本质或特征又是什么呢？对计算机网络的认识大致有以下三种观点：

| 观点 | 定义要点 | 抓住的本质 |
| :--- | :--- | :--- |
| **广义的观点** | 以实现远程通信为目的，一些互连的、独立自治的计算机的集合 | **计算机通信** |
| **用户透明性的观点** | 从后台技术实现角度描述，把计算机网络视作一种分布式系统，其内部资源分布与调度对用户**透明** | **内部实现对用户不可见** |
| **资源共享的观点** | 地理位置不同、功能相对独立的多个计算机系统通过通信线路互连，遵循共同的网络协议，由专门的网络操作系统管理，以实现资源共享、协同办公 | 以**用户**为中心 |

三种视角并不互相否定，而是同一事物的不同侧面——把它们综合起来才是完整的认识：**使用**上透明（用户不必关心内部实现），**核心**是以人为本，**实现**靠通信技术加计算机技术，**功能**是通信、资源共享与协同工作。

其中表述最完整的是"资源共享的观点"，它可以拆成四个要点：

| 要点 | 内容 |
| :--- | :--- |
| **目的** | 实现计算机**资源**的共享，资源包括硬件与软件，如程序、数据、存储、打印机 |
| **形态** | 互连的计算机**分布在不同地理位置**，需要通过通信线路互连 |
| **关系** | 互连的计算机是**独立或"自治"**的，相互之间不存在依赖关系 |
| **关键** | 通信过程中**必须遵循相同的网络协议** |

### 计算机网络的基础概念

计网是一名概念非常多的课程，有非常多的专有名词，我们先来看以下几个：

- **计算机网络**（network）：由若干**结点(node)**和连接这些结点的**链路(link)**组成。
- **集线器(hub)**：可以把多个结点连接起来组成一个计算机网络。普通民用领域如今已很少使用。
- **交换机(switch)**：同样用来连接多个结点，家庭、公司、学校通常用它组建内部网络。
- **互连网**（internet，小写）：由两个或多个计算机网络互相连接起来，形成规模更大的计算机网络。
- **路由器(router)**：把两个或多个计算机网络互相连接起来，形成规模更大的计算机网络。
- **因特网**（Internet，大写）：又称互联网，由各大 ISP 和国际机构组建，覆盖全球范围。
- **ISP**(Internet Service Provider) 即互联网服务提供商，如中国电信、中国移动、中国联通。

![家庭网络的常见接法](/notes-assets/cn1-01-home-network.jpg)

*家用路由器其实是路由器和交换机的组合。*

> **最本质的区别**：因特网（Internet）**必须**使用 TCP/IP 协议通信，而互连网（internet）可以使用任意协议。

### 计算机网络的发展历程

新技术的出现需要两个条件：**强烈的社会需求**与**前期的技术储备**；而两者之间还需要**创新**来打通——需求牵引、技术推动、创新落地，三者缺一不可。计算机网络正是计算机技术与通信技术紧密结合的产物，按应用需求与技术特色通常分为四个阶段：

**① 远程联机系统（20 世纪 50 年代）**

当时计算机造价昂贵、资源匮乏且放置集中，用户必须亲自带着程序到机房手工操作，极为不便。具有收发功能的**终端(terminal)** 解决了这个问题：用通信线路把计算机与终端相连，通过终端收发数据。这种"终端—通信线路—计算机"的模式就是远程联机系统，从此开启了计算机与通信技术相结合的时期。

> 它的结构特点是**单主机多终端**，严格意义上并不属于计算机网络的范畴。

**② 多计算机互联系统（20 世纪 60 年代）**

用户希望使用其他计算机上的资源，拥有多台计算机的组织也希望机器之间能交换信息，于是出现了以实现**资源共享**为目的的多机互联形态。这一阶段对通信的可靠性与准确性提出了更高要求，普遍方案是在计算机和线路之间设置**通信控制处理机（Communication Control Processor, CCP）**来提升系统性能。

> 它的结构特点是**以通信子网为中心，多主机多终端**；典型案例是 1969 年诞生的**阿帕网（ARPAnet）**。

**③ 标准、开放的计算机网络（20 世纪 70 年代中期起）**

各大公司在发布网络产品的同时，意识到制定体系结构与协议标准的重要性，纷纷推出各自专用的体系结构。国际标准化组织 ISO 于 1977 年成立专门机构研究开放系统互连问题，并于 1984 年颁布**开放系统互连参考模型（Open System Interconnect，OSI）**。

**④ 高速、互联、融合、移动、智能的计算机网络（20 世纪 80 年代末起）**

因特网在社会各领域广泛应用，电子商务、电子政务、远程教育、远程医疗、分布式计算、移动计算、即时通信、网络语音与视频等新应用不断涌现，对技术与性能提出越来越高的要求。这一阶段的走向可以用四个词概括：**泛在、融合、高速、智能**——网络无处不在、多种技术彼此融合、速率持续提升，并向智能化演进。支撑这些特征的代表性方向包括：

- **移动互联网**与**物联网**：连接的对象从"人"扩展到"物"；
- **云计算**与**大数据**：计算与存储资源集中到云端，数据成为核心资产；
- **软件定义网络（SDN）**：控制功能与转发功能分离，网络变得可编程；
- **人工智能**：网络开始具备自优化、自运维的能力；
- **Cyber Space（网络空间）**：网络从"通信基础设施"上升为与现实空间并列的活动疆域。

| 阶段 | 时间 | 结构特点 | 标志性事件 |
| :--- | :--- | :--- | :--- |
| **远程联机系统** | 20 世纪 50 年代 | 单主机多终端（严格说不属于计算机网络） | 终端(terminal)出现，计算机与通信技术开始结合 |
| **多计算机互联系统** | 20 世纪 60 年代 | 以通信子网为中心，多主机多终端 | 通信控制处理机(CCP)；1969 年 ARPAnet 诞生 |
| **标准、开放的计算机网络** | 20 世纪 70 年代中期起 | 体系结构与协议走向标准化 | ISO 于 1977 年成立专门机构，1984 年颁布 OSI 参考模型 |
| **高速、互联、融合、移动、智能** | 20 世纪 80 年代末起 | 应用驱动、技术融合、规模爆炸 | 因特网广泛应用，电子商务、远程教育、即时通信等新应用涌现 |

### 计算机网络的功能

- **数据通信**：实现计算机之间的数据传输，是**最基本、最重要**的功能。
- **资源共享**：包括硬件、软件、数据资源。例如智能音箱请求服务器处理、应用商店、分享视频。
- **分布式处理**：把复杂任务分配给网络中多台计算机处理，如大矩阵运算、MapReduce。
- **提高可靠性**：各台计算机互为替代机，如网盘服务器集群的数据冗余备份。
- **负载均衡**：各台计算机共同分担繁重工作，如用多台服务器均衡处理玩家请求。
- **其他**：满足社会与生活需求，如远程办公、远程教育、娱乐。

## 2. 计算机网络的类型

分类的作用是把一团乱麻变成脉络清晰、把无规律变成有规律、把主次不清变成重点突出。而分类的方法是**抓住并体现某些关键特征或关注点**——同一种划分，从服务提供者（研究、开发、实施）的角度看和从使用者（用户）的角度看，会得到不同的类别，也可能是两者的混合。
所以比"记住有哪几类"更重要的，是记住**每一种划分是为了研究哪一类问题**。

### 按分布范围：WAN/MAN/LAN/PAN

| 类型 | 范围 | 说明 |
| :--- | :--- | :--- |
| **广域网 WAN**（Wide Area Network） | 几十～几千公里 | 跨省、跨国、跨洲 |
| **城域网 MAN**（Metropolitan Area Network） | 几千米～几十千米 | 一个或几个相邻城市；常采用以太网技术，因此常并入局域网范畴探讨 |
| **局域网 LAN**（Local Area Network） | 几十米～几千米 | 学校、企业、家庭中的网络；采用以太网技术 |
| **个域网 PAN**（Personal Area Network） | 几十米以内 | 家庭或个人网络，通常用无线技术连接个人设备，故常称**无线个域网 WPAN**，如蓝牙、Zigbee |

两者各自的"技术画像"差别明显：

- **局域网**：适用于公司、机关、校园、工厂等**有限范围**内计算机、终端与各类信息处理设备的连网需求；特点是**数据传输率高（10Mbps～10Gbps）、传输延迟低（＜几十个 ms）、误码率低**，且易于建立、维护与扩展，覆盖范围一般在几公里以内。典型技术有光纤分布式数据接口（FDDI）、令牌环（Token-Ring）、以太网（Ethernet）、Wi-Fi（802.11 系列）。
- **广域网**：覆盖范围一般为几十公里到几千公里以上，可覆盖一个国家或地区甚至跨越各大洲，因此也称**远程网**。主要技术曾是 PSTN（公共交换电话网）、ISDN（综合业务数字网）、帧中继（Frame Relay）、ATM（异步传输模式）、SDH（同步数字体系），如今大多已被**以太网 / IP / MPLS / OTN（光传送网）/ SD-WAN** 替代。

> 这种分类方法关注的是网络的**技术选择、设计、实现、管理、适用性**。

### 按传输技术：广播式/点对点

- **广播式网络**：一台计算机发送数据分组时，广播范围内所有计算机都会收到该分组，再通过检查分组的目的地址决定是否接收。**所有无线网络都是广播式的。**
- **点对点网络**：数据只会从发送方"点对点"发到接收方，精准送达。路由器转发的数据分组就属于这一类。

> 这种分类方法关注的是**传输与转发技术、安全**。用抓包工具观察数据包的传输过程能直观区分两者：广播式网络里，一个数据包会被同一广播范围内所有节点收到；点对点网络里，数据包只沿一条链路送到指定的下一跳。例如一次 `ping` 的 ICMP 请求会被封装进三层的 IP 分组中，抓包时能直接看到这种逐层封装。

### 按使用者：公用/专用

- **公用网**：向公众开放的网络，如宽带，交手机话费即可使用的互联网。
- **专用网**：仅供某个组织内部使用，如政府、军队、电力、银行的内部网络。
- **虚拟专用网（Virtual Personal Network, VPN）**：借助公用网构建的**逻辑**专用网——物理上跑在公用网上，逻辑上却像一条只属于自己的专用通道，是"公用／专用"在工程实践中的折中形态。

> 这种分类方法关注的是**用户对象、网络管理、安全性**。

### 按传输介质：有线/无线

- **有线网络**：如网线、光纤。
- **无线网络**：如 5G、WiFi、卫星。

> 这种分类方法关注的是**物理实现、抗干扰性、保密性、安全性**。

### 按传输速率：高速/低速

分为**低速网**与**高速网**。这一划分站在用户感受一侧：远程抄表只需要极低的速率，而 4K 视频协作对速率极为敏感。

### 按网络角色：骨干/接入

分析真实的大型网络时，还常按设备与链路在整体结构中扮演的角色来划分：

- **骨干网（Backbone Network）**：连接各区域、承载汇聚流量、追求高带宽与高可靠性的核心网络；
- **接入网（Access Network）**：把用户侧设备接入骨干网的那一段，更关注覆盖范围、成本与接入方式。

> 这种分类方法关注的是**职责分工、性能取舍与建设运维成本**，也是读懂一张真实网络拓扑时最常用的视角之一。

## 3. 计算机网络的组成

### 从组成部分看

- **硬件**：主机（即端系统 end system，如电脑、手机、物联网设备）、通信设备（如集线器、路由器、交换机）、通信链路（如网线、光纤、同轴电缆）。
- **软件**：方便用户使用、实现资源共享，如 Email 客户端、聊天软件、网盘软件。
- **协议**：规定网络中的通信规则，由软件、硬件共同实现，如网卡加软件实现的网络通信协议。

> 端系统内部安装**网络适配器（Network Interface Card, NIC/网卡）**，负责把主机数据发送到网络上，同时接收来自网络的数据,是实现网络通信的硬件基础。

### 从逻辑功能看

仅按软硬件分类对研究网络并不有利——几乎任何系统都能拆成软硬件，这种划分无法揭示网络内部各部分的通信关系。研究组成划分，绕不开研究的**粒度（Granularity）**：粒度决定了观察网络时取的"放大倍数"，取不同的粒度就会得到不同的划分方式。其中最适中的一种视角是从**功能**出发。网络最基本的两个功能，恰好对应组成上的两大子网：

- **资源子网**：运行应用程序、向用户提供可共享的硬件、软件和信息资源的部分，主要由连接到互联网上的主机组成。
- **通信子网**：负责计算机间信息传输的部分，即把计算机和其他用户装置互连在一起的所有通信设备和介质的总称，主要由通信链路、通信设备和协议构成。

> **关键判据**：数据从资源子网中的一个**端设备**出发，经过通信子网，到达资源子网中的另一个**端设备**；**通信子网中的设备控制数据的流动，但不会生成或更改数据内容**

| 面向的对象 | 承担的功能 | 对应的子网 |
| :--- | :--- | :--- |
| **面向用户** | 数据处理 | **资源子网** |
| **面向传输** | 数据通信 | **通信子网** |

> 主机内部实现信息传输的网络适配器与底层协议属于**通信子网**，而非资源子网。

> **易错点**：**应用服务器属于资源子网**——Web 浏览器与 Web 服务器、邮件客户端与邮件服务器，都是"提供或使用共享资源的端设备"，不要因为它们"在网络中提供服务"就划进通信子网。

### 从工作方式看

- **边缘部分**：由连接到互联网上的主机及其软件组成，直接为用户服务（通信、资源共享）。
- **核心部分**：由大量网络和连接这些网络的路由器组成，为边缘部分提供服务（连通性、交换服务）。

把"边缘／核心"落到真实的因特网上，就得到一幅层次结构的图景：用户计算机与终端通过**校园网、企业网或 ISP** 接入**地区主干网**，地区主干网再通过**国家主干网**联入**国际高速主干网**，形成由路由器互联的、大型的、层次结构的网际网。接入网一侧属于网络边缘，直接面向用户与资源；主干网一侧（地区／国家／国际）属于网络核心，只负责把数据高效地送到对端。

> 想知道数据实际经过了哪些中间节点，可以用 `ping` 与 `tracert`（Windows）/ `traceroute`（Linux）。两者提供的信息量不同：`ping` 只回答"通不通、往返多久"，`tracert` 会逐跳列出路径上的每一个中间路由器。

## 4. 网络拓扑结构

**拓扑（Topology）**是对网络中**节点关系的抽象**，即把形态各异的设备与线路抽象成"点"和"线"之后得到的几何形状。网络拓扑影响传输与通信方式、性能、可靠性以及建设管理成本，是网络设计与组网时**首要考虑的因素之一**。

抽象的口径不同，得到的拓扑也不同：

| 抽象依据 | 得到的拓扑 | 现代叫法 | 含义 |
| :--- | :--- | :--- | :--- |
| **物理连通性** | **物理拓扑** | **underlay** | 设备与线缆实际怎么连 |
| **逻辑连通性** | **逻辑拓扑** | **overlay** | 数据在逻辑上怎么走 |

> **物理拓扑和逻辑拓扑可以不一致**：最典型的例子是早期用集线器（Hub）连接的双绞线以太网——物理上是星型，逻辑上却是总线型（共享信道、存在冲突），因此仍需 CSMA/CD 协议控制介质访问；1994 年后交换机取代集线器，物理与逻辑拓扑才都变成星型。

![七种常见拓扑结构](/notes-assets/cn1-07-topologies.jpg)

### 总线型

采用**单根传输线路**作为公共传输信道，所有节点通过专门的连接器连到这条公共信道上，它被称为**总线**。任一节点发送的数据都能通过总线传播，并被总线上所有其他节点接收。

- **优点**：属于广播网络，结构形式简单，易于实现与扩充。
- **缺点**：存在"总线争用"问题；可靠性和灵活性差，且**传输延时不确定**。
- **典型代表**：集线器连接的设备。

### 星形

有一个**中心节点**，其他各节点通过**点对点**与中心节点相连，形成辐射结构；**节点之间的数据通信都要通过中央节点**。

- **优点**：结构简单、管理方便、**可扩充性强**、组网容易；由中央设备实现数据转发，**不存在"总线争用"问题**。
- **缺点**：需花费大量电缆；中心节点故障会直接造成整个网络瘫痪（**单点故障**）。
- **典型代表**：以太网交换机连接的设备，常用于局域网。

### 树形（扩展星形）

又称**扩展星形拓扑结构**（Extended Star），本质上是**星形结构的重复**：中央星形拓扑上的某个节点，又是另一个星形拓扑的中心节点。它同时也是一种**分层结构**（Hierarchy），**数据流具有明显的层次性**。在节点规模相当的情况下，树形拓扑中通信线路的总长度较短，从而**减少了链路与设备的投资**，成本低、易于推广。

- **优点**：在星形的优点之外更富于层次，可**隔离某些网络流量**。
- **缺点**：结构较星形复杂；除叶节点及连线外，任一节点或连线的故障都会影响相关支路网络的正常工作。
- **适用场景**：分级管理和控制的网络系统。

### 环形

各节点和通信线路连接形成一个**闭合的环**，**每个节点只与相邻的两个节点相连**。环中数据按一个方向沿环逐站传输：发送端发出的数据沿环绕行一周后回到发送端，并由发送端将其从环上删除。因此**每个节点都必须把信息转发给下一个相邻节点**，任一节点发出的数据都可以被环上其他节点接收。

- **优点**：结构简单、易于实现、**传输时延确定**、路径选择简单。
- **缺点**：**维护与管理复杂**；任一节点或连接节点的线路故障都可能造成网络瘫痪。
- **典型代表**：令牌环网（流行于 2000 年以前）；它通过"令牌(token)"解决争用问题——令牌沿环依次传递，拿到令牌者才可使用信道。

### 双环

由两个**互不相连的独立同心环**组成，通常是**主环加备用环**（同一时刻只有一个环在工作）。

- **优点**：在单环基础上大幅提高**可靠性**——主环出故障时可切换到备用环。
- **缺点**：维护与管理复杂，且投资大。

### 网状

又称**无规则型**：节点之间的连接是任意的、不存在规律，每个节点都可以有多条线路与其他节点相连，因此节点之间存在**多条可选路径**，传输数据时可以灵活选用空闲路径或者避开故障线路。按连接的完整程度分为两档：

- **部分网状（Partially Mesh）**：只有部分节点之间存在多条链路。多条链路提供了冗余连接，代价是结构复杂。
- **完全网状（Full Mesh）**：每一个节点都与其他每一个节点直接相连，冗余度最高，但**链路数随节点数迅速增长**——$n$ 个节点需要 $\frac{n(n-1)}{2}$ 条链路。

- **优点**：可以充分、合理地使用网络资源，并具有很高的**可靠性**。
- **缺点**：这种可靠性以**建设成本和管理复杂度**的提高为代价。
- **典型代表**：由众多路由器构建的广域网（多为部分网状）。

> **联系**：BGP 要求同一 AS 内的路由器两两建立 iBGP 会话，即"全连通（Full Mesh）"，其会话总数同样是 $\frac{n(n-1)}{2}$。

### 不同拓扑结构的对比

| 拓扑结构 | 传输方式 | 优点 | 缺点 | 典型代表 |
| :--- | :--- | :--- | :--- | :--- |
| **总线型（Bus）** | 广播式 | 结构形式简单，易于实现与扩充 | 存在"总线争用"；可靠性与灵活性差、传输延时不确定 | 集线器连接的设备 |
| **星形（Star）** | 点对点 | 结构简单、管理方便、可扩充性强、组网容易；无"总线争用" | 耗用大量电缆；中心节点成为全网可靠性的关键（单点故障） | 以太网交换机（局域网） |
| **树形／扩展星形** | 点对点（分层） | 线路总长度短、减少链路与设备投资；富于层次，可隔离网络流量 | 结构较复杂，任一节点／连线故障影响相关支路 | 分级管理和控制的网络系统 |
| **环形（Ring）** | 广播式（绕环传递） | 结构简单，时延确定，路径选择简单 | 维护与管理复杂；任一节点或线路故障都可能使网络瘫痪 | 令牌环网 |
| **双环（Dual Ring）** | 广播式（绕环传递） | 主环加备用环，可靠性显著提高 | 维护与管理复杂，投资大 | 高可靠环网（如 FDDI 双环） |
| **部分网状** | 点对点 | 多条链路提供冗余连接 | 结构复杂 | 运营商广域网（部分） |
| **完全网状（Full Mesh）** | 点对点 | 每条链路冗余，可靠性最高 | 链路数按 $\frac{n(n-1)}{2}$ 增长，成本高 | 小型核心网络、iBGP 全连通 |

> Tip：**拓扑是不是决定性因素？拓扑相同的两个网络，性能一定相同吗？** 
> 
> 不一定——拓扑只规定了连接关系，真正决定性能的还有**技术选型**（用交换机还是集线器、跑什么协议）与**设备选型**（端口速率、背板带宽、缓存）。所以拓扑是"首要考虑因素之一"，但不是唯一因素。

## 5. 交换技术

数据在多节点之间如何被转发，直接决定了网络的效率和性能。从历史看，每一种通信网络都对应着一种交换技术：

| 时间 | 网络类型 | 交换技术 |
| :--- | :--- | :--- |
| 公元前 5 世纪起 | 邮政网络 | — |
| 1830s～1960s | 电报网络 | 报文交换 |
| 1870s～1960s | 电话网络 | 电路交换 |
| 1960s（ARPANET） | 计算机网络 | 分组交换 |

交换技术的演进始终围绕同一个核心矛盾：**如何在有限的通信资源下更高效地传输数据。**

### 电路交换

**定义**：通过物理线路的连接，动态地分配传输线路资源（如电话网络）。

**过程**：建立连接（尝试占用通信资源）→ 通信（一直占用通信资源）→ 释放连接（归还通信资源）。

**优点**：通信前从主叫端到被叫端建立一条专用的物理通路，在通信的全部时间内两个用户始终占用端到端的线路资源。数据直送，传输速率高，因此更适用于低频次、大批量的数据传输。

**缺点**：

- 建立／释放连接需要额外的时间开销；
- 线路被通信双方独占，利用率低；
- 线路分配的灵活性差；
- 交换节点不支持**差错控制**（无法发现传输过程中产生的数据错误）。

### 报文交换

报文交换的**核心思想是存储转发**，即把要传送的数据单元先存储进中间节点，再根据目的地址转发至下一节点。

**优点**：

- 通信前无需建立连接；
- 数据以"报文(message)"为单位在交换节点间存储转发，通信线路可以灵活分配；
- 通信时间内两个用户无需独占一整条物理线路，线路利用率比电路交换高；
- 交换节点支持差错控制（通过校验技术）。

**缺点**：

- 报文不定长，不方便存储转发管理；
- 长报文的存储转发时间开销大、缓存开销大；
- 长报文容易出错，重传代价高。

### 分组交换

把长报文拆成定长的**分组(Packet)**再存储转发。分组由**首部(Header)**和数据组成，首部即分组的控制信息，包含源地址、目的地址、分组号等。

![分组的结构](/notes-assets/cn1-02-packet-switching.jpg)

**优点**：

- 通信前无需建立连接；
- 数据以分组为单位在交换节点间存储转发，通信线路可以灵活分配；
- 通信时间内两个用户无需独占一整条物理线路，线路利用率高；
- 交换节点支持差错控制。

相比报文交换，分组交换进一步解决了几个问题：分组定长，方便存储转发管理；存储转发时间开销小、缓存开销小；分组不易出错，重传代价低。

**缺点**：

- 相比报文交换，控制信息占比增加；
- 相比电路交换，依然存在存储转发时延；
- 报文被拆分为多个分组，传输过程中可能出现失序、丢失等问题，增加处理复杂度。

### 虚电路交换

过程与电路交换类似：建立连接（虚拟电路）→ 通信（分组按序、按已建立好的既定线路发送，通信双方不能独占线路）→ 释放连接。区别在于它建立的是**逻辑**通路而非独占的物理通路。

### 交换技术性能相关例题

> **例 1（电路交换）**
> 设每一跳传播时延 = 1ms，电路交换机建立、释放下一跳连接耗时 = 1ms，接收方处理连接请求需要 2ms，数据传输速率 = 0.5kb/ms，报文大小 = 4kb。求完成一次传输的总时间。

![电路交换性能分析](/notes-assets/cn1-03-circuit-switching-example.jpg)

电路交换的总时间由三个阶段组成，分析的核心是**逐跳累加各阶段耗时**：

- 连接建立：$1\times3 + 1\times3 + 2 + 1\times3 = 11\text{ms}$
- 数据传送：$4/0.5 + 1\times3 = 11\text{ms}$
- 连接释放：$1\times3 + 1\times3 = 6\text{ms}$

**关键点**：电路交换的数据传送阶段，比特流**直达终点**，中间节点不做存储转发处理。因此数据传送时延仅由发送时延和传播时延构成，不受存储转发时延影响。

> **例 2（报文交换）**
> 设每一跳传播时延 = 1ms，数据传输速率 = 0.5kb/ms，报文大小 = 4kb，报文存储转发时延 = 2ms。求总时间。

![报文交换性能分析](/notes-assets/cn1-04-message-switching-example.jpg)

总时间 = 发送时延 × 跳数 + 传播时延 × 跳数 + 存储转发时延 × (跳数 − 1)。注意发送时延涉及全部 3 跳，而存储转发时延只涉及中间 2 个节点——**中间节点一定要接收完整个报文后，才能解析并转发**：

$$
\frac{4}{0.5} \times 3 + 1 \times 3 + 2 \times 2 = 31\text{ms}
$$

与例 1 对比可以看到：报文交换引入了额外的存储转发时延，代价显著。

> **例 3（分组交换）**
> 设每一跳传播时延 = 1ms，数据传输速率 = 0.5kb/ms，报文大小 = 4kb，分组存储转发时延 = 0.5ms。求总时间。

![分组交换性能分析](/notes-assets/cn1-05-packet-switching-example.jpg)

分组交换在机制上与报文交换同属存储转发，但分组定长且体积小，存储转发时延大幅降低。计算时还要考虑**流水线效应**——当第一个分组被路由器转发时，源节点可以同时发送后续分组，不同分组的传输过程在时间上重叠，总时间远小于逐个串行发送之和。在题目给定参数下，分组交换的总时间约为 **17.5ms**，明显优于报文交换的 31ms。

这正是互联网选择分组交换的根本原因：**把长报文切成小分组，用流水线并行换掉串行的等待。**

### 总体对比

| 性能指标 | 电路交换 | 报文交换 | 分组交换 |
| :--- | :--- | :--- | :--- |
| 完成传输所需时间 | 最少（排除建立／释放连接） | 最多 | 较少 |
| 存储转发时延 | 无 | 较高 | 较低 |
| 通信前是否需要建立连接？ | 是 | 否 | 否 |
| 缓存开销 | 无 | 高 | 低 |
| 是否支持差错控制？ | 不支持 | 支持 | 支持 |
| 报文数据有序到达？ | 是 | 是 | 否 |
| 是否需要额外的控制信息 | 否 | 是 | 是，且占比最大 |
| 线路分配灵活性 | 不灵活 | 灵活 | 非常灵活 |
| 线路利用率 | 低 | 高 | 非常高 |

## 6. 计算机网络的性能指标

性能指标是衡量网络"好不好用"的量化语言。设计网络、选购设备、诊断故障，都需要用这些指标来思考和表达。

### 数据传输速率

- **信道(Channel)**：表示向某一方向传送信息的通道。注意信道不等同于通信线路——一条通信线路在逻辑上往往对应一条发送信道和一条接收信道。
- **速率(Speed)**：连接到网络上的节点在信道上传输数据的速率，全称数据传输速率，也称数据率或比特率。
  - 单位：bit/s（或 b/s、bps，bit per second），有时也用 B/s（1B = 8b，B 是 Byte 字节，b 是 bit 比特）。
  - 对于 K、M、G、T，bps 采用**十进制**标准：$1\text{Kbps} = 1\times10^3\text{bps}$，$1\text{Mbps} = 1\times10^6\text{bps}$。

### 带宽

- **带宽(bandwidth)**：某信道所能传送的最高数据率，单位为 bps。
- **上行带宽／下行带宽**：分别指上传数据与下载数据的信道的带宽。

> **例：**
> 主机 A 和 B 之间的链路带宽为 100Mbps，主机 A 的网卡速率为 1Gbps，主机 B 的网卡速率为 10Mbps，求 A 给 B 发送数据的最高理论速率。

实际速率受**瓶颈**限制，即链路带宽和两端节点性能中的最差者：链路 100Mbps、A 网卡 1Gbps、B 网卡 10Mbps，瓶颈在 B 的网卡，答案是 **10Mbps**。

这揭示了一个重要原则——网络通信的实际速率由**木桶的短板**决定。选型时应确保链路带宽与终端设备性能相匹配，避免高性能设备被低性能环节拖累。

> 补充：带宽在通信领域也表示某信道允许通过的信号频带范围，单位为 Hz。信道带宽越大，传输数据的能力越强。

### 吞吐量

**吞吐量(Throughput)**：单位时间内通过某个网络（或信道、接口）的**实际**数据量，单位为 bps。它受带宽限制，也受复杂的网络负载情况影响——这是它与"带宽"这个理论上限的区别。

### 时延

**时延(Delay)**：数据（一个报文或分组，甚至比特）从网络（或链路）的一端传送到另一端所需的时间，也称延迟或迟延。它由四部分组成：

- **发送时延**（传输时延）：节点将数据推向信道所花的时间。
- **传播时延**：电磁波在信道中传播一定距离所花的时间。
- **处理时延**：路由器处理所花的时间，如分析首部、查找转发表。
- **排队时延**：数据排队进入、排队发出路由器所花的时间。

![数据传输中的四种时延](/notes-assets/cn1-08-delay-types.jpg)

$$
\text{总时延} = \text{发送时延} + \text{传播时延} + \text{处理时延} + \text{排队时延}
$$

$$
\text{发送时延} = \frac{\text{数据长度(bit)}}{\text{发送速率(bit/s)}}
$$

$$
\text{传播时延} = \frac{\text{信道长度(m)}}{\text{电磁波在信道中的传播速度(m/s)}}
$$

> 处理时延与排队时延受网络负载、路由器性能等诸多因素影响，在实际网络中动态变化，难以精确计算。

> **例：总时延计算**
> H1 给 H2 发送一个 1000B 的数据分组，H1 往链路 A 发送数据的速率为 100Mbps，路由器往链路 B 发送数据的速率为 80Mbps。链路 A 的传播时延为 0.01ms，链路 B 的传播时延为 0.05ms。不考虑路由器的处理时延和排队时延，求传输整个分组的总时延。

![时延计算示例](/notes-assets/cn1-09-delay-example.jpg)

总时延 = 各跳发送时延之和 + 各跳传播时延之和。计算时注意单位统一：1000B = 8000b，100Mbps = $10^8$bps。

H1 → 链路 A 的发送时延：

$$
\frac{1000\text{B}}{100\text{Mbps}} = \frac{8000\text{b}}{10^8\text{bps}} = 8\times10^{-5}\text{s} = 0.08\text{ms}
$$

路由器 → 链路 B 的发送时延：

$$
\frac{1000\text{B}}{80\text{Mbps}} = \frac{8000\text{b}}{8\times10^7\text{bps}} = 10^{-4}\text{s} = 0.1\text{ms}
$$

总时延 $= 0.01 + 0.08 + 0.05 + 0.1 = 0.24\text{ms}$。

> **最容易出错的地方是单位换算**——务必注意 **B（字节）与 b（比特）的区别**，以及 K、M、G 在速率中采用十进制标准（$10^3$、$10^6$、$10^9$）而非二进制。

### 时延带宽积

**时延带宽积** = 某链路的传播时延 × 带宽，表示一条链路中**已从发送端发出但尚未到达接收端的最大比特数**。它常被用来设计最短帧长。

> **例：时延带宽积与大文件传输**
> 在一个分组交换网络中，主机 H1 和 H2 通过路由器互连，2 段链路的带宽均为 100Mbps，时延带宽积均为 1000bits。若 H1 向 H2 发送 1 个大小为 1MB 的文件，分组长度为 1000B，则从 H1 开始发送时刻起到 H2 收到文件全部数据时刻止，所需的时间至少是（　）
>
> A. 80.02ms　　B. 80.08ms　　C. 80.09ms　　D. 80.10ms

**答案：D**

这道题综合了三个知识点：用时延带宽积反推传播时延；大文件被拆分为多个分组后要算出分组数量与每个分组的发送时延；总时间由"第一个分组走完全程"加上"其余分组依次发送"构成（流水线效应）。"至少"意味着不考虑排队和处理时延。

- 分组数量：$1\text{MB} / 1000\text{B} = 10^6\text{B} / 10^3\text{B} = 1000$ 个
- 每个分组的发送时延：

$$
\frac{1000\text{B}}{100\text{Mbps}} = \frac{8000\text{b}}{10^8\text{bps}} = 8\times10^{-5}\text{s} = 0.08\text{ms}
$$

- 单向传播时延：

$$
\frac{\text{时延带宽积}}{\text{带宽}} = \frac{10^3\text{b}}{10^8\text{bps}} = 10^{-5}\text{s} = 0.01\text{ms}
$$

- 总时间：$0.01 + 0.08 + 0.01 + (0.08 \times 1000) = 80.10\text{ms}$

关键在于正确理解**流水线效应**：第一个分组走完整个路径时，后续分组已经在管道中，总时间远小于逐个串行发送的时间。

### 往返时延 RTT

**往返时延(RTT)**：从发送方发送完数据，到发送方收到来自接收方的确认，总共经历的时间。

![往返时延的构成](/notes-assets/cn1-10-rtt.jpg)

- $t_1$：发送方发送数据的发送时延（**不计入 RTT**）
- $t_2$："数据"的单向传播时延
- $t_3$：接收方收到数据后的处理时延
- $t_4$："确认"的发送时延
- $t_5$："确认"的传播时延（通常 $t_5$ 与 $t_2$ 相等）

$$
RTT = t_2 + t_3 + t_4 + t_5
$$

网络游戏中的"游戏延迟"，反映的就是主机与服务器之间的 RTT。

### 信道利用率

$$
\text{信道利用率} = \frac{\text{有数据通过的时间}}{\text{有数据通过的时间} + \text{没有数据通过的时间}}
$$

> 信道利用率不能太低（浪费资源），也不能太高（容易导致网络拥塞）。

> **例：蓝牙传照片**
> 手机 H1 和 H2 通过蓝牙连接，连接时长为 1 分钟。在此期间，H1 以 80Mbps 的速率给 H2 传输了 20 张大小 10MB 的照片，求蓝牙连接期间的信道利用率。

$$
\text{信道利用率} = \frac{(20 \times 10\text{MB}) / 80\text{Mbps}}{1\text{min}} = \frac{20 \times 10 \times 8\text{Mb} / 80\text{Mbps}}{60\text{s}} = \frac{20\text{s}}{60\text{s}} = 33.3\%
$$

33.3% 意味着在 1 分钟的连接中仅有 20 秒在真正传数据，其余 40 秒信道空闲。实际网络中，信道利用率过低浪费资源，过高则容易拥塞，需要维持在合理区间。

**网络利用率**则是所有信道利用率的加权平均值，用于衡量网络带宽或信道的整体使用比例。

## 7. 计算机网络的分层结构

前面的内容回答了网络"是什么"，但要从工程上把网络做出来，只回答"是什么"远远不够：网络要同时容纳异构的硬件与传输介质、连接形态各异的操作系统、支撑从网页浏览到实时视频的各类应用。

### 分层的必要性

**两台计算机之间传递文件**是一个最小的网络场景，看上去很简单，实际却要解决一大堆问题：

- **应用侧**：用户接口或网络应用程序；
- **传输控制**：流量控制（以接收方可以接受的发送速度传送文件）、拥塞现象的发现与解决、传输错误的发现与解决；
- **数据处理**：数据分段与重组、编址（以便数据能正确到达目标计算机）；
- **路径与定位**：传输路径的选择、从源节点到目标节点的通信、物理设备的准确定位。

除了数据本身，还要牵扯一大摊工程事务：计算机（含网卡或光猫）、线路（网线或电话线、交换机）、网络互连设备，以及硬件安装与配置、系统软件安装与配置、应用软件安装与使用、故障排除。

只做"资源子网／通信子网"的逻辑划分还不够——**这一颗粒度仍然太大**，对网络节点功能的研究与开发还不具有足够的指导作用。问题需要再推进一步：**不能再停留在"哪些设备属于哪个子网"，而要回答"一个网络节点内部到底该具备哪些功能、这些功能怎么组织"。**

研究复杂对象的基本思路是**抽象 → 建模、提炼 → 简化**。**计算机网络体系结构**就是为研究、开发、实现及学习复杂的计算机网络而抽象出来的结构模型，它的着眼点在于：

> **通过对网络节点功能进行合理的逻辑划分，简化网络的设计与实现。**

### 分层的有效性：类比邮政系统

邮政系统是一个天然的分层通信系统。从上海的"你"把信寄给北京的"你的朋友"，链条是这样的：

**你 →（信）→ 邮局 A →（邮包）→ 上海机场 →（货运箱）→ 北京机场 →（邮包）→ 邮局 B →（信）→ 你的朋友**

这条链上不同环节遵守**不同的规则**：用户规则、邮政规则、机场规则。数据逐级下行时被一层层包起来（信 → 邮包 → 货运箱），到对端再一层层拆开（货运箱 → 邮包 → 信）。

一个通信系统只涉及**对等双方**，而一个分层的通信系统强调的是**明确分工、服务与规则**：发送端的基本功能是**写信、分信、送信**，接收端的基本功能是**接信、分信、读信**。

分层的优越性体现在三点：**降低复杂性**（分而治之，各个击破）、**促进模块化开发**（对特定层的功能而言，其内容以及与上下层之间的接口都已确定）、**提高灵活性与可扩展性**（避免一个层的技术或功能变化影响相邻的其它层）。

其中"分层(Layer)"与"分块(Block)"是两种不同的切分方式，区别在于两种不同的关系：

| 切分方式 | 关系 | 含义 | 例子 |
| :--- | :--- | :--- | :--- |
| **分层(Layer)** | **串的关系** | A 是 B 的基础，B 是 C 的基础……B 利用 A 提供的功能或服务，加上自己的工作，为 C 提供更强大的功能或服务 | 写电脑程序 |
| **分块(Block)** | **并的关系** | A＋B＋C → 整体 | 程序函数 |

分块是"把整体拆成并列的几坨"，彼此之间是**并**的；分层是"层层叠加、下层支撑上层"，彼此之间是**串**的——上层要**站在**下层的功能与服务之上，才能提供更强的能力。

### 分层原则

1. 根据**功能**进行抽象分层，每个层次所要实现的功能或服务均有明确的规定；
2. 每层功能的选择应**有利于标准化**；
3. 不同的系统**分成相同的层**，**对等层具有相同功能**；
4. 不同系统的对等层之间在通信时，有明确的通信规定或规则；
5. 高层使用下层提供的服务时，**下层服务的实现是不可见的（透明的）**；
6. **层的数目要适当**——层次太少功能不明确，层次太多体系结构过于庞大。

### 三种并存的分层模型

分层模型的构成要素有三组：**实体(Entity)**、**第 N+1／N／N−1 层**与**接口**，层与层之间则由**协议**连接。据此形成了三种并存的分层模型：

| 模型 | 层次（自顶向下） | 说明 |
| :--- | :--- | :--- |
| **OSI 参考模型** | 应用层 → 表示层 → 会话层 → 运输层 → 网络层 → 数据链路层 → 物理层（**七层**） | 计算机网络体系结构在**法律上的标准** |
| **TCP/IP 模型** | 应用层 → 传输层 → 网际层 → 网络接入层（**四层**） | 计算机网络体系结构在**事实上的标准** |
| **五层模型** | 应用层 → 传输层 → 网络层 → 数据链路层 → 物理层（**五层**） | 由 OSI 与 TCP/IP **整合而成的实用模型** |

### 网络体系结构

**网络体系结构(Network Architecture)** 是**网络层次结构模型与各层协议的集合**；等价地说，计算机网络的各层及其协议的集合，就是这个计算机网络及其构件所应完成的功能的精确定义。

- **体系结构是抽象的**：它只定义网络**应该实现的功能**，**不涉及具体的硬件与软件实现**。遵循同一体系结构的前提下究竟用何种硬件或软件去完成这些功能，属于**实现(Implementation)**的问题——**体系结构定义了"做什么"，实现解决"怎么做"。**
- 不同的网络体系结构中，分层的数量、各层的名称、内容与功能都可能不同，所以讨论网络时必须先声明"按哪套体系结构说话"。

体系结构之所以必须标准化，关键在于**专用(Proprietary)**与**开放(Open)**两条路线的差别：

| 对比维度 | **专用(Proprietary)** | **开放(Open)** |
| :--- | :--- | :--- |
| **技术归属** | 个别厂商开发、拥有并控制整个技术或核心技术 | 技术的免费使用，对公众开放 |
| **互通性** | 无法互兼容、互操作 | 不同厂商的产品可以互兼容、互操作 |
| **对技术发展的作用** | **阻碍**技术的发展与进步 | **促进**技术的发展与进步 |

物理层就有一个具体的例子：之所以要规定物理接口的**机械、电气、功能和规程特性**，是为了让不同的制造厂家既能够根据公认的标准各自独立地制造设备，**又能使各个厂家的产品相互兼容**。

### 网络体系结构的核心概念

- **源(source)**：通信过程中数据的**发送方**；**目标(destination)**：数据的**接收方**。
- **实体(Entity)**：**每一层上的活动元素**，包括实现该层功能的所有硬件与软件。
- **对等实体(Peer entity)**：相互通信的两个不同节点上**位于同一层次、完成相同功能**的实体。
- **服务(Service)**：每一层为其**相邻的上层**所提供的功能。
- **接口(Interface)**：**同一节点内相邻层之间**交换信息的连接点，下层通过接口向相邻上层提供服务。
- **协议(Protocol)**：**对等实体之间**为实现有效的数据交换或通信所必须遵守的**规则或标准的集合**。

通信的**双向性**决定了一个网络节点**同时具备源与目标的角色**。

关于服务与接口还有两点要补充：**服务**是 N 层使用 N−1 层所提供的服务，**向** N+1 层**提供更高的服务**，高层使用低层提供的服务时并不需要知道低层服务的具体实现方法；**接口**通过定义**服务及原语操作**实现，服务的实现细节对上层是透明的，因此**只要接口条件不变、下层功能不变**，下层功能的具体实现方法与技术的变化不会影响整个系统的工作。

同一套分层结构可以从两个方向去看：

- **从水平角度看，对等实体受协议约束**：不同机器上的同一层称为**对等层**，同一层的实体称为**对等实体**；**协议**是控制对等实体之间通信的规则的集合，是**水平**的。
- **从垂直角度看，上一层实体通过接口请求相邻下层的服务**：**接口**即同一节点内相邻两层的实体交换信息的逻辑接口，又称**服务访问点(Service Access Point, SAP)**；**服务**是下层为紧邻的上层提供的功能调用，是**垂直**的。
- 数据自顶向下传输时，会加入每一层的首部协议信息。

![数据在网络中的传输过程](/notes-assets/cn1-11-encapsulation.jpg)

**关于协议的进一步理解**：

- 协议**通常仅说明**特定通信规则所需要提供的功能是什么，**不会说明如何实现**这些功能，因此特定协议的实现可以**技术无关**；
- 网络协议是**按层次结构来组织**的；
- 一个功能完备的计算机网络需要制定**一整套复杂的协议集**，每种协议都是针对一个特定的目标或需求；
- 网络协议需要**不断发展和完善**——当一种新的网络服务出现时，就需要制定新的协议。

### 协议数据单元

**协议数据单元(PDU)**：每层实体所采用的数据格式由该层协议所决定，称为协议数据单元。它是协议的载体，是网络中所传送数据的逻辑组成单元。

在**源端**，数据从高层到下层，涉及数据的**封装(encapsulation)**；在**目的端**，从下层到高层，是**拆封**过程。第 n 层的 PDU 记为 **n-PDU**；**服务数据单元(SDU)** 是为完成上一层实体所要求的功能而传送的数据，记为 n-SDU；**协议控制信息(PCI)** 是控制协议操作的信息，记为 n-PCI。三者的关系是：

$$
\text{n-SDU} + \text{n-PCI} = \text{n-PDU} = (\text{n-1})\text{-SDU}
$$

### 协议三要素

协议由**语法**、**语义**与**语序**三部分组成：

- **语法**：**用户数据与控制信息的结构与格式**，以及**数据出现的顺序**。例如协议控制信息（首部）占几个字节、每个字节是什么含义、数据部分最多多少字节。常见做法是**固定长度 + 选项**，从而做到可变长（参见 IP 数据报头）。
- **语义**：解释控制信息每个部分的含义，规定**需要发出何种控制信息**，以及**完成的动作与做出什么样的响应**。例如"发送方发送完数据后，接收方是否需要应答"，以及应答的种类（如传输成功、传输失败）。
- **语序**（又称同步／时序）：对**事件发生顺序**的详细说明。例如发送方发送完数据后接收方需要立即应答；如果发送方在 10 秒内未收到"传输成功"应答，则重新发送数据。

### 分层要完成的功能

把网络功能分层，本质上是要给下面这些"麻烦事"各自找到合适的归属：

- **差错控制**：确保数据在传输过程中不出错；
- **流量控制**：发送端的发送速率必须使接收端来得及接收；
- **分段和重装**：发送端把数据块划分为更小的单位，接收端再还原；
- **复用和分用**：发送端几个高层会话复用一条低层连接，接收端再分用；
- **连接建立和释放**：交换数据前先建立一条逻辑连接，传送结束后释放。

## 8. OSI 参考模型

认识 OSI 模型要回答四个问题：层的数量、名称及其功能是什么？相邻层之间的交互（服务与接口）如何发生？数据封装与拆封是怎么回事？对等实体之间的通信（协议）靠什么约束？
OSI 参考模型自顶向下分为七层：

**应用层 → 表示层 → 会话层 → 运输层 → 网络层 → 数据链路层 → 物理层**

自下而上的口诀是"**物联网叔会使用**"（物、链、网、输、会、示、用）。

> **每一层都建立在下一层的基础上**——最低 4 层负责数据传输，最高 3 层负责处理网络应用。

### OSI 参考模型各层的功能与涉及的问题

#### 物理层

- **功能**：完成**两节点间比特流的传输**。它是最低层，利用传输介质为通信的网络节点之间**建立、管理和释放物理连接**，并为数据链路层提供数据传输服务。
- **涉及问题**：传输介质、信道类型；数据与信号之间的转换、信号传输中的衰减和噪声；**物理接口的机械、电气、功能和规程特性**。此外还要定义电路接口参数（形状、尺寸、引脚数等），以及传输信号的含义与电气特征（如 5V 表示 1、1V 表示 0，每比特信号持续 0.1ms）。

#### 数据链路层

- **先看它要解决什么问题**：物理层发送和接收数据的过程中会出现问题——节点如何知道它所接收的数据是否正确？如果噪声改变了一个分组的目标地址，节点如何察觉它丢失了本应收到的分组？在广播网络环境中，多个节点同时试图在一条线路上发送数据时发生的冲突如何解决？
- **功能**：实现**两个相邻节点之间的无差错数据传输**。
- **涉及问题**：对物理层提供的原始比特流传输服务进行加强；**成帧、物理寻址、确认、差错控制和流量控制**。差错控制的具体做法是**检错 + 纠错**或**检错 + 丢弃 + 重传**（需使用校验编码技术，对含多个比特的**帧(frame)** 进行检错）；流量控制用于协调两个节点的速率。

#### 网络层

- **功能**：在**通信子网**中选择一条合适的路径，使发送端运输层所传下来的数据能够通过所选择的路径到达目的端。
- **涉及问题**：为数据在节点之间传输创建逻辑链路；**寻址方案**（存在哪些网络以及设备在这些网络中所处的位置）；**路由选择**（找到通过网络的最优路径）；**拥塞控制**（避免因子网中同时出现过多分组而出现的网络瓶颈）；**异构网络互连**。此外还包括**分组转发**（将分组 Packet，又称数据报，从合适的端口转发出去）、**连接建立与释放**（确保分组有序、不重复到达）与**可靠传输管理**（接收方需返回分组确认信息）。

#### 运输层（传输层）

- **功能**：负责**端到端进程间**数据传输和控制功能。
- **承上启下的层**：它下面三层主要面向**网络通信**，确保数据被准确有效地从源主机传输到目标主机；它上面三层面向**用户主机**，为用户提供各种服务。
- **涉及问题**：通过**确认、差错控制和流量控制**等机制**弥补网络层服务质量的不足**；为高层提供端到端进程之间的数据传输服务；**数据分段**。它还承担**复用和分用**——发送端几个高层实体复用一条低层连接，接收端再分用。
- 运输层是计算机通信体系结构中**关键的一层**，它**向高层屏蔽了下层数据通信的细节**。在运输层中交互的数据单元称为**报文段(Segment)**。

#### 会话层

- **功能**：**建立、管理和终结**不同机器上的应用程序或进程间的**会话连接**，以确保点到点传输不中断。
- **涉及问题**：管理数据交换。会话管理采用**检查点机制**，当通信失效时从检查点继续恢复通信。

#### 表示层

- 表示层以下各层只关心可靠的数据传输，而表示层关心的是所传送数据的**语法和语义**。
- **功能**：处理两个通信系统之间所交换信息的**表示方式**，包括**数据格式变换、数据加密与解密、数据压缩与恢复**。

#### 应用层

- **功能**：为用户的应用程序**提供网络服务**，是**计算机网络与用户之间的界面**。
- **与 OSI 其他层不同**：它不为任何其他 OSI 层提供服务，只为 **OSI 模型以外的应用程序**提供服务。常见的应用层服务有文件传送、虚拟终端、远程用户登录、电子邮件、网络电话、WWW、VOD 等。在应用层中交互的数据单元称为**报文(message)**。

### OSI 参考模型七层功能总结

| 层次 | 一句话功能 | 英文 |
| :--- | :--- | :--- |
| **应用层** | 为用户的应用程序提供网络服务 | Application |
| **表示层** | 处理两个通信系统之间所交换信息的表示方式 | Presentation |
| **会话层** | 建立、管理和终结进程间的会话连接 | Session |
| **运输层** | 负责端到端进程间数据传输和控制功能 | Transport |
| **网络层** | 选择路径，实现源到目的节点数据的传输 | Network |
| **数据链路层** | 实现两个相邻节点之间的无差错数据传输 | Data Link |
| **物理层** | 完成两节点间比特流的传输 | Physical |

> 判断"某设备／某功能属于哪一层"时，最快的方法就是回来比对这张表。其中"**端到端**"（运输层）与"**相邻节点**"（数据链路层）最容易被混淆——**端到端说的是进程到进程，相邻节点说的是直接相连的两台设备**。

### OSI 参考模型各层的协议数据单元

| 层次 | 该层协议 | 数据传输单元（PDU） | 教材常用记法 |
| :--- | :--- | :--- | :--- |
| **应用层** | Application protocol | APDU | 报文(Message) |
| **表示层** | Representation protocol | PPDU | 报文(Message) |
| **会话层** | Session protocol | SPDU | 报文(Message) |
| **运输层** | Transport protocol | Segment | 报文段(Segment) |
| **网络层** | — | Packet | 分组／数据报(Packet) |
| **数据链路层** | — | Frame | 帧(Frame) |
| **物理层** | — | Bits | 比特(bit) |

> 上三层的数据单元既可记作 APDU／PPDU／SPDU，也可**统称为报文(Message)**；而运输层以下（Segment／Packet／Frame／Bits）两边完全一致，最需要记牢的正是这四层。

**并非网络中的所有节点都具备 OSI 七层所描述的全部功能**——通常，通信子网中的节点至多拥有下面三层的功能。这与常见网络设备的能力层次是一致的：

| 设备 | 功能层次 |
| :--- | :--- |
| 主机 | 实现了 OSI 参考模型全部七层 |
| 集线器 | 物理层 |
| 交换机 | 物理层、数据链路层 |
| 路由器 | 物理层、数据链路层、网络层 |
| 网线、光纤 | 物理传输媒体 |

## 9. TCP/IP 模型

与 OSI 不同，TCP/IP 不是纸上的标准，而是**实际跑在互联网上的那一套**：它被称为"**异种网络互连的唯一协议体系**"，适用于不同机型（从 PC 到巨型机）、不同类型的网络（从局域网到广域网）。

TCP/IP 模型自顶向下分为四层：**应用层 Application → 传输层 Transport → 网际层 Internet → 网络接入层 Network Access**。

| 层次 | 说明 | 与 OSI 的对应 |
| :--- | :--- | :--- |
| **应用层** Application | 为用户提供 TCP/IP 网络应用，并为这些应用提供网络支撑服务 | 相当于 OSI 应用层（并承担会话层、表示层的职能） |
| **传输层** Transport | 提供**可靠与不可靠两类**传输服务 | OSI 运输层 |
| **网际层** Internet | 也称**网络互连层** | OSI 网络层 |
| **网络接入层** Network Access | 模型的**最低层**，是 **IP 数据传输的物理通道**，**允许采用不同的网络技术** | OSI 物理层 + 数据链路层 |

> 最低层这里称「**网络接入层(Network Access)**」，也写作"网络访问层"，或称「**网络接口层**」。
>
> 自下而上的口诀是"**接网叔用**"（接→网络接入层、网→网际层、输→传输层、用→应用层）。

### TCP/IP 模型的本质

TCP/IP 不是一套先设计好再照着实现的模型，而是**实际运行、持续生长的协议体系**。一句话概括：

> **TCP/IP 本质上是一个协议集（一整套协议），"四层模型"只是对这个协议集组织方式的概括。**

直接推论是：**TCP/IP 不是两个协议**——名字里的 TCP、IP 只是最关键的两个，此外还有 UDP、ICMP、ARP、RARP 以及大量应用层协议。具体各层的主要协议如下：

| 层次 | 该层主要协议 |
| :--- | :--- |
| **应用层** Application | **HTTP、TELNET、FTP、SMTP、DNS、TFTP** |
| **传输层** Transport | **TCP、UDP** |
| **网际层** Internet | **IP、ICMP、ARP、RARP** |
| **网络接入层** Network Access | **Ethernet、Token Ring、Wi-Fi、PPP** |

> 这张清单本身就是"TCP/IP 是协议集"的最好证据：**网际层远不止 IP 一个协议**（还有差错报告用的 ICMP、地址解析用的 ARP 与反向解析用的 RARP），应用层更是一大串；而"网络接入层"里列的都是具体的链路技术（以太网、令牌环、Wi-Fi、PPP），恰恰说明这一层**不规定具体协议、什么网络技术都能接**。

### TCP/IP 模型的特长

| 特长 | 推论 |
| :--- | :--- |
| **开放的协议标准** | 兼容／互操作 |
| **独立于特定的计算机硬件与操作系统** | 无关乎机型（从 PC 到巨型机） |
| **独立于特定的底层网络及其硬件实现** | 可运行在不同的 LAN、MAN 和 WAN 之上 |
| 是**异构网络互连的唯一事实标准** | 技术与产品相伴而生，协议在持续演进与扩充 |


### TCP/IP 模型的设计理念

- **剔除会话层与表示层**：这样能提高网络效率；如果某些特定应用需要数据格式转换、会话管理功能，就交给**应用层的特定协议**去实现。
- **物理层与数据链路层合并为网络接口层**：因为网络硬件种类繁多，不应该有过多限制。网络接口层为网络层传输"分组"，但 TCP/IP 并未具体描述网络接口层的功能与协议，交给网络设备商自由发挥。
- **网络层只保留"尽最大能力交付"**：不再进行差错控制，数据传输是**不可靠**的，这样**路由器负载更低**，可靠性由传输层负责，把压力分摊给网络边缘部分（主机）。对比：OSI 网络层可向上提供**有连接可靠**的服务（虚电路）与**无连接不可靠**的服务（数据报），而 TCP/IP 网际层**仅提供无连接不可靠**的服务（数据报）。
- **运输层提供两类服务**：对比 OSI 运输层**仅**提供面向连接的可靠服务，TCP/IP 传输层可提供**有连接可靠**的服务（**TCP**）与**无连接不可靠**的服务（**UDP**）。

### TCP/IP 模型的各层任务

- **网络接入层**：实现相邻结点间的数据传输（为网络层传输"分组"），但**具体怎么传输不作规定**。这种设计让 TCP/IP 体系结构具有更强的**灵活性、适应性**。
- **网际层**：去除其他功能，仅保留**路由选择、分组转发、拥塞控制、网际互联**四个核心功能。
- **传输层**：除核心功能**复用和分用**外，还有差错控制、流量控制、连接建立与释放、可靠传输管理。
- **应用层**：同 OSI 参考模型。

## 10. OSI 与 TCP/IP 的对比与五层模型

### 层次的对应关系

| OSI 参考模型 | TCP/IP 模型 |
| :--- | :--- |
| 应用层 | **应用层** |
| 表示层 | **应用层** |
| 会话层 | **应用层** |
| 运输层 | **传输层** |
| 网络层 | **网际层** |
| 数据链路层 | **网络访问层** |
| 物理层 | **网络访问层** |

### OSI 参考模型与 TCP/IP 模型对比

| 对比维度 | **OSI 参考模型** | **TCP/IP 模型** |
| :--- | :--- | :--- |
| **层数** | 七层，但**会话层很少用到，表示层几乎为空** | 四层，但**网络接入层并非实际的一层**；未明确划分物理层与数据链路层（而这一划分是**必要且合理**的） |
| **功能划分** | 寻址、流控与差错控制**在每一层重复出现，系统效率低** | 功能重复问题相对较少，但**服务、接口与协议的区别不清晰** |
| **设计思想** | 更受**通信思想**支配，**不完全适合计算机与软件开发方式** | 从**互联网实际需求**出发，**更贴近计算机与软件的工作方式** |
| **产品实现情况** | **尚无完全按 OSI 实现的网络产品**，仅作为**理论参考模型** | 已有多款**成熟产品与实现**（如 TCP/IP 协议栈），是网络互连的**事实标准** |

> 这四条对比很"反直觉"——它没有一味夸 TCP/IP：TCP/IP 的毛病是"服务、接口与协议的区别不清晰"；OSI 的优点则被明确承认——"物理层与数据链路层的划分是必要且合理的"。这正是下面整合五层模型的依据。

### 实用五层模型

把两个模型整合起来，就得到**实用五层模型**：

**应用层 → 传输层 → 网络层 → 数据链路层 → 物理层**

整合的依据就藏在上面那张对比表里：

- 取 **OSI 的物理层与数据链路层**——因为"这一划分是必要且合理的"（TCP/IP 把这两层并成"网络接入层"，而网络接入层并非实际的一层）；
- 取 **TCP/IP 的传输层、网际层与应用层**——因为它们"从互联网实际需求出发，更贴近计算机与软件的工作方式"，且事实上跑的就是这一套。

> 一句话：**五层模型 = 借 OSI 的下两层分法 + 借 TCP/IP 的上三层分法。** 它既保留了细分的清晰度，又贴合实际协议集，因此成为国内教材的通行讲法。

各层在体系结构中的地位可以通俗地记为：**物理层是基础，数据链路层不可或缺，网络层最复杂，运输层最重要，应用层最亲近。**

把一台能上网的计算机按五层模型拆开，常见的软硬件各归其位：

- **浏览器软件** → 应用层（应用层"为用户的应用程序提供网络服务"）
- **端口** → 运输层（运输层实现"端到端进程间"通信，"端"指端口）
- **IP 地址** → 网络层（网络层的"寻址方案"决定设备在网络中的位置）
- **网卡** → 物理层 + 数据链路层（承担比特流传输与成帧、物理寻址）
- **网线** → 物理层（物理传输媒体）
- **操作系统** → **跨层**（它是实现各层协议的系统软件，网络栈就由它提供，不能简单归到某一层）

### 两个学习视角：自上而下/自下而上

同一个五层模型，既可以自上而下看，也可以自下而上看：

| 视角 | 出发点 | 用语 | 层次推进顺序 |
| :--- | :--- | :--- | :--- |
| **自上而下** | **应用驱动** | "**顶天**" | 应用接口 → 进程通信 → 端到端主机通信 → 相邻节点通信 → 原始比特流传输 |
| **自下而上** | **基础架构出发** | "**立地**" | 原始比特流传输 → 相邻节点通信 → 端到端主机通信 → 进程通信 → 应用接口 |

这条链上的五个台阶依次对应五层，合起来就是"**应用与通信**"：

- **应用接口** —— 应用层
- **进程通信** —— 传输层
- **端到端主机通信** —— 网络层
- **相邻节点通信** —— 数据链路层
- **原始比特流传输** —— 物理层

> **怎么用**：**自上而下（顶天）**适合从应用需求出发理解网络——先问"这个应用需要什么"，再往下找支撑，国外教材一般采用这种方式；**自下而上（立地）**适合从基础架构出发做工程——先看有什么网络与设备，再谈能支撑什么应用，国内教材一般采用这种方式。两者说的是同一个模型。

## 小结

- **定义**：网络是互连的、自治的计算机系统的集合，以**资源共享**为目的，以**共同的网络协议**为关键。因特网与一般互联网的本质区别在于是否必须使用 TCP/IP。
- **分类与组成**：六个分类维度各有其**关注点**；按功能可分为**资源子网**与**通信子网**，分界线是"是否生成或更改数据内容"。
- **拓扑**：七种结构各有取舍，且**物理拓扑与逻辑拓扑可以不一致**；拓扑是组网首要考虑因素之一，但不是唯一因素。
- **交换技术**：电路交换独占资源、时延确定；报文交换引入存储转发但开销大；**分组交换用定长分组与流水线效应换来了效率**，这是互联网选择它的根本原因。
- **性能指标**：速率、带宽、吞吐量、时延（发送＋传播＋处理＋排队）、时延带宽积、RTT、信道利用率——它们是同一套账的不同算法，单位换算（B 与 b、十进制与二进制）是最容易出错的地方。
- **分层**：体系结构的着眼点是**对网络节点功能做合理的逻辑划分**；水平方向靠**协议**约束对等实体，垂直方向靠**服务与接口**连接相邻层。
- **两个模型**：OSI 是法律上的标准，TCP/IP 是事实上的标准；**五层模型**取 OSI 的下两层与 TCP/IP 的上三层，是后续章节的总纲。
