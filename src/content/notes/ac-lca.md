## LCA 问题概述

树上两点 $u,v$ 之间**只有一条路**，这条路可以拆成两段：$u$ 往上走到某个点，再从那个点往下走到 $v$。这个"转折点"就是**最近公共祖先**（Lowest Common Ancestor，LCA）：

> LCA(u,v) = 同时是 $u$ 和 $v$ 的祖先的点里，**深度最大**的那个。

按照惯例，**每个点算它自己的祖先**，所以 $u$ 本身是 $v$ 的祖先时，LCA 就是 $u$。

有了它，一堆问题立刻变成公式：

$$d(u,v) = \text{dep}[u] + \text{dep}[v] - 2\,\text{dep}\big[\text{LCA}(u,v)\big]$$

也就是"两条到根的路径加起来，再减掉重复走的那段"

总结成步骤就是：

1. 先把深的那个**抬到同一层**；
2. 然后两个人**一起往上走**，直到相遇；
3. 相遇的点就是 LCA。

```cpp
int lca_naive(int u, int v) {
    while (dep[u] > dep[v]) u = fa[u];        // ① 对齐深度
    while (dep[v] > dep[u]) v = fa[v];
    while (u != v) { u = fa[u]; v = fa[v]; }  // ② 一起往上
    return u;
}
```

问题很清楚：**一次只走一步**。放在一条长度为 $n$ 的链上，单次询问就是 $O(n)$；$5\times10^5$ 次询问直接 $O(n^2)$，必超时。

所以要想办法"一次走很多步"。

## 求法 1：倍增

### 跳表

设 `up[k][v]` = 从 $v$ 向上跳 $2^k$ 步到达的点，有递推公式：

$$\text{up}[k][v] = \text{up}[k-1]\big[\text{up}[k-1][v]\big]$$

**"向上 $2^k$ 步" = 先向上 $2^{k-1}$ 步，再向上 $2^{k-1}$ 步。** 有了这一条，整张表就能一层层往上填：

```cpp
const int N = 500005, LOG = 20;      // 2^19 = 524288 > 5e5，所以 LOG 取 20
int dep[N], up[LOG][N];

// 预处理：先 BFS 求 dep 与 up[0]，再递推填满整张表
void build(int root) {
    // …… BFS：up[0][v] = u, dep[v] = dep[u] + 1 ……
    up[0][root] = 0;                 // 0 号点是哨兵：0 的祖先还是 0
    for (int k = 1; k < LOG; k++)
        for (int v = 1; v <= n; v++)
            up[k][v] = up[k - 1][up[k - 1][v]];
}
```

注意**哨兵 0**：根往上跳会到 0，0 再往上跳还是 0。这样"跳到根以上"不会越界，也不会崩，只会得到 0，而 0 显然不可能是答案，所以后面的判断天然把它们排除掉了。

### 查询

```cpp
int lca(int u, int v) {
    if (dep[u] < dep[v]) swap(u, v);        // 让 u 是深的那个

    // ① 把深度差 d 做二进制拆分，能跳就跳
    int d = dep[u] - dep[v];
    for (int k = 0; k < LOG; k++)
        if (d >> k & 1) u = up[k][u];

    // ② 如果已经重合，那 u 本身就是 LCA
    if (u == v) return u;

    // ③ 从高位往低位"试跳"：跳过去还不相遇，就跳
    for (int k = LOG - 1; k >= 0; k--)
        if (up[k][u] != up[k][v]) {
            u = up[k][u];
            v = up[k][v];
        }
    return up[0][u];                        // 此时两人的父亲就是 LCA
}
```

- **为什么不直接跳到 LCA？** 因为你在跳之前并不知道 LCA 在哪儿，所以只要能跳到"**LCA 的正下方**"就够了 —— 那两个点的父亲就是 LCA。
- **怎么保证不过头？** 先试大步子：如果两人各跳 $2^k$ 步之后**仍然不是同一个点**，说明 LCA 还在更上面，这一步跳得安全；否则就缩小步子再试。

:::example 例 1 · 手算一遍倍增
树：`1` 是根，`1-2`、`1-3`、`2-4`、`2-5`、`4-6`。求 $\text{LCA}(6,5)$。

深度：`dep[1]=0, dep[2]=1, dep[3]=1, dep[4]=2, dep[5]=2, dep[6]=3`。

**第一步**：`dep[6] - dep[5] = 1`，二进制是 `1`，所以 $k=0$ 时跳一步：`6 → 4`。此时 `u = 4, v = 5`，深度都是 2。

**第二步**：`u != v`，继续。

**第三步**：从大到小试跳。

| $k$ | `up[k][4]` | `up[k][5]` | 相等吗 | 动作 |
| :--- | :--- | :--- | :--- | :--- |
| 2（跳 4 步） | 0（跳出根了） | 0 | 相等 | 不跳（已经到根以上，跳了就过头） |
| 1（跳 2 步） | 0 | 0 | 相等 | 不跳 |
| 0（跳 1 步） | 2 | 2 | 相等 | 不跳（**跳了就正好是 LCA 本身，过头了**） |

循环结束，`u = 4, v = 5`，答案是 `up[0][4] = 2`。**验证**：4 的祖先是 2、1；5 的祖先是 2、1；公共祖先里最深的是 2 ✓。

再看一遍第 2、3 行的"相等就不跳" —— 这里"相等"恰恰意味着"跳过去就碰头了"，也就是**跳过头**。这正是为什么条件写成 `up[k][u] != up[k][v]` 而不是 `dep[...] > dep[...]`。
:::

> **易错点**：第 ③ 步必须**从大到小**枚举 $k$。从小到大的话，你可能先跳了一小步就越过了 LCA（因为条件只判断"不相同"，跳过头时仍然"不相同"），最后得到的是 LCA 的祖先

## 求法2：欧拉序 + ST 表

### 欧拉序求解

对树做一次 DFS，**每次进入一个点、或者从一个儿子返回，都把"当前所在的点"记一笔**，记出来的序列就叫**欧拉序**。

拿例 1 那棵树（`1-2`、`1-3`、`2-4`、`2-5`、`4-6`，根为 1）走一遍：

| 动作 | 记下的点 | 序列 |
| :--- | :--- | :--- |
| 进入 1 | 1 | `1` |
| 进入 2 | 2 | `1 2` |
| 进入 4 | 4 | `1 2 4` |
| 进入 6 | 6 | `1 2 4 6` |
| 从 6 返回 4 | 4 | `1 2 4 6 4` |
| 从 4 返回 2 | 2 | `1 2 4 6 4 2` |
| 进入 5 | 5 | `1 2 4 6 4 2 5` |
| 从 5 返回 2 | 2 | `1 2 4 6 4 2 5 2` |
| 从 2 返回 1 | 1 | `1 2 4 6 4 2 5 2 1` |
| 进入 3 | 3 | `1 2 4 6 4 2 5 2 1 3` |
| 从 3 返回 1 | 1 | `1 2 4 6 4 2 5 2 1 3 1` |

要点：

1. 长度恰好是 **$2n-1$**：每条边被"下去一次、上来一次"各记一个点，再补上根，正好 $2(n-1)+1$
2. 每个点可能出现**很多次**（度数越大出现越多），但**第一次出现的位置**只有一个，记为 `first[v]`
3. 序列里相邻两项在树上是**相邻的点**（要么往下走一步，要么往上退一步）

### 深度最小点求解

取 $u$、$v$ 第一次出现的位置，中间这一段子序列。回想 DFS 行程：

> 想去 $v$，必须先从 $u$ **往上**走到某个祖先，再**往下**走到 $v$。
> 这段行程里"最高"的那一点 —— 也就是深度最小的那一点 —— 正是那个转折点，也就是 LCA

为什么不可能更高？因为 LCA 以上的祖先还没被 DFS 回溯到，在这段行程里根本不会出现。

:::note 手算：LCA(6,5) 的区间
`first[6] = 4`、`first[5] = 7`，取欧拉序第 4 到第 7 项：

| 位置 | 4 | 5 | 6 | 7 |
| :--- | :--- | :--- | :--- | :--- |
| 点 | 6 | 4 | 2 | 5 |
| 深度 | 3 | 2 | **1** | 2 |

最小深度 1 出现在位置 6，点 **2** —— 和例 1 用倍增算出来的一样 ✓

再看一对"跨到另一棵子树"的：`LCA(6,3)`，`first[6] = 4`、`first[3] = 10`，区间是 4~10：

| 位置 | 4 | 5 | 6 | 7 | 8 | 9 | 10 |
| :--- | :--- | :--- | :--- | :--- | :--- | :--- | :--- |
| 点 | 6 | 4 | 2 | 5 | 2 | **1** | 3 |
| 深度 | 3 | 2 | 1 | 2 | 1 | **0** | 1 |

最小深度 0 在位置 9，点 **1** ✓（6 和 3 分居根的两侧，LCA 当然就是根）
:::

### ST 表

区间最小值（RMQ）是**静态**的，标准做法是 **ST 表**（Sparse Table，稀疏表）：

- `st[k][i]` = 从位置 $i$ 开始、长度 $2^k$ 的区间里，**深度最小**的那个位置；
- 递推：`st[k][i] = 深度更小的那个(st[k-1][i], st[k-1][i + 2^(k-1)])` ——
  "长度为 $2^k$ 的区间"= 左右两个"长度为 $2^{k-1}$"的区间取更优；
- 查询 $[l,r]$：取 $k=\lfloor\log_2(r-l+1)\rfloor$，比较 `st[k][l]` 与 `st[k][r-2^k+1]` ——
  这两个长度 $2^k$ 的区间**合起来一定盖住** $[l,r]$（允许重叠，取最小值不怕重叠）。

**复杂度分析**：

一次查询只做两次查表加一次比较，与区间长度无关，因此时间复杂度为$O(1)$

代价则是空间 $O(n\log n)$ —— 序列长 $2n$、层数 $\log(2n)$，$n=5\times10^5$ 时约 80 MB，交题前先看内存限制

```cpp
const int N = 500005, LOG = 20;      // 2^19 = 524288 > 5e5
int dep[N], fa[N], first[N];
int it[N], stk[N];                   // it：邻接表游标；stk：显式栈
int euler[N << 1], tot;              // 欧拉序，长度 2n-1
int lg[N << 1], st[LOG][N << 1];     // st 里存的是"深度最小的位置"

void buildEuler(int root) {
    int sp = 0;
    stk[sp++] = root; fa[root] = 0; dep[root] = 0;
    euler[++tot] = root; first[root] = tot;
    while (sp) {
        int u = stk[sp - 1];
        if (it[u] < (int)g[u].size()) {            // 还有没走过的儿子
            int v = g[u][it[u]++];
            if (v == fa[u]) continue;
            fa[v] = u; dep[v] = dep[u] + 1;
            stk[sp++] = v;
            euler[++tot] = v;
            if (!first[v]) first[v] = tot;         // 只在第一次到它时记录
        } else {
            sp--;                                  // 子树走完，回溯
            if (sp) euler[++tot] = stk[sp - 1];    // 回到父亲，再记一次
        }
    }
}

void buildST() {
    lg[1] = 0;
    for (int i = 2; i <= tot; i++) lg[i] = lg[i >> 1] + 1;
    for (int i = 1; i <= tot; i++) st[0][i] = i;
    for (int k = 1; (1 << k) <= tot; k++)
        for (int i = 1; i + (1 << k) - 1 <= tot; i++) {
            int a = st[k - 1][i];
            int b = st[k - 1][i + (1 << (k - 1))];
            st[k][i] = dep[euler[a]] < dep[euler[b]] ? a : b;
        }
}

int lcaST(int u, int v) {
    int l = first[u], r = first[v];
    if (l > r) swap(l, r);
    int k = lg[r - l + 1];
    int a = st[k][l], b = st[k][r - (1 << k) + 1];
    return dep[euler[a]] < dep[euler[b]] ? euler[a] : euler[b];
}
```

> **易错点**：`st` 里存的是**位置（下标）**，不是点号，最后要从 `euler[位置]` 取回点。
> 直接存点号也能跑，但比较深度时得再查一次 `dep`，反而更绕。

> **提示**：还有 $O(n)$ 空间的做法 —— 欧拉序里相邻两项的深度差恰好是 $\pm1$，可以用 ±1 RMQ 或笛卡尔树。
> 那是另一个话题，日常做题到这里就够了。

## 求法3：Tarjan 算法

### Tarjan 算法的步骤

**离线** = 把所有询问一次性读进来，再统一回答；**在线** = 来一个答一个。

离线的好处是：**回答顺序可以打乱**，于是能用更便宜的手段把答案批量算出来。

Tarjan 算法把询问"挂"到树上，一次 DFS 就全答完，就使用了“离线”的：

一对询问 $(u,v)$，在 $u$ 上挂一份、在 $v$ 上挂一份。每个点维护一个列表，元素是 `(另一端, 询问编号)`。

DFS 进入 $u$，把它的**整棵子树**处理完、准备回溯之前，扫一遍挂在 $u$ 上的询问：

- 若另一端点 $q$ **还没被访问过** → 跳过。等 $q$ 那边做完时会回答这同一对；
- 若 $q$ **已经被访问过** → $\text{LCA}(u,q)$ 就是 **$q$ 在并查集里的代表元**。

并查集只有两条规则：

1. 一开始每个点自成一个集合（`dsu[i] = i`）；
2. **一个点回溯时，把它并到它父亲上**（`dsu[u] = fa[u]`）。

把"已完成"理解成"这个点访问过了，并且已经顺着某条路往根合并了一段"。那么：

> 一个已完成点 $q$ 的代表元 = **从 $q$ 往上能走到的、最靠上的那个"已合并"的点**。

现在 $u$ 刚做完自己的子树，$q$ 在**别的分支**上也已完成。它们的路径只可能在 LCA 处汇合，
而 LCA **此刻还没回溯**（它还在等所有儿子），所以 `dsu[lca]` 仍然指向自己 ——
于是 `find(q)` 会顺着 $q \to \dots \to \text{LCA}$ 一路合并上去，**恰好停在 LCA**。

:::note 手算：Tarjan 求 LCA(6,5)
还是那棵树，只问一对 $(6,5)$。按 DFS 顺序（1 → 2 → 4 → 6 → 5 → 3）走，只看合并与回答：

| 步骤 | 发生了什么 | 并查集 | 回答 |
| :--- | :--- | :--- | :--- |
| 1 | 6 的子树写完，回溯前扫询问 | `dsu[6] = 4` | 挂在 6 上的 `(6,5)`：5 还没访问 → 跳过 |
| 2 | 回到 4，扫询问 | `dsu[4] = 2` | 4 上没有询问 |
| 3 | 进入 5，回溯前扫询问 | （先回答再合并） | 挂在 5 上的 `(5,6)`：6 已访问 ✓，`find(6)`：6→4→2，`dsu[2]` 仍是 2 → **2** ✓ |
| 4 | 5 回溯 | `dsu[5] = 2` | — |
| 5 | 回到 2，扫询问 | `dsu[2] = 1` | — |
| 6 | 进入 3，回溯 | `dsu[3] = 1` | — |

重点看第 1 行：6 回溯时并给了 4，4 回溯又并给 2，**但 2 还没回溯**（另一个儿子 5 刚进去），
所以 `dsu[2]` 仍指向自己 —— 这就是第 3 行 `find(6)` 停在 2 的原因。
:::

### 代码实现

$5\times10^5$ 的链上递归必爆栈，所以用"邻接表游标 + 显式栈"的**迭代后序**：

```cpp
const int N = 500005;
vector<int> g[N];
vector<pair<int, int> > qs[N];       // qs[u]：(另一个端点, 询问编号)
int dsu[N], ans[N], fa[N], vis[N], it[N], stk[N];

int find(int x) {                    // 迭代版，杜绝递归爆栈
    int r = x;
    while (dsu[r] != r) r = dsu[r];
    while (dsu[x] != r) { int t = dsu[x]; dsu[x] = r; x = t; }   // 路径压缩
    return r;
}

void tarjan(int root, int n) {
    for (int i = 1; i <= n; i++) dsu[i] = i;
    int sp = 0;
    stk[sp++] = root; vis[root] = 1; fa[root] = 0;
    while (sp) {
        int u = stk[sp - 1];
        if (it[u] < (int)g[u].size()) {              // 还有儿子没走
            int v = g[u][it[u]++];
            if (v == fa[u]) continue;
            fa[v] = u; vis[v] = 1;
            stk[sp++] = v;
        } else {                                     // 后序：子树全部处理完
            for (size_t i = 0; i < qs[u].size(); i++) {
                int q = qs[u][i].first;
                if (vis[q]) ans[qs[u][i].second] = find(q);   // 只在对方已访问时回答
            }
            if (fa[u]) dsu[u] = fa[u];               // 并到父亲上（必须在回答之后）
            sp--;
        }
    }
}
```

两个顺序都不能反：

- **先回答、再合并**：如果先把 $u$ 并到父亲上，`find(q)` 就可能越过 LCA 继续往上，答案直接变祖先；
- **合并要塞进 `if (fa[u])`**：根没有父亲，不能把它并到 0 上去。

> **易错点**：`u == v` 的询问（自己问自己）读入时就要**单独回答掉**。否则在回溯时 `vis` 判断为真，
> `find` 返回的是它合并之后的代表元，答案就错了。

## 三种求法的对比

| 场景 | 选谁 |
| :--- | :--- |
| 一般情况 | **倍增**：$O(\log n)$，代码最短、空间也小 |
| 询问 $10^6$ 次、必须每题 $O(1)$ | 欧拉序 + ST 表（先确认内存够） |
| 询问量很大、且允许离线 | **Tarjan**：理论上最快，空间还最小 |
| 已经写了树链剖分 | 直接用树剖求 LCA（见「树的重链剖分」），$O(\log n)$，常数更小 |

## LCA 的经典用法

### 两点距离

$$d(u,v) = \text{dep}[u] + \text{dep}[v] - 2\,\text{dep}[\text{LCA}(u,v)]$$

原理是两条到根的路径在 LCA 以上重叠，重叠部分被算了两次。

### 祖先判定

$u$ 是 $v$ 的祖先 $\iff \text{LCA}(u,v) = u$。

如果已经算过 DFS 序，还有个更快的写法（$O(1)$，不需要 LCA）：`dfn[u] <= dfn[v] && dfn[v] < dfn[u] + sz[u]`。

### 树上差分

要给路径 $u \to v$ 上的**每个点**加 1，不必真的爬一遍路径 —— 只要在四个位置打标记，最后**自底向上求和**就能还原：

| 类型 | 怎么打标记 | 最后怎么统计 | 典型题 |
| :--- | :--- | :--- | :--- |
| **点差分** | `cnt[u]++`、`cnt[v]++`、`cnt[lca]--`、`cnt[fa[lca]]--` | 子树求和 = 每个点被覆盖的次数 | 洛谷P3258、P1600 |
| **边差分** | `cnt[u]++`、`cnt[v]++`、`cnt[lca] -= 2` | 子树和 = "该点到父亲那条边"被覆盖的次数 | 洛谷P2680、P3038 |

怎么记才不混？一句话：

> **点差分多减一个"LCA 的父亲"，边差分只在 LCA 减两次。**

道理是：点差分要保留 LCA 本身被算一次，所以 LCA 处减 1（抵消重复）、它父亲处再减 1（把"LCA 以上"彻底熄灭）；而边差分里 LCA 身上那条"到它父亲的边"根本不在路径上，所以直接减 2。

:::example 例 2 · 松鼠的新家（点差分 + 一个必踩的坑）
一棵 $n$ 个点的树，松鼠要按顺序访问 $a_1,a_2,\dots,a_n$，每次沿唯一路径走过去。求每个点被经过多少次。

**思路**：$n-1$ 段路径，每段都是"整条路径加 1"，而且只在最后统计一次 —— 标准的**树上点差分**。

对每一段 $(a_i, a_{i+1})$：`cnt[a_i]++`、`cnt[a_{i+1}]++`、`cnt[lca]--`、`cnt[fa[lca]]--`。

**那个坑**：相邻两段是**首尾相接**的。$a_2,a_3,\dots,a_n$ 这些"中转站"被前一段数了一次、又被后一段数了一次 —— 但实际只经过一次。所以最后要对 $a_2 \dots a_n$ 各减 1。

**解**：打完标记后，按 DFS 的逆序（保证儿子先算完）做一次子树求和，输出每个点的值。
:::

> **易错点**：树上差分只适合"**先改完、最后问一次**"。如果修改和询问是交替的（加一次、问一次、再加），就得换树链剖分，把路径拆成区间交给线段树动态维护。

### 路径相交判定

两条路径 $(a,b)$ 与 $(c,d)$ **有公共点**，当且仅当：

> $\text{LCA}(a,b)$ 在路径 $(c,d)$ 上，**或** $\text{LCA}(c,d)$ 在路径 $(a,b)$ 上。

而"点 $x$ 在路径 $(u,v)$ 上"用距离公式判：$d(u,x) + d(x,v) = d(u,v)$
